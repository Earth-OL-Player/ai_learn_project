# sprint202613 当期设计方案

版本：v1.0  
日期：2026-05-16  
迭代定位：真实 AI 面试题库初始化与无外键题库模型清理  
对应需求：`doc/3.迭代文档/sprint202613/1.当期需求文档.md`

## 1. 架构说明

本迭代不新增独立服务和新中间件，继续使用既有三工程架构：`ai-learn-web` 调用 `ai-learn-backend`，后端通过 MySQL 保存系统题库、用户、刷题汇总和成长数据，`ai-service` 与 Qdrant 继续服务于 RAG 和 AI 刷题能力。

设计重点是清理历史验证模型：题库从“少量示例题 + 知识点关联”调整为“真实 Top300 题库 + 分类字符串”；数据库从“业务表带外键约束”调整为“无外键约束 + 业务逻辑校验 + 索引约束”。这样更符合当前全新项目快速迭代和本地数据清理需求。

## 2. 数据库设计

### 2.1 新增迁移脚本

新增 Flyway migration：

```text
V12__remove_foreign_keys_and_knowledge_tables.sql
```

主要职责：

1. 兼容已执行历史版本的数据库，检测并移除历史外键约束。
2. 删除 `question_knowledge_points` 表。
3. 删除 `knowledge_points` 表。
4. 调整 `questions.question_type` 为分类字符串字段。
5. 调整 `questions.importance_score` 为 `DECIMAL(5,1)`，兼容 CSV 小数评分。
6. 清理旧题库数据和旧刷题汇总中题目编码状态。
7. 重新写入 `AI面试题Top300.csv` 中的 300 道真实题目。

### 2.2 外键清理范围

迁移脚本覆盖历史表中的外键名称：

| 表 | 历史外键 |
| --- | --- |
| `suggestions` | `fk_suggestions_user_id` |
| `comments` | `fk_comments_user_id` |
| `question_knowledge_points` | `fk_question_knowledge_points_question_id`、`fk_question_knowledge_points_knowledge_point_id` |
| `rag_index_tasks` | `fk_rag_index_tasks_user_id` |
| `user_badges` | `fk_user_badges_user_id`、`fk_user_badges_badge_id` |
| `growth_events` | `fk_growth_events_user_id` |
| `user_question_stats` | `fk_user_question_stats_user_id` |
| `user_practice_sessions` | `fk_user_practice_sessions_user_id` |

说明：去除外键后仍保留主键、唯一索引和普通索引，保证查询性能和必要的业务唯一性。

### 2.3 真实题库初始化策略

CSV 原始字段：

```text
code,question,question_type,standard_answer,importance_score,occurrence_count
```

初始化策略：

- `code` 为空时按行号生成 `AI-TOP-0001` 到 `AI-TOP-0300`。
- `question_type` 原样写入 `questions.question_type`。
- `importance_score` 按 1 位小数写入。
- `occurrence_count` 按整数写入。
- 初始化前清理旧题库数据，避免旧验证数据混入真实题库。

## 3. 后端设计

### 3.1 移除知识点接口链路

删除以下知识点相关对象：

| 类型 | 对象 |
| --- | --- |
| Controller | `KnowledgePointController` |
| Service | `KnowledgePointService` |
| Mapper | `KnowledgePointMapper` |
| Record | `KnowledgePointRecord` |
| Response | `KnowledgePointResponse` |

`AuthFilter` 同步移除 `/api/v1/knowledge-points` 保护路径，避免保留无效接口配置。

### 3.2 题目查询调整

`QuestionMapper` 不再 join `question_knowledge_points` 和 `knowledge_points`，只查询 `questions` 表。

新增公开分类查询：

```text
GET /api/v1/questions/types
```

实现逻辑：

```sql
SELECT DISTINCT question_type
FROM questions
WHERE deleted = 0
ORDER BY question_type ASC;
```

### 3.3 响应对象调整

`QuestionListResponse` 和 `QuestionDetailResponse` 移除知识点列表字段，仅保留题目编码、题目内容、分类、参考答案、重要性评分、出现次数和创建时间等核心字段。

### 3.4 小数评分兼容

以下对象中的 `importanceScore` 调整为 `BigDecimal`：

- `QuestionListRecord`
- `QuestionListResponse`
- `QuestionDetailResponse`
- `SystemQuestionRecord`
- `SystemQuestionWriteRecord`
- `SystemQuestionRequest`
- `SystemQuestionResponse`
- `PracticeQuestionRecord`
- `PracticeQuestionResponse`

`SystemQuestionAdminService` 中 CSV 解析增加小数解析逻辑，并在保存前统一规整为 1 位小数。

### 3.5 刷题权重兼容

`PracticeService` 抽题权重计算从整数重要性评分调整为小数重要性评分：

```text
权重加成 = importanceScore / 100 * 4
```

这样既兼容历史整数评分，也保留 Top300 CSV 中的小数权重差异。
