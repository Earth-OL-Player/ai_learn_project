## 3. 业务规则

1. 系统题库数据以 `AI面试题Top300.csv` 为准，旧的少量验证题目不再作为默认题库保留。
2. CSV 字段固定为 `code,question,question_type,standard_answer,importance_score,occurrence_count`。
3. 当 CSV 中 `code` 为空时，系统初始化时生成 `AI-TOP-0001` 到 `AI-TOP-0300` 的稳定编码。
4. `questions.question_type` 是题目分类唯一来源，页面筛选和下拉框直接使用该字段。
5. 不再维护独立知识点表，也不再维护题目与知识点多对多关系。
6. 热门面经页面不再展示知识点筛选项和题目知识点信息。
7. 重要性评分支持 0-100 范围内 1 位小数，用于保留真实数据中的评分精度。
8. 系统数据库不再定义外键约束；数据关联由业务字段、唯一索引、普通索引和服务逻辑保证。
9. 去除外键不代表允许提交脏数据，业务接口仍需做参数校验、权限校验和逻辑删除控制。
10. 已初始化过旧版本数据库的本地环境，升级后应通过新 Flyway migration 清理外键、知识点表和旧题库数据。

## 4. 数据要求

### 4.1 题目表字段

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 题目自增 ID | 数据库主键 |
| `code` | 题目编码 | 唯一业务编码，CSV 为空时自动生成 |
| `question` | 题目内容 | 必填 |
| `question_type` | 题目分类字符串 | 必填，前端分类下拉来源 |
| `standard_answer` | 参考答案 | 必填 |
| `importance_score` | 重要性评分 | 0-100，支持 1 位小数 |
| `occurrence_count` | 真实面试出现次数 | 非负整数 |
| `created_at` | 创建时间 | 系统维护 |
| `updated_at` | 更新时间 | 系统维护 |
| `deleted` | 逻辑删除标识 | 0 未删除，1 已删除 |

### 4.2 下线表

| 表名 | 下线原因 |
| --- | --- |
| `knowledge_points` | 题目分类改为直接使用 `questions.question_type` 字符串 |
| `question_knowledge_points` | 不再维护题目与知识点多对多关联 |

### 4.3 分类查询

分类下拉使用如下逻辑：

```sql
SELECT DISTINCT question_type
FROM questions
WHERE deleted = 0
ORDER BY question_type ASC;
```
