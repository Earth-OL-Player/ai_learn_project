## 1. 当期目标

本迭代围绕“平台统一系统题库 + AI 聊天式刷题”形成闭环：由超级管理员维护系统题库，普通用户不再维护个人题库；用户在 AI 智能刷题页面按分类抽题、作答、获得 AI 评分与学习建议；系统只保存用户与题目编码维度的汇总数据，不保存完整答题记录和聊天记录，从源头控制 TOC 场景下的数据存储压力。

## 3. 业务规则

1. 系统题库只允许超级管理员维护，普通登录用户无权调用管理接口。
2. 系统题库新增和 CSV 导入时，`code` 可为空；为空时后端自动生成唯一题目编码。
3. 管理题目时只需要维护 `code`、`question`、`question_type`、`standard_answer`、`importance_score`、`occurrence_count`；创建时间、更新时间和逻辑删除由系统维护。
4. `code` 是题目稳定业务标识，用户刷题汇总只记录 `question_code`，不直接依赖题目自增 ID。
5. 平台不再面向用户开放个人题库新增、导入、删除和浏览入口。
6. 平台不再在个人中心展示答题记录列表和薄弱点分析，避免继续强化旧数据模型。
7. AI 智能刷题默认选择全部分类；用户可以多选分类后再开始刷题或下一题。
8. 出题阶段只能接收出题相关内容；若用户输入与刷题无关内容，需要给出温馨提示。
9. 答题阶段未评分前，用户输入会被视为当前题答案；明显出题或无关请求需要提示用户先完成当前题。
10. 当前题评分后，用户可继续围绕本题追问学习，也可以点击下一题或重新回答。
11. 每次下一题或重新回答时，前端清空上一题聊天内容，只展示当前题上下文。
12. 系统不保存完整用户答案和聊天明细，仅保存每个用户、每个题目编码的答题次数、最高得分、最近得分和最近答题时间。

## 4. 数据要求

### 4.1 题目核心字段

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| `id` | 题目自增 ID | 数据库主键 |
| `code` | 题目编码 | 稳定业务标识，新增可自动生成 |
| `question` | 题目内容 | 必填 |
| `question_type` | 题目分类 | 必填，前端按该字段筛选 |
| `standard_answer` | 参考答案 | 必填 |
| `importance_score` | 重要性评分 | 0-100，默认 60 |
| `occurrence_count` | 真实面试出现次数 | 非负整数，默认 0 |
| `created_at` | 创建时间 | 系统维护 |
| `updated_at` | 更新时间 | 系统维护 |
| `deleted` | 逻辑删除标识 | 0 未删除，1 已删除 |

### 4.2 用户刷题汇总字段

| 字段 | 说明 |
| --- | --- |
| `user_id` | 用户 ID |
| `question_code` | 题目编码 |
| `answer_count` | 用户累计回答该题次数 |
| `best_score` | 用户该题历史最高得分 |
| `last_score` | 用户该题最近一次得分 |
| `first_answered_at` | 首次答题时间 |
| `last_answered_at` | 最近答题时间 |

## 5. 验收标准

- 超级管理员可以进入管理者中心的系统题库管理页面，普通用户不能进入。
- 超级管理员可以分页查询系统题库，并按关键词、分类筛选。
- 超级管理员可以新增、编辑、删除系统题目；`code` 为空时系统自动生成。
- 超级管理员可以下载 CSV 模板，并上传符合模板的 CSV 批量导入题目。
- 前端不再展示“我的题库”入口，手动访问 `/my-questions` 不再作为有效业务入口。
- 个人中心不再展示“我的答题记录”和“薄弱点分析”。
- AI 智能刷题页面以聊天式布局展示，默认全部分类，可多选分类。
- 点击开始刷题、下一题或输入出题类语言时，可以获得系统题库中的一道题。
- 用户提交答案后可以获得评分、参考答案、命中点、缺失点、优化建议和成长变化。
- 用户重新回答同一题时，若得分未超过历史最高分，则经验值不增加。
- 数据库仅保留用户题目汇总数据，不新增完整聊天记录表。
