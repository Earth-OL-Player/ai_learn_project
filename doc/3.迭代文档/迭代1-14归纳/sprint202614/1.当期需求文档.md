## 1. 当期目标

本迭代围绕 AI 智能刷题的“前端页面 -> Java 后端 -> Python AI 服务”全链路进行问题修复和体验优化。重点解决后端调用 Python AI 服务时请求体丢失导致 422 校验失败的问题；优化答题后页面不再重复展示当前题目；修复本地兜底评分把题目分类当作必答关键词导致误扣分的问题；同时优化评分详情区域的留白和卡片样式，让页面保持清新简约。

## 3. 业务规则

1. 前端只调用 Java 后端公开接口，不直接调用 Python AI 服务。
2. Java 后端调用 Python AI 服务时必须发送 UTF-8 JSON 请求体，并携带内部鉴权 Token。
3. 后端调用 AI 服务失败、超时、非 2xx 或业务响应异常时，必须自动切换到后端本地规则兜底，不能影响用户完成刷题。
4. 答案评分应以参考答案含义覆盖情况为准，题目分类只作为展示和筛选信息，不作为必答关键词。
5. RAG 检索片段可用于学习讨论和参考提示，但不得作为本地兜底评分的强制扣分项。
6. 评分支持大小写不敏感和常见同义表达匹配，降低用户使用等价表达时被误扣分的概率。
7. 用户提交答案后，页面应保留当前题上下文状态，但评分消息本身不重复渲染题目卡片。
8. 本题讨论回复应直接回答用户疑问，不再先复述“你的问题是……”这类冗余内容。
9. 本迭代不新增单元测试代码，验证以构建、语法检查和人工联调为主。

## 4. 接口与数据要求

### 4.1 Java 到 Python AI 服务调用

调用路径保持不变：

```text
POST /internal/v1/practice/answer/grade
POST /internal/v1/practice/discuss
```

请求要求：

- HTTP 版本固定为 HTTP/1.1，避免本地 Uvicorn 对 h2c 升级请求支持不完整导致请求体解析异常。
- `Content-Type` 使用 `application/json; charset=utf-8`。
- 请求体使用 UTF-8 编码序列化。
- 日志不得打印内部 Token、用户答案全文或真实模型密钥。

### 4.2 兜底评分关键词来源

| 来源 | 是否作为必答关键词 | 说明 |
| --- | --- | --- |
| 参考答案 | 是 | 从参考答案中提取术语、领域短语和短关键词 |
| 题目分类 | 否 | 只用于展示、筛选和复习兜底提示 |
| RAG 检索片段 | 否 | 只用于讨论参考，不作为评分扣分项 |
| 用户答案 | 否 | 用于命中判断，不反向新增评分要求 |

### 4.3 前端展示要求

- `QUESTION` 类型消息展示题目卡片。
- `GRADING` 类型消息不展示题目卡片，只展示评分、建议和评分详情。
- `DISCUSSION` 类型消息不展示题目卡片，避免追问时重复刷屏。
- 评分详情展开后，命中点、缺失点、参考答案、经验变化需要具备清晰留白。

## 5. 验收标准

- 启用 `AI_SERVICE_ENABLED=true` 且启动 Python AI 服务后，提交答案不再出现 Python 端 422 `Field required body` 校验失败。
- Java 后端调用 Python AI 服务时不再触发 Uvicorn `Unsupported upgrade request` 对主流程造成影响。
- 用户提交答案后，前端评分消息不重复展示当前题目内容。
- 用户回答 RAG 分类题但未复述“RAG 检索增强生成”分类名时，不再出现缺少该分类名的扣分提示。
- 用户使用“向量化、切分、重排、提示词”等同义表达时，兜底评分可以识别为相关要点。
- 本题追问回复不再出现“你的问题是……”或重复用户问题的冗余句式。
- “查看评分详情”展开后的左侧留白和明细卡片样式明显改善。
- 后端构建通过，前端构建通过，Python 代码语法检查通过。
- `doc/中间件/AI模型服务.md` 已补充本地联调和 422 排查说明。
