# sprint26015 当期设计方案

版本：v1.0  
日期：2026-05-17  
迭代定位：答题功能优化设计，围绕评分来源识别、兜底讨论限制、评分卡片展示和本地聊天状态恢复进行轻量改造。

## 1. 设计原则

1. 保持改动聚焦：只改造刷题链路相关代码，不引入无关重构。
2. 不新增中间件：聊天记录恢复优先使用浏览器 localStorage，与后端当前题状态配合完成。
3. 不新增单元测试：本迭代仅执行构建和手工验收。
4. 保持接口兼容：新增字段使用可选增强方式，前端兼容旧数据为空的情况。
5. 明确模型来源：AI 服务需要把本次评分是否为兜底策略返回给后端。

## 2. 总体方案

### 2.1 链路划分

```text
用户输入
  ↓
ai-learn-web 刷题页
  ↓
ai-learn-backend PracticeService
  ↓
ai-service PracticeAgentService
  ↓
真实大模型 或 本地规则兜底
```

### 2.2 改造点概览

| 模块 | 改造点 |
| --- | --- |
| ai-service | 评分响应增加 fallbackUsed；讨论兜底改为无法探讨提示。 |
| ai-learn-backend | 识别评分是否兜底；调整评分提示语；扩展无关内容拦截；讨论兜底返回固定提示。 |
| ai-learn-web | 评分卡片结构化展示；经验变化悬浮提示；localStorage 保存当前题聊天记录。 |
| doc | 补充本迭代需求、设计和验收文档。 |

## 3. 后端设计

### 3.1 AI 服务评分来源标记

`PracticeGradeResponse` 增加字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| fallbackUsed | bool | true 表示本次评分使用本地规则兜底；false 表示真实大模型评分成功。 |

处理规则：

1. 大模型评分成功并结构化解析成功：`fallbackUsed=false`。
2. 未配置大模型、大模型调用失败或解析失败：`fallbackUsed=true`。
3. 后端直接调用 AI 服务失败并使用 Java 本地规则评分：视为 `fallbackUsed=true`。

### 3.2 后端评分响应封装

`PracticeAiClient.grade` 返回内部包装对象，包含：

1. `GradingResult gradingResult`
2. `boolean fallbackUsed`

`PracticeService.submitAnswer` 根据 `fallbackUsed` 生成不同提示：

- 兜底：说明大模型异常，已使用本地兜底评分，并提示重新作答或下一题。
- 正常：提示可探讨细节、重新作答或下一题。

### 3.3 讨论兜底策略

当讨论阶段 AI 服务不可用或返回本地兜底时，统一返回：

> 抱歉，当前大模型调用异常，仅保留兜底策略评分功能，无法和您进行探讨。

该提示不暴露内部异常详情，不误导用户认为本地规则具备真实讨论能力。

### 3.4 无关内容拦截

在 `PracticeService` 中扩展明显无关词命中规则，覆盖天气、新闻、股票、旅游、做饭、写诗、翻译、笑话、帅、好看等表达。

处理阶段：

1. 答题阶段：命中后提示围绕当前题提交答案。
2. 讨论阶段：命中后提示围绕本题技术概念、解题思路或答案细节提问。

## 4. 前端设计

### 4.1 评分卡片结构

评分卡片包含：

1. 得分和正确性标签。
2. 经验变化悬浮提示。
3. 加粗“优化建议：”标题和建议内容。
4. 评分详情折叠面板。

评分详情改为单列列表：

1. 命中点：使用项目符号列表展示。
2. 缺失点：使用项目符号列表展示。
3. 参考答案：使用段落展示。

### 4.2 经验变化展示

根据 `earnedExperience` 判断展示样式：

| 条件 | 展示 |
| --- | --- |
| earnedExperience > 0 | 绿色向上箭头 + “+X 经验” |
| earnedExperience = 0 | 柔和提示 “经验不变” |

### 4.3 聊天记录恢复

使用 localStorage 保存当前用户当前题的最后一次聊天记录。

#### 4.3.1 存储 key

```text
ai_learn_practice_chat_{userId}
```

#### 4.3.2 存储内容

| 字段 | 含义 |
| --- | --- |
| phase | 当前刷题阶段 |
| questionCode | 当前题编码 |
| messages | 当前页面消息列表 |
| updatedAt | 更新时间戳 |

#### 4.3.3 恢复规则

1. 页面初始化时先查询后端当前刷题状态。
2. 如果后端存在当前题，且 localStorage 中 questionCode 与当前题一致，则恢复聊天记录。
3. 如果不存在快照或题目不一致，则使用后端当前题构建默认提示。
4. 点击“下一题”或产生新题响应时，清空旧记录并保存新题记录。
5. 重新作答当前题不切换题目，因此保留同题聊天上下文。

## 6. 风险与兼容性

| 风险 | 处理方式 |
| --- | --- |
| 旧 AI 服务不返回 fallbackUsed | 后端默认按 false 处理 AI 服务成功响应；AI 服务不可达时仍按 true 兜底。 |
| localStorage 数据损坏 | 前端解析失败时自动移除损坏快照，回退到后端当前题状态。 |
| 用户切换账号 | 存储 key 包含 userId，不同账号互不覆盖。 |
| 无关内容规则误伤 | 只拦截明显无关高频词，避免影响正常技术讨论。 |
