# sprint26015 当期需求文档

版本：v1.0  
日期：2026-05-17  
迭代定位：答题功能优化，提升兜底提示、评分展示、无关内容拦截与未完成刷题状态保留体验。

## 1. 背景与目标

当前 AI 智能刷题已支持抽题、作答评分、继续讨论、重新作答和下一题，但存在以下体验问题：

1. 大模型异常时，用户无法明确知道当前评分来自本地兜底策略。
2. 评分完成后的提示语包含经验值变化，容易干扰用户专注刷题。
3. 评分详情布局偏拥挤，经验变化占用明细区域。
4. 命中点、缺失点和优化建议展示不够结构化。
5. 答题页刷新、页面切换或退出重新登录后，只能恢复题目，无法恢复最后一次对话记录。
6. 答题阶段和讨论阶段对明显无关内容的拦截不足。

本迭代目标是在不新增中间件、不新增单元测试的前提下，优化答题闭环体验，让用户在模型正常或异常场景下都能获得清晰、稳定、简洁的反馈。

## 2. 需求范围

### 2.1 大模型调用失败兜底优化

#### 2.1.1 首次评分提示兜底来源

当评分过程中真实大模型不可用、AI 服务异常、AI 服务业务失败或 AI 服务返回本地规则兜底结果时，评分回复需要明确提示：

- 当前大模型调用异常。
- 已使用本地兜底策略完成评分和解析。

#### 2.1.2 兜底评分后的行动提示

大模型异常兜底评分完成后，行动提示统一为：

- “您可以重新作答或者开始下一题”。

#### 2.1.3 兜底讨论限制

当用户在讨论阶段继续追问，但大模型当前不可用时，不再使用本地规则伪造讨论回复，应返回明确提示：

- “抱歉，当前大模型调用异常，仅保留兜底策略评分功能，无法和您进行探讨”。

### 2.2 大模型调用成功优化

#### 2.2.1 正常评分后的行动提示

大模型评分成功后，评分完成提示不再描述经验值，行动提示统一为：

- “您可以与我探讨细节、重新作答或者开始下一题”。

#### 2.2.2 答题阶段无关内容拦截

当用户处于答题阶段，输入明显非答题内容时，需要拦截并友好提示，例如：

- “我帅吗”
- “今天天气怎样”

提示应引导用户围绕当前题目提交答案。

#### 2.2.3 讨论阶段无关内容拦截

当用户处于讨论阶段，输入明显非技术讨论内容时，需要拦截并友好提示，例如：

- “我帅吗”
- “今天天气怎样”

提示应引导用户围绕本题技术概念、解题思路或答案细节提问。

### 2.3 两种场景通用展示优化

#### 2.3.1 去除经验值首句描述

评分回复首句不再展示如下经验变化描述：

- “评分完成，本次未超过历史最高分，经验值不增加”
- “评分完成，本次提升了 X 点经验”

经验变化改为在评分卡片中以轻量视觉效果展示。

#### 2.3.2 命中点和缺失点结构化展示

评分详情中的命中点和缺失点需要以列表形式展示，避免使用一段长文本展示多个要点。

#### 2.3.3 优化建议标题强化

评分卡片中，分数下方的优化建议前需要显示加粗标题：

- “优化建议：”

#### 2.3.4 评分详情布局调整

评分详情从两行两列四块文本调整为三行一列：

1. 命中点
2. 缺失点
3. 参考答案

不再在评分详情中展示“经验变化”块。

#### 2.3.5 经验变化视觉反馈

评分卡片中需要根据经验变化展示轻量效果：

- 经验增加：显示绿色向上箭头和本次增加经验。
- 经验不变：显示柔和的经验不变提示。

### 2.4 最后一次聊天记录保留

答题页需要保留当前题最后一次聊天记录状态，覆盖以下场景：

1. 刷新答题页面后，恢复当前题和对应聊天记录。
2. 从其他页面返回答题页后，恢复当前题和对应聊天记录。
3. 退出重新登录后，恢复当前用户当前题和对应聊天记录。
4. 用户点击“下一题”或发起明确新题请求后，开启新的聊天记录。

## 3. 非功能需求

1. 不新增单元测试代码。
2. 不新增真实密码、Token、密钥或生产连接地址。
3. 不新增 MySQL、Redis、Qdrant 等新的中间件依赖。
4. 前端 UI 保持清新、简约、大气。
5. 代码注释使用 UTF-8 简体中文。
