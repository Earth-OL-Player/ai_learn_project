## 1. 当期目标

本迭代只完成“能打开、能导航、能看学习路线”的最小底座，不引入注册登录、数据库、建议评论、题库和刷题逻辑。

交付后应达到：

- 前端工程和后端工程可以本地启动。
- 浏览器默认进入“AI 学习路线与资料”页面。
- 左侧展示四个规划菜单，主内容区能切换公开页面或显示后续迭代占位提示。
- 右上角展示登录入口占位，但不实现真实登录。
- 学习路线内容来自 `doc/学习路线页面` 的整理版，页面结构清晰可演示。

### 2.2 本期不做

- 不做注册、登录、退出、JWT 和权限守卫。
- 不连接 MySQL、Redis、Qdrant。
- 不做建议、评论、面试题、刷题 Agent 的真实接口。
- 不做个人中心、答题记录、成长体系。

## 3. 页面需求

### 3.1 全局布局

- 左侧固定菜单：AI 学习路线与资料、建议与评论、面试题大全、刷题 Agent。
- 默认高亮“AI 学习路线与资料”。
- 顶部用户区展示“登录 / 注册”入口占位，点击提示“登录能力将在 sprint202602 开放”。
- 主内容区根据路由展示页面内容。

### 3.2 学习路线页面

页面至少包含：

- 平台说明。
- 路线总览。
- 基础阶段：Python、数学基础、机器学习基础。
- 进阶阶段：深度学习、NLP、CV、大模型基础。
- 工程阶段：LangChain、LangGraph、RAG、向量数据库、模型部署。
- 实战阶段：AI Agent、知识库问答、智能刷题、企业应用。
- 资料区和学习建议。

### 3.3 占位页面

建议与评论、面试题大全、刷题 Agent 当前均为占位页，要求：

- 有明确标题。
- 有后续迭代说明。
- 不出现接口报错或空白页。

## 4. 接口需求

接口统一前缀：`/api/v1`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/learning/roadmap` | 游客 | 返回学习路线结构化内容 |
| GET | `/health` 或 `/actuator/health` | 游客 | 后端健康检查 |

学习路线响应建议：

```json
{
  "title": "AI 应用开发学习路线和资料集",
  "description": "面向 AI 应用开发学习者的阶段化路线",
  "sections": [
    {
      "title": "基础阶段",
      "summary": "打好编程、数学和机器学习基础",
      "items": ["Python 基础", "数学基础", "机器学习基础"]
    }
  ]
}
```

## 5. 非功能要求

- 文档、源码、配置统一 UTF-8。
- 前端 API 基础地址通过 `.env.example` 提供本地占位值。
- 后端响应遵循统一结构，包含 `code`、`message`、`data`、`traceId`。
- 不提交真实密码、Token、生产地址。
- 代码保持简单，避免为了后续功能过度抽象。

## 6. 验收标准

- `ai-learn-web` 可本地启动并访问。
- `ai-learn-backend` 可本地启动，健康检查可访问。
- 打开前端默认进入学习路线页面。
- 四个菜单展示完整，当前菜单高亮正确。
- 学习路线页面展示分区内容。
- 其他菜单点击后显示占位说明，不报错。
- 仓库未新增 MySQL、Redis、Qdrant 运行时依赖。
