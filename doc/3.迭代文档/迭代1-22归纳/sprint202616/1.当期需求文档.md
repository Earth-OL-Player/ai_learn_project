# sprint2616 当期需求文档

版本：v1.0  
日期：2026-05-17  
迭代定位：答题功能优化，补齐重答清理、答题上下文记忆、经验变化说明、无关内容智能拦截、Markdown 渲染和流式输出体验。

## 1. 背景与目标

当前 AI 智能刷题已具备抽题、作答、评分、讨论和重答能力，但在真实使用中仍存在以下问题：

1. 点击“重答本题”后，前端聊天记录和后端最近答案记忆未同步清理，容易把上一次答案带入新一轮重答。
2. 用户评分后继续追问“我刚刚回答的答案是什么”等问题时，大模型缺少题目和最近答案上下文，回答不稳定。
3. 经验增加或不变只有视觉结果，没有鼠标悬浮详情，用户不知道为什么增加或不增加。
4. 无关内容拦截只依赖关键词，不能准确判断用户输入是否与刷题、回答或技术讨论有关。
5. 讨论阶段大模型返回 Markdown 内容时，前端按纯文本展示，标题、加粗、列表等格式不可读。
6. 聊天输出不是流式展示，不符合主流 AI 聊天产品体验。

本迭代目标是在不新增单元测试代码的前提下，围绕 AI 智能刷题闭环做体验增强，让用户重答更干净、追问更准确、反馈更清晰、输出更自然。

## 2. 需求范围

### 2.1 重答本题清理上下文

用户点击“重答本题”后，需要满足：

1. 前端当前题聊天记录清空，只保留重新作答提示和题目卡片。
2. 本地 `localStorage` 当前题聊天快照同步重置。
3. 后端当前刷题会话中的最近答案记忆同步清空。
4. 重答后再次提交答案，讨论阶段只能引用新答案，不引用旧答案。

### 2.2 本题讨论上下文记忆

评分完成后，系统需要记录当前题最近一次用户答案，用于本题讨论阶段的大模型提示词。

用户在讨论阶段追问：

- “我刚刚回答的答案是什么？”
- “我刚才哪里没答好？”
- “结合我刚才的答案帮我优化一下。”

系统需要把当前题目、参考答案、最近一次用户答案和用户追问一起传给 AI 服务，确保回复围绕真实上下文。

### 2.3 经验变化悬浮详情

评分卡片中的经验变化标识需要支持鼠标悬浮说明：

| 场景 | 展示要求 |
| --- | --- |
| 首次回答 | 展示“首次回答得了 X 分，新增 X 经验” |
| 分数突破历史最高 | 展示“比上次回答多拿了 X 分，并突破历史最高分新增 Y 经验” |
| 未突破历史最高 | 展示“未能突破上次最高分 X 分，本次经验不变” |

### 2.4 大模型无关内容拦截

答题阶段和讨论阶段需要优先调用 AI 服务判断输入是否相关。

相关内容包括：

1. 当前题答案。
2. 对当前题技术概念、解题思路、评分结果的追问。
3. 泛技术学习问题。
4. 重答、下一题、继续刷题等刷题操作表达。

无关内容包括：

1. 天气、新闻、旅游、做饭等生活闲聊。
2. 股票、娱乐、颜值等与刷题无关内容。
3. 与技术学习无关的写诗、笑话、翻译等请求。

当 AI 服务不可用或未配置真实模型时，保留本地明显无关词兜底，避免主流程不可用。

### 2.5 Markdown 渲染

前端聊天气泡需要支持 Markdown 展示：

1. 支持标题、加粗、列表、行内代码和段落换行。
2. 禁止渲染原始 HTML，避免脚本注入风险。
3. 样式保持清新、简约、大气，与现有聊天卡片一致。

### 2.6 流式输出

用户发送聊天消息后，助手回复需要以流式方式逐段出现在聊天气泡中。

流式输出需要满足：

1. 前端发送消息后立即展示“AI 正在思考中...”占位。
2. 后端通过 SSE 返回文本分片和最终业务结果。
3. 前端收到文本分片后追加到当前助手气泡。
4. 前端收到最终结果后补齐题目卡片、评分卡片、成长数据和阶段状态。
5. 流式失败时提示错误，并移除未完成的助手占位消息。

## 3. 非功能需求

1. 本迭代禁止新增单元测试代码。
2. 不提交真实密码、Token、密钥或生产连接地址。
3. 新增数据库字段必须通过 Flyway migration 管理。
4. 涉及 MySQL 表结构变化时，同步更新 `doc/中间件/MySQL.md`。
5. 不新增 Redis、Qdrant 等新中间件。
6. 代码和文档统一使用 UTF-8 简体中文。
