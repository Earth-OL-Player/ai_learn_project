# sprint2617 当期设计方案

版本：v1.0  
日期：2026-05-17  
迭代定位：成长等级、修仙境界、段位角色形象与前端展示联动设计。

## 1. 设计原则

1. 新项目无历史包袱，直接替换旧等级和旧段位规则。
2. 经验来源不变，只重构等级计算、段位映射和展示方式。
3. 后端负责输出权威等级、总经验、升级阈值和段位名称。
4. 前端负责角色全身图展示、背景融合和页面布局展示。
5. 不新增单元测试代码，通过编译构建和手工验收验证。

## 2. 总体方案

### 2.1 链路概览

```text
用户答题得分
  ↓
user_question_stats.best_score 汇总
  ↓
GrowthLevel 按每 100 总经验计算等级
  ↓
GrowthRank 按等级范围映射修仙境界
  ↓
/users/me、/growth/me、/practice/state 返回成长展示字段
  ↓
个人中心与 AI 智能刷题左侧栏展示等级、经验、境界和角色形象
```

### 2.2 改造点清单

| 模块 | 改造点 |

| ai-learn-web | 新增境界角色卡组件；个人中心和成长概览改用新展示；刷题左侧栏增加角色形象和昵称。 |

## 3. 后端设计

### 3.1 等级值对象

`GrowthLevel` 不再维护固定枚举名称，改为动态值对象：

| 字段/方法 | 说明 |
| --- | --- |
| `EXPERIENCE_PER_LEVEL = 100` | 每 100 总经验升 1 级 |
| `resolveByExperience(int experience)` | 根据总经验计算等级 |
| `displayCode()` | 返回 `LV` 加等级数字，例如 `LV3` |
| `minExperience()` | 返回当前等级起始总经验 |
| `nextLevelExperience()` | 返回下一级所需总经验 |
| `progressText(int currentExperience)` | 返回 `LV8 700/800` 形式展示文案 |

等级公式：

```text
level = floor(max(experience, 0) / 100) + 1
currentLevelExperience = (level - 1) * 100
nextLevelExperience = level * 100
```

### 3.2 修仙境界枚举

`GrowthRank` 改为修仙境界枚举，通过等级范围匹配：

| 枚举编码 | 展示名称 | 等级范围 |
| --- | --- | --- |
| `QI_REFINING` | 炼气期 | LV1~LV10 |
| `FOUNDATION_BUILDING` | 筑基期 | LV11~LV20 |
| `GOLDEN_CORE` | 金丹期 | LV21~LV30 |
| `NASCENT_SOUL` | 元婴期 | LV31~LV40 |
| `SOUL_FORMATION` | 化神期 | LV41~LV50 |
| `VOID_REFINING` | 炼虚期 | LV51~LV60 |
| `BODY_INTEGRATION` | 合体期 | LV61~LV70 |
| `MAHAYANA` | 大乘期 | LV71~LV80 |
| `TRIBULATION` | 渡劫期 | LV81~LV90 |
| `TRUE_IMMORTAL` | 真仙境 | LV91~LV100 |
| `GOLDEN_IMMORTAL` | 金仙境 | LV101~LV110 |
| `TAIYI` | 太乙境 | LV111~LV120 |
| `GREAT_LUO` | 大罗境 | LV121~LV130 |
| `DAO_ANCESTOR` | 道祖境 | LV131 及以上 |

### 3.3 成长响应字段

`GrowthResponse` 在保留兼容字段基础上新增：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `levelValue` | number | 等级数字 |
| `currentLevelExperience` | number | 当前等级起始总经验 |
| `nextLevelExperience` | number | 下一级所需总经验 |
| `levelProgressText` | string | `LV8 700/800` 展示文案 |

`levelName` 保留为空字符串，避免前端或接口调用方在过渡期解析失败，但页面不再展示等级名称。

### 3.4 当前用户摘要

`UserSummary` 同步补充上述成长展示字段。登录和 `/users/me` 查询时都会按 `user_question_stats.best_score` 汇总刷新用户成长快照，避免旧用户表字段导致展示偏差。

### 3.5 数据库迁移

新增 Flyway migration：

```text
V14__refresh_growth_realm_defaults.sql
```

内容：

1. `users.rank_code` 从 `VARCHAR(16)` 扩大到 `VARCHAR(32)`，兼容 `FOUNDATION_BUILDING` 等新编码。
2. `users.rank_code` 默认值改为 `QI_REFINING`。
3. 将历史通用段位编码统一回收为 `QI_REFINING`，后续登录、查询或答题时会按总经验刷新为正确境界编码。

## 4. 前端设计

### 4.1 角色资源方案

生成资源：

```text
ai-learn-web/public/rank-characters/realm-sprite.png
```

该图片是一张横向 14 角色原始精灵图，顺序与修仙境界映射表一致。为满足全身展示和背景融合要求，前端实际使用从精灵图拆分出的透明全身图。

### 4.2 境界角色卡组件

新增组件：

```text
ai-learn-web/src/components/growth/RealmCharacterCard.vue
```

组件职责：

1. 根据 `rank` 匹配对应透明全身图。
2. 展示当前用户昵称。
3. 展示等级经验文案。
4. 展示境界标签。
5. 不使用上下浮动动画，保证人物全身像稳定展示并与 UI 背景融合。

### 4.3 个人中心页面

`ProfilePage.vue` 调整为：

1. 顶部左侧展示头像、昵称、用户名。
2. 基础资料卡不重复展示境界角色，角色统一在成长概览展示。
3. 资料表中将“经验值/等级/段位”调整为“当前总经验/等级经验/修仙境界”。
4. 提示文案说明每 100 总经验升 1 级和经验来源。

### 4.4 成长概览面板

`GrowthOverviewPanel.vue` 调整为：

1. 左侧展示境界角色卡。
2. 右侧展示总经验、累计答题、平均得分、连续学习。
3. 等级摘要展示 `LVx 当前总经验/下级总经验 · 境界`。
4. 进度条按当前等级区间计算：

```text
(currentExperience - currentLevelExperience) / (nextLevelExperience - currentLevelExperience)
```

### 4.5 AI 智能刷题左侧栏

`PracticeAgentPage.vue` 调整为：

1. 成长卡展示“当前总经验”。
2. 小字展示 `levelProgressText · rank`。
3. 左侧引导语下方展示境界角色卡，并移除重复经验卡片。
4. 角色卡昵称取当前用户昵称，未设置时回退用户名。
5. 评分或刷题状态变化后，同步更新 Pinia 中的成长字段。

## 5. 兼容与风险控制

1. 旧 `levelName` 字段保留但不展示，降低接口兼容风险。
2. 旧通用段位编码通过 V14 migration 统一回收，后续按真实经验刷新。
3. 角色资源复制到项目公开目录，不依赖 Codex 生成图片临时目录。
4. 图片为静态资源，页面不使用上下浮动动画，不引入新依赖。
5. 本迭代不新增 Redis、Qdrant 或其他中间件。

## 6. 验证方案

1. 执行后端 Maven 编译，确认 Java 代码和 Flyway 文件无语法问题。
2. 执行前端生产构建，确认 TypeScript、Vue 模板和静态资源引用无问题。
3. 手工登录后查看个人中心，确认等级名称不再展示。
4. 手工进入 AI 智能刷题，确认左侧栏展示昵称和当前境界角色。
5. 通过数据库或答题数据构造不同总经验，抽查 `LV8 700/800` 与境界映射。
