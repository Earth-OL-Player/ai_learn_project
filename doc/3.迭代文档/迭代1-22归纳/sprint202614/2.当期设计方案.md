## 1. 架构说明

本迭代不新增服务和中间件，继续沿用三工程架构：

```text
ai-learn-web -> ai-learn-backend -> ai-service -> 可选真实模型服务；Qdrant 为后续 RAG 预留
```

问题根因集中在两个层面：

1. Java `HttpClient` 默认可能对明文 HTTP 尝试 HTTP/2 h2c 升级，本地 Uvicorn 不支持该升级方式，导致 Python 端可能收到无请求体的 POST 请求并返回 422。
2. 后端和 AI 服务的本地兜底评分把题目分类加入必答关键词，导致用户答对核心内容但没有复述分类名时被误扣分。

设计策略是保持接口不变，做最小必要修复：Java 调用固定 HTTP/1.1 和 UTF-8 JSON；评分关键词只来自参考答案；前端仅在出题消息中展示题目卡片。

## 2. 后端设计

### 2.1 AI 服务客户端链路修复

修改 `PracticeAiClient`：

- `HttpClient` 构建时固定 `HttpClient.Version.HTTP_1_1`。
- 每次 `HttpRequest` 也显式设置 HTTP/1.1。
- `Content-Type` 改为 `application/json; charset=utf-8`。
- `BodyPublishers.ofString` 显式使用 `StandardCharsets.UTF_8`。
- AI 服务非 2xx、业务失败或异常时记录脱敏告警日志，并继续使用后端本地兜底。

这样可以避免 Python Uvicorn 侧出现 h2c 升级兼容问题，并保证中文题目、参考答案、用户答案以 UTF-8 传输。

### 2.2 后端兜底评分修复

修改 `AnswerGradingDomainService`：

- 不再把 `knowledgePoints` 或题目分类加入必答关键词。
- 关键词只从标准答案中提取，包括英文技术词、常见领域短语和短文本 token。
- 增加同义表达匹配，例如：
  - `Embedding` 命中 `向量化`、`向量表示`、`嵌入模型`。
  - `Chunk` 命中 `切分`、`分块`、`文本块`。
  - `Rerank` 命中 `重排`、`精排`。
  - `Prompt` 命中 `提示词`、`上下文`。
- 题目分类仅在没有缺失点时作为复习点兜底展示，不参与扣分。

### 2.3 后端本地讨论回复优化

修改 `PracticeService` 的本地讨论兜底回复：

- 删除“你刚才关注的是……”这类复述用户问题的句式。
- 直接给出理解层次、答题结构和参考答案要点。

## 3. Python AI 服务设计

### 3.1 AI 服务兜底评分修复

修改 `ai-service/app/practice/agent_service.py`：

- `_build_keywords` 只基于 `standardAnswer` 构建评分关键词。
- `questionType` 不再作为必答关键词。
- RAG 检索片段不再作为本地评分扣分项，避免检索结果引入额外要求。
- 增加与后端一致的常见术语和同义表达匹配规则。
- 保留真实大模型优先、本地规则兜底的策略。

### 3.2 大模型提示词约束

评分提示词新增约束：

```text
不要把题目分类当作必须命中的扣分项；允许用户使用同义表达，只按是否覆盖参考答案含义评分。
```

讨论提示词新增约束：

```text
不要复述用户疑问或题目原文，直接给出解释、示例或改进建议。
```

这样可以减少真实模型可用时的重复复述和误扣分类名问题。

### 3.3 请求校验日志优化

修改 `main.py` 的参数校验异常日志：

- 记录 `content-type` 和 `content-length` 等元信息。
- 不打印请求体、内部 Token 或用户答案全文。
- 便于后续快速判断 422 是否由空请求体、错误 Content-Type 或链路传输异常导致。

## 4. 前端设计

修改 `PracticeAgentPage.vue`：

### 4.1 消息展示逻辑

- `result.action === 'QUESTION'` 时展示题目卡片。
- `GRADING` 和 `DISCUSSION` 消息只展示文本、评分或讨论内容，不重复展示题目。
- `currentQuestion` 仍然从后端响应中同步，保证重答、下一题和当前状态不受影响。

### 4.2 评分详情样式

- 评分详情折叠面板增加顶部间距。
- 展开内容增加内边距。
- 命中点、缺失点、参考答案、经验变化分别使用浅色卡片承载。
- 保持页面清新、简约、大气的视觉风格。

## 6. 验证要求

本项目当前要求禁止新增单元测试代码，本期只执行构建、语法检查和人工联调。

- 后端执行 `mvn -DskipTests package`，确认编译通过。
- 前端执行 `npm run build`，确认页面构建通过。
- Python 执行 `python -m compileall app`，确认 AI 服务代码语法正确。
- 人工启动 Python AI 服务和 Java 后端后，在 AI 智能刷题页面提交答案，确认 Python 端不再出现请求体缺失 422。
- 人工验证 RAG 分类题答题，不复述分类名也不会出现“缺少「RAG 检索增强生成」相关说明”。
- 人工验证评分详情展开后的留白和卡片样式。
