# sprint2619 当期设计方案

版本：v1.0  
日期：2026-05-17  
迭代定位：建议评论区评论流重构设计，覆盖后端数据模型、接口、前端 UI 和验收验证。

## 1. 设计原则

1. 新项目无历史包袱，旧建议标题、建议状态、左右卡片表单布局直接移除，不做兼容展示。
2. 评论区和建议区共享同一套评论流视觉语言，差异只体现在是否允许回复、是否展示建议类型。
3. 文本内容限制必须前后端双保险：前端提示体验友好，后端负责最终拦截。
4. 点赞使用独立点赞明细表记录用户行为，避免同一用户重复点赞导致数据失真。
5. 排序只实现最热和最新两种明确规则，不扩展复杂推荐算法。
6. 本迭代不新增中间件，不新增单元测试代码。

## 2. 总体方案

### 2.1 链路概览

```text
用户进入 /suggestions-comments
  ↓

  ↓
用户发布、回复或点赞
  ↓

```

## 3. 数据库设计

### 3.1 comments 表沿用字段

评论表保留 `parent_id` 和 `like_count` 字段，用于一级父子评论和点赞数排序。本次新增点赞明细表，不直接依赖前端传入点赞数。

### 3.2 suggestions 表调整

旧建议表调整为轻量评论流模型：

```sql
ALTER TABLE suggestions DROP COLUMN title;
ALTER TABLE suggestions DROP COLUMN status;
ALTER TABLE suggestions ADD COLUMN like_count INT NOT NULL DEFAULT 0 COMMENT '点赞数';
```

说明：

1. `content` 承载建议正文。
2. `type` 保留建议类型。
3. `status` 删除后不再展示待处理、已处理等状态。
4. `title` 删除后不再要求用户额外填写标题。

### 3.3 点赞明细表

新增 `comment_likes`：

| 字段 | 说明 |
| --- | --- |
| id | 点赞明细 ID。 |
| comment_id | 评论 ID。 |
| user_id | 点赞用户 ID。 |
| created_at | 点赞时间。 |

新增 `suggestion_likes`：

| 字段 | 说明 |
| --- | --- |
| id | 点赞明细 ID。 |
| suggestion_id | 建议 ID。 |
| user_id | 点赞用户 ID。 |
| created_at | 点赞时间。 |

两张表均通过 `(内容ID, user_id)` 唯一键保证单用户只能保留一次点赞状态。

## 4. 后端设计

### 4.1 作者摘要

`AuthorSummary` 扩展字段：

```json
{
  "id": "1",
  "username": "learner",
  "nickname": "AI学习者",
  "avatar": null,
  "level": "LV3",
  "levelValue": 3,
  "rank": "炼气期"
}
```

等级和段位根据用户经验值通过既有成长体系计算，前端直接展示 `level + '·' + rank`。

### 4.2 文本校验

新增统一文本校验逻辑：

1. 去除首尾空格后长度必须为 2-1000。
2. 不能包含 `@` 或全角 `＠`。
3. 不能包含常见表情符号码点和变体连接符。
4. 校验失败统一抛出业务异常，提示“仅支持纯文字，不能使用表情和艾特”。

### 4.3 评论接口

#### 4.3.1 查询评论

```http
GET /api/v1/comments?pageNo=1&pageSize=10&sort=hot
```

排序规则：

| sort | SQL 排序 |
| --- | --- |
| hot | `like_count DESC, created_at DESC, id DESC` |
| latest | `created_at DESC, id DESC` |

查询策略：

1. 只分页查询 `parent_id IS NULL` 的父评论。
2. 根据父评论 ID 批量查询一级子评论。
3. 子评论按创建时间正序展示。
4. 如果当前请求带有效登录令牌，返回 `liked=true/false`；未登录时统一为 `false`。

#### 4.3.2 创建评论

```http
POST /api/v1/comments
```

请求体：

```json
{
  "content": "这是一条纯文字评论",
  "parentId": "10001"
}
```

规则：

1. `parentId` 为空时创建父评论。
2. `parentId` 不为空时必须指向未删除父评论。
3. 仅支持一级子评论，不能对子评论继续创建孙级评论。

#### 4.3.3 点赞评论

```http
POST /api/v1/comments/{id}/like
```

接口表现为切换点赞状态：未点赞则点赞，已点赞则取消点赞，并返回该评论最新展示数据。

### 4.4 建议接口

#### 4.4.1 查询建议

```http
GET /api/v1/suggestions?pageNo=1&pageSize=10&sort=hot
```

排序规则与评论一致。响应不再返回 `title`、`status`、`statusText`。

#### 4.4.2 创建建议

```http
POST /api/v1/suggestions
```

请求体：

```json
{
  "type": "FEATURE",
  "content": "希望增加学习计划导出功能"
}
```

类型枚举：

| 编码 | 文案 |
| --- | --- |
| FEATURE | 功能建议 |
| EXPERIENCE | 体验优化 |
| BUG | 问题反馈 |
| CONTENT | 内容建议 |

#### 4.4.3 点赞建议

```http
POST /api/v1/suggestions/{id}/like
```

接口表现为切换点赞状态，并返回该建议最新展示数据。

## 5. 前端设计

### 5.1 页面结构

```text
SuggestionsCommentsPage
  ├─ 页面头部：标题、说明、轻量页签
  ├─ interaction-board
  │   ├─ board-header：标题、总数、最热/最新
  │   ├─ composer：头像、建议类型选择、输入框、发布按钮
  │   └─ feed-list：评论流列表、空状态、分页
```

### 5.2 评论流组件表达

由于本次改动范围集中在单页，先在 `SuggestionsCommentsPage.vue` 内部完成复用函数和模板分支，不额外拆分新组件，避免过度抽象。

列表项展示规则：

1. 头像使用 `el-avatar`，规则与右上角一致。
2. 作者名称后展示等级段位徽标。
3. 建议区在作者行展示建议类型标签。
4. 正文使用 `white-space: pre-wrap` 保留换行，但不解析 HTML。
5. 元信息展示时间、点赞按钮、回复按钮；建议区不展示回复按钮。
6. 子评论缩进显示，并复用头像、作者、等级段位和点赞按钮。

### 5.3 交互状态

| 状态 | 设计 |
| --- | --- |
| activeTab | `suggestions` 或 `comments`。 |
| sort | 各页签独立保存 `hot` 或 `latest`。 |
| page | 各页签独立保存页码、页大小、总数。 |
| composer | 评论区只存内容，建议区存类型和内容。 |
| replyTarget | 评论区记录当前回复的父评论 ID。 |
| liked | 由后端返回，点赞后刷新当前列表。 |

### 5.4 清理旧功能

删除以下旧表达：

1. 建议标题输入框。
2. “默认待处理”标签。
3. 建议状态标签和 `statusText` 展示。
4. 左右双卡片布局。
5. “最新评论”“最新建议”的旧卡片头刷新按钮。
6. 建议类型中的“其他”。

## 6. 验证方案

1. 执行 `mvn -DskipTests package`，确保后端编译通过且不运行单元测试。
2. 执行 `npm run build`，确保前端类型检查和生产构建通过。
3. 手工登录访问 `/suggestions-comments`，验证建议区类型选择、纯文字限制、点赞、排序和无状态展示。
4. 手工切换到评论区，验证纯文字限制、父评论、子评论、点赞、最热/最新排序和等级段位展示。
