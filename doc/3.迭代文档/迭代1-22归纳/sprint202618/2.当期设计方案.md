# sprint2618 当期设计方案

版本：v1.0  
日期：2026-05-17  
迭代定位：热门面经类 Markdown 阅读页前后端改造设计。

## 1. 设计原则

1. 新项目无历史包袱，直接替换旧查询列表页，不保留重复入口和无用状态。
2. 后端提供热门面经阅读页所需的完整题目详情列表，前端负责组装类 Markdown 文档。
3. 分类名称只生成二级标题，题目内容不进入标题体系，保证目录简洁。
4. 接口数据渲染 Markdown 时关闭原始 HTML，避免题库内容被当作页面脚本执行。
5. 不新增单元测试代码，通过前端构建、后端编译和手工验收验证。

## 2. 总体方案

### 2.1 链路概览

```text
questions 未删除题目
  ↓
QuestionMapper 查询详情字段并按分类、高频权重排序
  ↓
/questions/interview-document 返回题目详情列表
  ↓
ai-learn-web 将题目按 questionTypeText 分组
  ↓
生成类 Markdown 文本：H1 页面标题 + H2 分类标题 + 普通题目块
  ↓
markdown-it 渲染正文，IntersectionObserver 驱动目录高亮
```

### 2.2 改造点清单

| 模块 | 改造点 |
| --- | --- |
| ai-learn-backend | 新增热门面经阅读文档接口，返回未删除题目的详情列表。 |
| ai-learn-web | 替换热门面经页面，移除筛选、分页、详情弹窗，改为 Markdown 阅读布局。 |
| doc | 新增 sprint2618 需求、设计、验收文档。 |

## 3. 后端设计

### 3.1 接口设计

新增接口：

```http
GET /api/v1/questions/interview-document
```

响应数据：

```json
[
  {
    "id": "1",
    "code": "AI-RAG-001",
    "question": "RAG 为什么需要召回重排？",
    "questionType": "RAG",
    "questionTypeText": "RAG",
    "standardAnswer": "参考答案内容",
    "importanceScore": 90,
    "occurrenceCount": 12,
    "createdAt": "2026-05-17T10:00:00+08:00"
  }
]
```

设计说明：

1. 复用 `QuestionDetailResponse`，避免新增重复 DTO。
2. 只返回 `deleted = 0` 的系统题目。
3. 排序规则为分类升序、重要性降序、出现次数降序、创建时间降序、ID 降序。
4. 接口放在 `/{id}` 路由之前，并使用明确路径避免和详情接口冲突。

### 3.2 应用服务设计

`QuestionService` 新增 `findInterviewDocument()` 方法：

1. 调用 Mapper 查询完整阅读数据。
2. 将 `QuestionDetailRecord` 转换为 `QuestionDetailResponse`。
3. 保持时间、评分、分类文案转换方式与详情接口一致。

### 3.3 仓储设计

`QuestionMapper` 新增 `findInterviewDocument()`：

```sql
SELECT q.id, q.code, q.question, q.question_type, q.standard_answer,
       q.importance_score, q.occurrence_count, q.created_at, q.updated_at
FROM questions q
WHERE q.deleted = 0
ORDER BY q.question_type ASC,
         q.importance_score DESC,
         q.occurrence_count DESC,
         q.created_at DESC,
         q.id DESC
```

本次不新增表字段、不新增索引、不引入新中间件，因此无需新增数据库迁移和中间件文档。

## 4. 前端设计

### 4.1 页面结构

热门面经页面改为：

```text
InterviewQuestionsPage
  ├─ markdown-layout
  │   ├─ markdown-toc-card：分类目录、收起按钮、激活态
  │   └─ markdown-card：类 Markdown 正文、加载态、空状态
```

### 4.2 Markdown 生成规则

前端根据接口数据生成 Markdown 文本：

```markdown
# 热门面经

精选 AI、RAG、Agent 等方向真实面试高频题，按分类连续阅读。

## RAG

**题目 1：RAG 为什么需要召回重排？**

> 题目编码：AI-RAG-001 ｜ 重要性：90 ｜ 真实面试出现次数：12

参考答案内容
```

注意事项：

1. `## 分类名称` 是唯一进入目录的业务标题。
2. 题目使用加粗普通文本，不使用 `###` 标题。
3. 标题 ID 通过分类名称生成，重复分类自动追加序号兜底。
4. 题目、分类等插入 Markdown 结构的内容会转义 Markdown 控制字符。

### 4.3 Markdown 渲染配置

`markdown-it` 配置如下：

| 配置 | 值 | 说明 |
| --- | --- | --- |
| html | false | 禁止接口数据中的原始 HTML 直接执行。 |
| linkify | true | 自动识别链接。 |
| breaks | false | 保持标准 Markdown 段落规则。 |

外部链接统一补充 `target="_blank"` 和 `rel="noreferrer"`。

### 4.4 目录交互设计

1. 目录项来自 Markdown 中的 `##` 分类标题。
2. 点击目录项更新当前激活项，并跳转到对应分类锚点。
3. 使用 `IntersectionObserver` 监听右侧正文中的 `h2[id]`。
4. 组件卸载时断开 Observer，避免页面切换后残留监听。

### 4.5 旧代码清理

`InterviewQuestionsPage.vue` 删除以下状态和方法：

1. 筛选表单相关状态和查询方法。
2. 分页状态。
3. 详情弹窗状态和详情加载方法。
4. 分类下拉数据加载。
5. 重要性标签样式方法和时间格式化方法。

## 5. 验证方案

1. 执行 `npm run build`，确保前端类型检查和构建通过。
2. 执行 `mvn -DskipTests package`，确保后端编译通过且不运行单元测试。
3. 手工登录后访问 `/interview-questions`，检查左侧目录、右侧正文、分类标题、题目普通正文展示和旧查询样式清理结果。
