## 1. 当期目标

在已有页面和工程底座上，补充真实用户体系，让平台具备注册、登录、退出、当前用户、基础权限引导和个人中心基础展示能力。

完成后应达到：

- 用户可以注册、登录和退出。
- 前端刷新后可以恢复登录态。
- 游客访问受保护页面时看到“登录后即可使用该功能”。
- 登录用户可以访问个人中心基础页。
- 后端使用 MySQL 保存用户，密码加密存储。

## 4. 接口需求

统一前缀：`/api/v1`。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/register` | 游客 | 注册，成功返回 token 和用户摘要 |
| POST | `/auth/login` | 游客 | 登录，成功返回 token 和用户摘要 |
| POST | `/auth/logout` | 登录用户 | 退出登录 |
| GET | `/users/me` | 登录用户 | 当前用户信息 |

登录成功响应 `data`：

```json
{
  "accessToken": "access_token占位符",
  "tokenType": "Bearer",
  "expiresIn": 7200,
  "user": {
    "id": "用户ID占位符",
    "username": "demo_user",
    "nickname": "演示用户",
    "avatar": null,
    "email": "demo@example.com",
    "experience": 0,
    "level": "Lv1",
    "levelName": "AI 入门者",
    "rank": "青铜",
    "createdAt": "2026-05-14T00:00:00+08:00"
  }
}
```

## 5. 安全要求

- 密码必须使用 BCrypt 或 Argon2 哈希保存。
- 响应中禁止返回 `passwordHash`。
- JWT 密钥通过环境变量或本地私有配置提供，示例配置只写占位符。
- token 不允许放在 URL 查询参数中。
- 认证失败返回 `AUTH_UNAUTHORIZED`，用户名重复返回 `RESOURCE_CONFLICT`。

## 6. 验收标准

- 可以完成注册，数据库中保存密码哈希而不是明文。
- 重复用户名注册失败并给出明确提示。
- 正确密码可登录，错误密码登录失败。
- 登录成功后右上角展示用户信息。
- 刷新页面后前端能通过 `/users/me` 恢复登录态。
- 游客访问面试题、AI智能刷题、个人中心时看到登录引导。
- 退出登录后 token 和用户信息被清理。
