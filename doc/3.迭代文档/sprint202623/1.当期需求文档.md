# sprint2623 当期需求文档

版本：v1.1  
日期：2026-05-22  
迭代定位：个人中心支持昵称和性别编辑，系统内部按性别切换人物形象

## 1. 背景

当前用户注册后昵称只能在注册阶段填写，个人中心只能查看基础资料，无法在后续学习过程中调整昵称。用户表也没有性别字段，个人中心无法展示用户是否已设置性别。

本迭代的用户可感知功能域只包含“编辑昵称”和“编辑性别”：用户在个人中心看到昵称、性别，并能打开编辑弹窗完成保存。性别未设置时，前端统一展示为 `-`。

人物形象切换属于系统内部展示逻辑，不在个人资料编辑区向用户体现“默认形象”“人物形象”等概念。系统只根据用户性别自动决定个人中心成长概览和 AI 智能刷题页的人物形象。

## 2. 需求范围

### 2.1 用户资料字段

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2623-R01 | 用户新增 `gender` 性别字段，注册时不填写，默认保存为空。 | P0 |
| S2623-R02 | 当前用户查询接口返回性别字段，前端登录态和个人中心可直接读取。 | P0 |
| S2623-R03 | 性别只支持空、男、女三种业务状态，接口层使用 `MALE`、`FEMALE` 或空值。 | P0 |

### 2.2 个人中心编辑

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2623-R04 | 用户可在个人中心打开“编辑资料”弹窗，编辑昵称和性别。 | P0 |
| S2623-R05 | 性别为空时，个人中心展示 `-`；编辑弹窗中性别选择支持清空。 | P0 |
| S2623-R06 | 昵称编辑必须校验非空、长度不超过 64 位，并沿用昵称唯一性校验。 | P0 |
| S2623-R07 | 用户保存资料成功后，页面和全局登录态立即刷新，无需重新登录。 | P0 |
| S2623-R08 | 资料编辑交互保持清新简约，保存中状态、错误提示和移动端布局清晰可用。 | P1 |

### 2.3 系统内部形象适配

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2623-R09 | 系统内部在性别为空或女性时，继续展示当前女性修仙人物形象套图。 | P0 |
| S2623-R10 | 系统内部在性别为男性时，AI 智能刷题页和个人中心成长概览展示男性人物形象套图。 | P0 |
| S2623-R11 | 男性人物形象需要与当前女性套图保持同一修仙境界体系和卡片尺寸，避免页面跳动。 | P1 |

## 3. 非功能要求

1. 不编写单元测试代码，本迭代只做功能开发、编译和构建验证。
2. 代码注释和文档统一使用 UTF-8 简体中文。
3. 不新增 MySQL、Redis、Qdrant 等中间件类型；数据库结构调整通过 Flyway migration 发布。
4. 不提交真实密码、Token、密钥、生产连接地址等敏感信息。
5. 前端 UI 保持清新、简约、大气，表单控件需要有清晰标签、加载态和错误提示。

## 4. 验收标准

| 编号 | 验收项 | 验收标准 |
