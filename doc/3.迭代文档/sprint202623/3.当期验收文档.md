## 2. 前端页面和功能验收

### 2.1 用户性别字段和当前用户接口

验收步骤：

1. 启动 MySQL 和 ai-learn-backend，确认 Flyway 自动执行成功。
2. 注册一个新用户，注册表单不填写性别。
3. 使用登录 token 调用 `GET /api/v1/users/me`。

验收点：

- `users` 表包含 `gender` 字段。
- 新注册用户 `users.gender` 默认为 `NULL`。
- 当前用户接口返回 `gender` 字段，空值不影响登录和个人中心展示。

### 2.2 个人中心资料展示

验收步骤：

1. 登录普通用户，进入个人中心。
2. 查看基础资料卡中的用户名、昵称、性别、邮箱和注册时间。
3. 确认当前用户没有设置性别时的展示。

验收点：

- 性别为空时，个人中心展示 `-`。
- 基础资料卡只展示用户资料，不出现“默认形象”“人物形象”等系统内部文案。
- 页面顶部提供清晰的“编辑资料”入口。

### 2.3 编辑昵称和性别

验收步骤：

1. 在个人中心点击“编辑资料”。
2. 在弹窗中修改昵称。
3. 在性别下拉框中选择“男”并保存。
4. 再次打开弹窗，选择“女”并保存。
5. 再次打开弹窗，清空性别并保存。

验收点：

- 弹窗只包含“昵称”和“性别”两个可编辑字段。
- 性别下拉框只提供“男”“女”，并支持清空。
- 保存按钮展示加载态，保存成功后提示“资料已保存”并关闭弹窗。
- 昵称、性别展示立即更新，无需重新登录。
- 清空性别后，个人中心性别展示为 `-`。

### 2.4 昵称重复校验

验收步骤：

1. 准备两个普通用户。
2. 登录用户 A，进入个人中心编辑资料。
3. 将昵称修改为用户 B 已占用的昵称并保存。

验收点：

- 页面提示“昵称已被使用，请更换后重试”。
- 用户 A 原昵称不被覆盖。
- 弹窗仍保留当前输入，方便用户继续修改。

### 2.5 系统内部人物形象切换

验收步骤：

1. 在个人中心将性别保存为“男”。
2. 观察个人中心成长概览和 AI 智能刷题页左侧人物形象。
3. 将性别保存为“女”或清空。
4. 再次观察个人中心成长概览和 AI 智能刷题页左侧人物形象。

验收点：

- 性别为男时，系统内部展示男性人物形象。
- 性别为空或女时，系统内部展示当前女性人物形象。
- 人物形象切换不影响个人资料编辑交互，也不影响刷题、重答、发送答案等原有流程。
