# sprint2616 当期设计方案

版本：v1.0  
日期：2026-05-17  
迭代定位：答题功能优化设计，围绕当前题上下文记忆、智能相关性判断、Markdown 渲染和 SSE 流式输出做轻量改造。

## 1. 设计原则

1. 聚焦刷题链路，不重构无关模块。
2. 新增状态只保存当前题必要上下文，不引入完整聊天记录表。
3. 真实模型优先，模型不可用时保留本地兜底，保证刷题主流程可用。
4. 前端增强展示不改变原有卡片主结构，保持清新简约。
5. 不新增单元测试代码，仅执行构建、语法检查和手工验收。

## 2. 总体方案

### 2.1 链路概览

```text
用户输入
  ↓
ai-learn-web PracticeAgentPage
  ↓
ai-learn-backend PracticeController / PracticeService
  ↓
ai-service PracticeAgentService
  ↓
真实大模型 或 本地兜底规则
```

| 模块 | 改造点 |

| ai-learn-web | 聊天消息改用 SSE 流式接口；Markdown 渲染；重答清空快照；经验 tooltip。 |

| doc | 新增本迭代需求、设计、验收文档，并更新 MySQL / AI模型服务说明。 |

## 3. 后端设计

### 3.1 当前题答案记忆

`user_practice_sessions` 新增字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `last_answer_text` | `TEXT NULL` | 保存当前题最近一次用户答案，用于讨论阶段提供上下文。 |

处理规则：

1. 抽取下一题或重答本题时，`last_answer_text` 置空。
2. 当前题评分完成后，保存本次用户答案，最多保留 4000 字符。
3. 讨论阶段调用 AI 服务时，将题目、参考答案、最近答案和用户追问一起传入。
4. 该字段只保存当前题最近答案，不保存完整聊天记录。

### 3.2 经验变化详情

`PracticeGradingResponse` 新增增强字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `previousBestScore` | number | 评分前历史最高分 |
| `previousLastScore` | number/null | 评分前最近一次得分 |
| `experienceDetail` | string | 前端 tooltip 展示文案 |

后端根据 `user_question_stats` 的旧记录生成文案：

1. 无旧记录：首次回答文案。
2. 本次得分超过历史最高分：突破文案。
3. 本次得分未超过历史最高分：经验不变文案。

### 3.3 智能相关性判断

后端新增 `PracticeAiClient.judgeRelevance`，调用 AI 服务：

```text
POST /internal/v1/practice/relevance
```

请求包含：

1. 当前题编码、题目、分类、参考答案。
2. 当前阶段：`ANSWERING` 或 `DISCUSSING`。
3. 用户输入内容。

AI 服务返回：

```json
{
  "relevant": true,
  "reason": "与当前题技术讨论相关"
}
```

后端处理规则：

1. AI 服务返回 `relevant=false` 时拦截并提示围绕刷题或本题讨论。
2. AI 服务不可用、未启用或解析异常时，回退到本地明显无关词兜底。
3. 本地兜底只拦截天气、新闻、股票、旅游、做饭、写诗、翻译、笑话、颜值等明显无关内容，避免误伤正常技术表达。

### 3.4 SSE 流式聊天接口

后端新增：

```text
POST /api/v1/practice/messages/stream
Accept: text/event-stream
```

事件设计：

| 事件名 | data | 含义 |
| --- | --- | --- |
| `message` | 文本片段 | 助手回复的分片内容 |
| `result` | `PracticeMessageResponse` JSON | 最终业务结果，用于补齐题目、评分、成长状态 |
| `error` | 错误文案 | 流式处理失败提示 |

实现方式：

1. Controller 使用 `SseEmitter` 输出事件。
2. 异步线程恢复 `AuthContext`，复用原有刷题阶段判断和权限校验。
3. 讨论阶段通过 AI 服务 `/internal/v1/practice/discuss/stream` 读取真实模型流式片段，并透传给前端。
4. 出题和评分阶段仍需要完整业务结果，无法在结构化评分完成前展示最终卡片，因此保留完成后分片输出提示文案。
5. 最后发送完整业务 JSON，前端据此补齐题目、评分和成长信息。
6. 前端仍保留原非流式接口，便于其他调用方兼容。

## 4. AI 服务设计

### 4.1 讨论提示词补充上下文

`PracticeDiscussRequest` 新增：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `lastUserAnswer` | string | 当前题最近一次用户答案 |

讨论提示词增加说明：

- 如果用户询问刚刚的题目、刚刚提交的答案或评分依据，优先使用上下文准确回答。
- 上下文包含题目分类、题目、参考答案、用户刚刚提交的答案和用户疑问。

### 4.2 相关性判断提示词

AI 服务新增 `judge_relevance` 能力：

1. 要求模型只返回 JSON。
2. 明确相关和无关示例。
3. 不确定时返回 `relevant=true`，避免误伤。
4. 解析失败时返回空结果，由后端使用本地兜底规则。

### 4.3 讨论阶段真实流式输出

AI 服务新增：

```text
POST /internal/v1/practice/discuss/stream
```

处理规则：

1. 启用真实模型时，调用 OpenAI 兼容 Chat Completions 接口并传入 `stream=true`。
2. 逐行读取模型返回的 SSE 数据，从 `choices[0].delta.content` 提取可见文本片段。
3. 将每个文本片段封装为内部 SSE `message` 事件返回给 Java 后端。
4. 模型不支持流式、未返回可见 token 或调用异常时，回落到非流式讨论或本地兜底提示。

## 5. 前端设计

### 5.1 流式消息处理

前端新增 `postStream` 通用方法解析 SSE：

1. 读取 `ReadableStream`。
2. 按 SSE 空行拆分事件块。
3. 解析 `event:` 和 `data:`。
4. `message` 事件追加到当前助手气泡。
5. `result` 事件反序列化为 `PracticeMessageResult`，补齐业务卡片。

### 5.2 Markdown 渲染

聊天气泡使用 `markdown-it` 渲染：

1. `html=false`，不渲染原始 HTML。
2. `breaks=true`，保留换行体验。
3. 样式支持标题、段落、列表、加粗和行内代码。
4. 用户消息和助手消息复用同一安全渲染方式。

### 5.3 重答清理

点击“重答本题”后：

1. 后端重置当前会话阶段为 `ANSWERING` 并清空 `last_answer_text`。
2. 前端以 `clearMessages=true` 应用响应。
3. 本地聊天快照先清空再保存新重答提示。

### 5.4 经验 tooltip

评分卡片原经验浮标外层增加 `el-tooltip`：

1. 优先展示后端 `experienceDetail`。
2. 旧接口缺少该字段时，前端根据 `earnedExperience` 做兼容兜底。
3. tooltip 使用浅色效果，避免破坏清爽 UI。

## 7. 风险与兼容性

| 风险 | 处理方式 |
| --- | --- |
| AI 服务未升级 | 后端相关性判断返回空时走本地关键词兜底；讨论上下文为空也兼容。 |
| SSE 被浏览器或代理中断 | 前端捕获错误并移除未完成助手占位消息。 |
| Markdown XSS | `markdown-it` 禁用 HTML，避免原始标签渲染。 |
| 答案过长 | 后端最多保存 4000 字符作为当前题上下文。 |
| 历史数据库缺字段 | 通过 Flyway V13 自动补齐。 |
