# sprint2619 当期需求文档

版本：v1.0  
日期：2026-05-17  
迭代定位：建议评论区按 B 站评论区观感重新设计，评论区支持文字、点赞、父子评论和排序，建议区在相同 UI 基础上兼容建议类型且移除处理状态。

## 1. 背景与目标

当前建议评论区仍保留表单卡片、建议标题、建议处理状态等偏管理后台的表达方式，和截图中 B 站评论区的轻量交流体验差距较大。本迭代需要彻底替换旧功能和旧 UI：评论区聚焦纯文字交流，建议区在同一套评论流体验上增加建议类型选择，减少无关字段和管理状态。

本迭代目标如下：

1. 评论区视觉和交互参考截图中的 B 站评论区：顶部标题、评论总数、最热/最新排序、头像输入框、列表项、点赞与回复。
2. 评论只能发送文字，不能发送表情、艾特人，也不提供转发到动态能力。
3. 评论作者名称后展示用户等级与段位，格式为 `LVX·段位`。
4. 评论支持点赞、一级父子评论，并支持按最热和最新排序。
5. 不支持“UP主觉得很赞”“互相关注”等 B 站关系标签。
6. 建议区复用评论区 UI 和功能表达，但不能父子评论。
7. 建议区可选择建议类型：功能建议、体验优化、问题反馈、内容建议。
8. 建议列表查询时展示建议类型，不再展示或设置待处理、已处理等状态。
9. 删除旧建议标题、旧状态标签、旧左右表单卡片等过时功能表达。

## 2. 需求范围

### 2.1 评论区功能

| 功能 | 要求 |
| --- | --- |
| 发表评论 | 登录后可发表 2-1000 字纯文字评论。 |
| 内容限制 | 禁止表情字符、`@`、全角 `＠`，不提供图片、表情面板、艾特选择器和转发到动态入口。 |
| 默认头像 | 评论输入框和评论列表头像使用系统右上角头像相同规则：有头像用头像，无头像展示用户名或昵称首字。 |
| 作者信息 | 作者名称后展示 `LVX·段位`，等级和段位来自用户成长体系。 |
| 点赞 | 登录用户可对评论点赞或取消点赞，展示最新点赞数。 |
| 父子评论 | 支持一级子评论，父评论下展示回复列表；不设计孙级评论。 |
| 排序 | 最热按点赞数倒序，最新按发布时间倒序。 |
| 不支持项 | 不展示“UP主觉得很赞”“互相关注”“点踩”“转发到动态”。 |

### 2.2 建议区功能

| 功能 | 要求 |
| --- | --- |
| 提交建议 | 登录后选择建议类型并填写 2-1000 字纯文字内容。 |
| 建议类型 | 仅支持功能建议、体验优化、问题反馈、内容建议四类。 |
| 列表展示 | 查询列表时展示建议类型、作者、等级段位、时间和点赞数。 |
| 点赞 | 登录用户可点赞或取消点赞建议。 |
| 排序 | 最热按点赞数倒序，最新按发布时间倒序。 |
| 不支持项 | 不支持父子建议，不展示处理状态，不再填写建议标题。 |

### 2.3 页面结构

1. 页面保留“建议区”和“评论区”两个页签，默认进入建议区。
2. 每个页签内部使用同一套轻量评论流布局。
3. 顶部展示标题、总数、最热/最新切换。
4. 输入区使用头像 + 圆角大输入框 + 发布按钮的横向结构。
5. 列表项使用头像、作者、等级段位、正文、时间、点赞、回复入口的纵向结构。
6. 空状态文案保持轻量，不出现旧卡片式待处理提示。

## 3. 后端接口需求

### 3.1 评论接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/comments?pageNo=1&pageSize=10&sort=hot` | 查询父评论分页，并携带子评论。 |
| POST | `/api/v1/comments` | 发表评论或一级子评论。 |
| POST | `/api/v1/comments/{id}/like` | 点赞或取消点赞评论。 |

评论响应需要包含：评论 ID、内容、父评论 ID、点赞数、当前用户是否已点赞、回复数、作者摘要、子评论列表、创建时间。

### 3.2 建议接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/suggestions?pageNo=1&pageSize=10&sort=hot` | 查询建议分页。 |
| POST | `/api/v1/suggestions` | 提交建议。 |
| POST | `/api/v1/suggestions/{id}/like` | 点赞或取消点赞建议。 |

建议响应需要包含：建议 ID、内容、建议类型、建议类型文案、点赞数、当前用户是否已点赞、作者摘要、创建时间。

## 4. 非功能需求

1. 本迭代禁止新增单元测试代码。
2. 不引入新的 MySQL、Redis、Qdrant 等中间件依赖。
3. 数据库结构变更通过 Flyway 迁移完成，不提交真实密码、Token、密钥或生产连接地址。
4. 后端对内容限制做最终校验，前端做即时提示，避免绕过页面后写入非法内容。
5. 前端 UI 保持清新、简约、大气，避免过度拟物和复杂动效。
6. 代码和文档统一使用 UTF-8 简体中文。
