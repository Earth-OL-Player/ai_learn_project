# sprint2622 当期需求文档

版本：v1.0  
日期：2026-05-18  
迭代定位：AI智能刷题服务 LangChain/LangGraph 化、多轮上下文记忆增强、无关问题本地拦截提速

## 1. 背景

当前 AI 智能刷题功能已支持智能抽题、答案评分、本题讨论、流式回复、经验成长和勋章反馈，但 AI 服务层仍通过 Python 标准库 `urllib.request` 直接调用 OpenAI 兼容 `/chat/completions` 接口，提示词、结构化解析、流式解析和兜底逻辑都散落在业务代码中，维护成本较高。

同时，当前“短期记忆”只包含当前题、参考答案、最近一次答案和当前疑问；当用户进行多轮追问时，大模型无法感知前序疑问和回答，容易在“刚才说的方案”“第二点是什么意思”等指代问题上丢失上下文。

本迭代基于 LangChain 官方文档和当前可用版本，将 AI 服务重构为 LangChain 1.3 写法，并在讨论链路引入 LangGraph 进行会话状态编排，提升代码可维护性和多轮对话体验。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2622-R01 | AI 服务依赖升级为 `langchain==1.3.1`、`langchain-openai`、`langgraph`，不再手写 `urllib.request` 调用大模型。 | P0 |
| S2622-R02 | 答案评分继续支持真实大模型结构化评分和本地规则兜底，响应字段保持不变。 | P0 |
| S2622-R03 | 本题讨论继续支持非流式和流式回复，前后端接口路径和主要响应结构保持不变。 | P0 |
| S2622-R04 | 大模型未配置、模型调用失败或结构化结果异常时，仍必须保持本地兜底能力。 | P0 |

### 2.2 无关问题本地拦截

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| S2622-R05 | Java 后端不再调用 AI 服务进行相关性判断，避免额外大模型调用增加用户等待时间。 | P0 |
| S2622-R06 | 答题阶段和讨论阶段仍保留本地关键词拦截明显无关问题。 | P0 |
| S2622-R07 | Python AI 服务下线 `/internal/v1/practice/relevance` 相关代码，避免保留无用链路。 | P1 |

### 2.3 当前题多轮上下文增强

| 编号 | 需求 | 优先级 |

| S2622-R09 | 后端持久化当前题 AI 评分摘要，作为后续追问上下文。 | P0 |

| S2622-R12 | 多轮历史需要限制长度，避免异常长上下文拖慢模型调用。 | P0 |

| --- | --- | --- |

| S2622-R14 | Java 后端负责维护服务端会话记忆，并把评分摘要和历史传给 AI 服务。 | P0 |

## 3. 非功能要求

1. 不编写单元测试代码，本迭代仅做功能开发和构建/编译验证。
2. 代码注释和文档统一使用 UTF-8 简体中文。
3. 不提交真实密码、Token、密钥、生产连接地址等敏感信息。
4. 不新增 MySQL、Redis、Qdrant 等中间件类型；如新增数据库字段，应通过 Flyway 后续迁移实现。
5. LangChain/LangGraph 代码写法以官方文档为准，不虚构框架能力。
6. 保持 AI 服务在未配置真实大模型时仍可启动并使用本地评分兜底。
