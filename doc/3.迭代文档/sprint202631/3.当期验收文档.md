## 2. 前端页面和功能验收

### 2.1 登录入口、面板与主题

验收步骤：

1. 游客访问首页，登录后观察右下角圆形助手按钮。
2. 展开面板，切换站内页面，再收起和展开；使用 Escape 收起。
3. 切换深浅主题，在手机宽度检查按钮、对话框、步骤条及底部导航。
4. 退出登录，再以另一账号登录。

验收点：

- 游客看不到入口；登录后显示 56px 圆形按钮，桌面对话框约占可视面积四分之一。
- 面板随布局跨页面保留，主题与本站一致，手机不横向溢出，操作时折叠为步骤条。
- 输入支持 Enter 发送、Shift + Enter 换行；手机面板内 Tab 焦点循环，Escape 后焦点返回入口。
- 退出或切换账号立即清除旧账号消息、任务和本地原稿恢复槽，迟到响应不串号。

### 2.2 项目问答、导航与个人信息

验收步骤：

1. 询问“怎么开始 AI 智能刷题”“评论和建议有什么区别”。
2. 点击回答的站内来源；发送“打开评论区”“打开路线和资料”“打开个人中心”。
3. 查询“我的模型权益”“我的成长”“我的刷题统计”；查询最新或热门评论、建议。
4. 在管理端维护模型配置，使用 BASIC、PRO、SUPER 对应权益账号分别验证，并与该账号的刷题模型比较。

验收点：

- 展示实际流式文本；来源链接来自公开知识索引和站内白名单。
- 评论导航进入评论页签，建议导航进入建议页签；不能操作任意网址或管理端。
- 个人查询只使用当前登录身份；动态数据取自业务服务。
- 助手与刷题共用模型选择和工厂；任务中途模型权益或配置变更时终止当前任务，重新发送后使用新配置。
- 无真实模型、AI 服务关闭或工具不兼容时明确提示，不伪造执行成功。

### 2.3 真实表单填写、发布与回复

验收步骤：

1. 发送“把‘学习路线很清晰’填入评论框，先不要发”。
2. 发送“帮我提交一条‘学习路线很清晰’的评论”。
3. 发送“帮我写一条功能建议并发布”，查看表单内容后确认发布；另一次选择保留草稿并取消。
4. 在评论列表点击明确父评论的“回复”，发送“帮我回复‘谢谢分享’”。
5. 检查列表新增记录和数据库结果；重放同一提交请求。

验收点：

- 助手确实导航、定位、滚动、填写响应式表单，建议选择实际类型，回复打开实际回复框。
- 目标控件显示静态高亮、AI 光标、步骤文字；提交显示点击反馈，成功定位新增记录。
- “仅填写”结束后保留草稿，数据库不新增业务记录；生成或不明确授权的内容必须等待确认。
- 明确发布原文可直接执行；无法可靠验证的表达保守进入确认。正文遵守现有 2～1000 位纯文字校验，不静默改写。
- 业务提交使用与手工表单相同的校验和页面更新逻辑；后端写入与幂等结果原子提交，重复请求返回同一记录。
- 回复只能写入明确父评论下，不能猜测回复对象或创建多级回复。

### 2.4 原有草稿、暂停和用户接管

验收步骤：

1. 先手工填写未提交内容，再让助手填写不同内容。
2. 选择保留原稿并填写新内容，随后点击“恢复保留的原草稿”；另一次选择追加。
3. 操作途中暂停；修改正文后选择“采用表单正文”，继续检查并确认。
4. 选择“我来操作”或“停止”；待确认时手工切换页签、修改内容，观察任务暂停。
5. 刷新页面后打开助手，点击继续；过期后重新发送任务。

验收点：

- 非空草稿不会自动被覆盖；替换和追加需要用户选择，原稿在当前页面内存中可恢复。
- 暂停保留任务和草稿；接管取消后续自动提交，页面仍可手工操作。
- 正文修改产生新版本并撤销旧授权；旧版本确认、旧执行代数回执被拒绝。
- 刷新恢复会重新检查页面和控件，不复用旧坐标；用户未保存原稿恢复槽不跨刷新持久化。
- 更换建议类型或回复目标时，应停止后重新发起明确指令；“采用表单正文”只更新正文。
- 目标缺失、页面加载超时、提交失败时保留草稿并停止后续步骤；减弱动态效果模式仍完成真实填写和文字反馈。
