所有真实账号、密码、地址和 Token 只能放私有配置、环境变量或管理端，不写入本文件。开发验证的模拟模型地址、临时账号与临时数据库配置不能用于正式部署。

## 2. 数据库变更

新增迁移：[V11__add_site_assistant.sql](../../../ai-learn-backend/src/main/resources/db/migration/V11__add_site_assistant.sql)。未修改 V1～V10，没有外键，没有新增审计或权限模型。

| 新表 | 用途 | 关键约束 |
| --- | --- | --- |
| `assistant_session` | 当前用户会话及到期时间 | 用户/更新时间、到期时间索引 |
| `assistant_run` | 每轮指令、模型指纹、状态、页面上下文、执行代数和租约 | `(user_id, client_request_id)` 唯一，防止重放创建新任务 |
| `assistant_message` | 用户、模型及 ToolMessage 协议历史 | 会话/递增 ID 索引 |
| `assistant_operation` | 固定动作计划、正文版本与哈希、授权、步骤位置及发布结果 | `(run_id, tool_call_id)` 唯一；业务写入和结果在同一事务内完成 |

建议和评论继续写入现有业务表，助手表不保存模型 Key 或完整 JWT。默认会话/消息保留 7 天；任务从创建起 10 分钟有效，暂停和确认不会延长；终态任务/操作记录保留 30 天。后端每分钟处理过期任务及执行租约，每小时清理过期助手数据，不删除已发布评论、建议或刷题数据。

发布步骤：

1. 依照已有中间件文档备份业务库，发布新版 Java 后端。
2. 保持 `SPRING_FLYWAY_ENABLED=true`，让 Flyway 执行新增 V11。
3. 确认下面查询返回版本 11、成功标识及四张新表。
4. 发布新版 ai-service 和前端，按验收文档联调。

```sql
SELECT version, description, success
FROM flyway_schema_history WHERE version = '11';
SHOW TABLES LIKE 'assistant_%';
SHOW INDEX FROM assistant_run;
SHOW INDEX FROM assistant_operation;
```

若部署流程集中执行迁移而应用关闭 Flyway，应在部署迁移环节使用 Flyway 执行同一新增版本，完成后再启动应用。不要只手工建四张表却遗漏迁移记录，否则后续重新开启 Flyway 会发生表已存在冲突。确实采用纯手工 SQL 管理的环境，应由数据库维护者执行 V11 原文并统一迁移记录策略，不自动修改 Flyway 历史或 checksum。

当前 Maven 使用 Spring Boot 3.3.6 管理的 Flyway 10.10.0。本次 MySQL 8.4.11 迁移成功，但有“数据库版本高于已测试范围”的告警；此前中间件文档中的“已显式使用 12.6.1”与实际不符，已修正。本期没有升级 Flyway，生产 TDSQL 兼容性应按原部署环境验证。

## 3. 配置变更

Java 新变量，均已写入 `ai-learn-backend/.example.env` 和 `application.yml`：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `ASSISTANT_SESSION_RETENTION_DAYS` | `7` | 会话及消息有效天数 |
| `ASSISTANT_OPERATION_RETENTION_DAYS` | `30` | 终态运行与操作幂等记录保留天数 |
| `ASSISTANT_CONFIRMATION_TTL_MINUTES` | `10` | 整轮任务、页面动作及确认有效分钟数，从创建起计算 |
| `ASSISTANT_MAX_TOOL_CALLS` | `8` | 每轮外部业务工具调用上限；前端定位、填写等步骤不额外消耗模型调用 |
| `ASSISTANT_RUN_TIMEOUT_SECONDS` | `120` | 每段活动执行预算和租约秒数；等待用户或浏览器时结束流并释放线程 |

Python 新变量，均已写入 `ai-service/.example.env`：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `AI_ASSISTANT_MODEL_TIMEOUT_SECONDS` | `60` | 单次助手模型调用超时秒数 |
| `AI_ASSISTANT_GRAPH_RECURSION_LIMIT` | `24` | 单段 LangGraph 图递归上限 |

已有配置继续生效：`DATABASE_URL`、`DATABASE_USERNAME`、`DATABASE_PASSWORD`、`JWT_SECRET`、`AI_SERVICE_ENABLED`、`AI_SERVICE_BASE_URL`、`AI_SERVICE_TOKEN`、用户模型权益及 `model_configs`。`AI_SERVICE_TIMEOUT_SECONDS` 保留给原刷题调用；助手内部流使用新的活动预算，不要误认为调整原变量即可调整助手预算。

助手新消息复用现有 AI 请求频率限制，助手发布复用现有评论写入频率限制；额外通过数据库保证每用户最多一个活跃助手任务。已有 AI 流线程池继续共用，不新增 Redis。会话换档或配置变更时会终止旧任务，下一轮重新解析模型。

私有环境占位示例：

```dotenv
# Java 私有环境；Token 真实值请自行生成，禁止提交仓库。
AI_SERVICE_ENABLED=true
AI_SERVICE_BASE_URL=http://127.0.0.1:8000
AI_SERVICE_TOKEN=<两端一致的内部Token占位符>
ASSISTANT_RUN_TIMEOUT_SECONDS=120
ASSISTANT_CONFIRMATION_TTL_MINUTES=10

# Python 私有环境；Token 与 Java 相同，模型优先使用 Java 传入的用户配置。
AI_SERVICE_TOKEN=<两端一致的内部Token占位符>
AI_ASSISTANT_MODEL_TIMEOUT_SECONDS=60
AI_ASSISTANT_GRAPH_RECURSION_LIMIT=24
```

模型需要支持当前 LangChain 供应商适配、流式输出和 `tools`。仅对明确的“不支持 tools”协议错误降级为文本回答，并提示操作不可用；认证、网络、模型未配置错误直接提示失败，不切换到另一模型、不根据普通 JSON 文本执行操作。

## 4. 构建、知识索引与代理

没有新增或升级 npm、Maven、Python 依赖。新环境按照项目现有锁文件和 requirements 安装依赖；Java 构建需要 JDK 17 以上。本机系统默认 Java 8 不适用，本次使用已有 IDE 自带 JDK 完成构建。

`package-lock.json` 中部分依赖解析地址是内网镜像，外部开发者需确保镜像可访问，或经仓库维护者同意更新镜像解析地址。本次仅在忽略目录中转换下载地址并填充本地缓存，未修改锁文件、依赖版本。

助手公开知识位于 `ai-service/app/assistant/knowledge/`，只索引根 README、前端公开学习 Markdown 和人工维护的公开功能说明。更新公开资料后，在 ai-service 目录执行：

```powershell
python -m app.assistant.build_knowledge
```

生成的 `public-index.json` 随源码部署，不需要 MySQL 知识表、embedding 服务或向量库。生产只需部署 ai-service 工程，无需读取完整仓库或内部配置目录。

Nginx/宝塔的助手流式接口配置可参考下面片段，并合并到现有站点；普通 `/api/` 代理保持原设置：

```nginx
location ~ ^/api/v1/assistant/(sessions/[^/]+/messages|runs/[^/]+/(continue|resume))/stream$ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 150s;
}
```

若调整活动预算，代理读取超时应相应更长；前端助手流有 180 秒等待上限，预算高于该值时还需同步调整 `api/assistant.ts` 的上限。助手状态和提交请求 15 秒超时，超时后查询持久化结果，不自动重发。前端、Java 和 ai-service 应一起发布；Python 内部端口不对公网开放。无需在生产应用 CVM 上额外安装本地 MySQL，继续连接文档中的 TDSQL。
