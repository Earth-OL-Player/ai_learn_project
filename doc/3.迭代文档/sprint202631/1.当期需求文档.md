# sprint202631 当期需求文档：站内 AI 智能助手

日期：2026-10-03（补充前端表单操作与可视化反馈）  
状态：已获用户编码授权，功能已实现；具体实现、验证范围与待验收项见设计方案和验收文档。  
需求来源：[需求简介](需求简介.md)。本文将原始要求细化为可实施、可验收的建议方案；标注为“建议”的内容可以在评审时调整。

## 1. 需求分析与目标

在网站中提供类似腾讯云智能助手 KiKi 的常驻助手入口，让已登录用户通过自然语言了解项目、寻找功能并完成站内操作。借鉴其入口和交互形式，视觉使用本站品牌与主题，不复制第三方品牌素材。

助手需要同时具备三类能力：

1. **回答问题**：基于本站真实内容解释学习路线、面试题库、智能刷题、成长体系、模型权益及建议评论区的使用方式。
2. **理解上下文**：识别当前页面，结合本次会话理解“打开那里”“回复这一条”等指令；对象不唯一时询问用户。
3. **执行操作**：通过受控工具完成导航、查询和明确授权的发布；发布时在真实页面定位控件、填写表单、触发提交，让用户看到操作过程，并根据真实执行结果反馈成功或失败。

“包括但不限于”意味着能力可扩展，不等于助手可以随意调用所有接口。本期先覆盖下述明确工具范围，后续功能沿用相同接入机制。

## 2. 现状与约束

| 现状 | 对本期的影响 |
| --- | --- |
| Vue 3 + TypeScript + Pinia + Element Plus，统一 AppLayout | 助手挂载到全局布局，跨页面保持会话 |
| 已有浅色、深色主题和移动端底部导航 | 助手复用主题变量，避让底部导航与安全区 |
| Spring Boot 负责认证及业务，FastAPI 负责模型 | 用户身份、业务校验和数据写入继续由 Java 承担 |
| 已使用 LangChain、LangGraph | 延续现有技术栈，不新建独立 Agent 服务 |
| 刷题按用户有效模型权益选择模型 | 助手复用相同解析服务，不让用户额外配置模型 |
| 建议与评论是不同数据，评论支持父评论及一级回复 | “发评论”进入评论区，不能误发成建议；回复必须有明确目标 |
| 评论为 2～1000 位纯文字，禁止表情和艾特 | 助手提交与手工提交执行相同校验，不自行改写违规内容 |

遵守项目约定：不编写单元测试；不增加外键、审计管理端或权限模型；需要数据库变更时新增 Flyway 版本，不修改历史迁移。

## 4. 关键交互规则

### 4.1 问答与事实依据

- 静态知识来自现有项目介绍、公开学习资料和经过整理的功能说明；不将整个仓库、密钥配置或内部文档送入模型。
- 模型权益、个人统计、评论列表等动态信息实时查询，不能从旧对话推断当前结果。
- 找不到依据时明确说明，提供相关功能入口，不编造页面、规则或操作成功消息。
- 允许围绕本站资料进行解释；无关话题简短引导回站内任务，不默认增加联网搜索。

### 4.2 用户授权与发布

建议采用以下规则，供人工评审确认：

| 用户表达 | 助手行为 |
| --- | --- |
| “打开建议评论区” | 直接打开页面；未指定页签时沿用页面默认建议页签 |
| “打开评论区” | 打开页面并切换评论页签 |
| “帮我提交一条‘这个学习路线很清晰’的评论” | 明确授权且提供原文，校验通过后直接提交一次 |
| “帮我写一条夸这个网站的评论” | 先生成草稿，显示发布按钮；用户确认后才发布 |
| “回复这条评论：谢谢分享” | 当前有唯一、可验证父评论目标时执行；否则先询问选择对象 |
| “评论一下这个功能” | 不能默认理解为公开发布，先澄清 |
| “打开评论区，然后提交‘XXX’” | 串行执行；导航成功后发布；逐步展示结果 |
| “把‘这个学习路线很清晰’填入评论框，先不要发” | 在真实表单中填写并保留草稿，流程结束，不触发提交 |

用户原文不得被模型静默润色。生成草稿、修改内容或更换目标后，原确认失效。待确认草稿建议 10 分钟有效；超时、账号切换或目标失效后不可继续执行。

### 4.3 面板与视觉

- 右下角圆形按钮建议直径 56px，带明确的“AI 助手”无障碍名称，采用本站蓝绿品牌色。
- 桌面宽度不小于 1024px 时，建议面板宽约 `40vw`、高约 `62.5dvh`，面积约为视口的 25%；最小尺寸和边距优先保障可用性。
- 768～1023px 使用宽度不超过 520px、可视高度约 70% 的面板；小于 768px 使用接近全宽的底部面板，避免强行压缩为四分之一。此移动端例外属于建议评审项。
- 面板包含：标题与当前模型、关闭按钮、消息区、工具结果卡片、输入框、发送/停止、新会话入口。
- 桌面展开不覆盖整页遮罩；移动端按面板交互管理焦点。关闭后焦点返回入口，支持键盘操作及 Esc 收起。
- 收起不等于停止；继续生成时入口显示轻量状态。退出登录则终止未完成任务；已提交的评论不因关闭或停止被回滚。
- 不覆盖登录弹窗、关键提交按钮和移动导航；浅色、深色主题均复用本站样式变量。

### 4.4 会话与模型

- 助手会话与刷题会话完全分离，不修改当前题目、刷题阶段、答案或成长结算。
- 每轮开始时获取与当前用户刷题相同的有效模型配置；本轮固定配置，下一轮反映授权或后台配置变化。
- 不支持 tool calling 的有效模型仍可尝试文本问答，但明确提示操作能力不可用，不偷偷切换其他模型。
- 建议本期保留当前会话及操作结果以支持刷新恢复，不制作会话历史列表、全文搜索和跨设备同步产品入口；新会话与刷题记录无关。
- 模型不可用时展示错误和已有静态帮助入口，不假装完成问答或发布。

### 4.5 前端表单操作与可视化反馈

本期采用“站内可见操作”体验。用户下达发布指令后，默认经过真实页面的表单操作，不能后台先完成发布再播放模拟过程。仅问答或个人统计查询不强制跳转页面。

以“帮我发一条评论：这个学习路线很清晰”为例：

| 步骤 | 页面中的真实变化 | 视觉反馈 |
| --- | --- | --- |
| 1. 打开页面 | 进入建议评论区并切换评论页签 | 步骤条显示“打开评论区”，目标页签短暂高亮 |
| 2. 定位输入框 | 等待页面加载并滚动到评论表单 | 输入框出现蓝绿色描边，助手光标移至输入框 |
| 3. 填写内容 | 将原文写入真实输入框，表单状态同步变化 | 聚焦并分段呈现填写过程，提示“正在填写评论” |
| 4. 准备提交 | 检查内容、授权和按钮可用状态 | 完整内容可见，提交按钮高亮；需确认的草稿停在此处 |
| 5. 触发提交 | 调用该表单的提交处理，实际请求只发送一次 | 助手光标显示点击波纹，按钮进入真实 loading 状态 |
| 6. 展示结果 | 根据服务端结果更新列表并定位新评论 | 新评论短暂高亮，步骤条显示完成；失败则保留草稿并显示原因 |

回复评论时，先定位对应父评论、展开其回复框，再填写和提交；发布建议时，展示建议类型的选择。输入框找不到、控件不可用或目标已变化时，暂停并解释原因，不悄悄改为后台发布。

交互约束：

- 助手光标是页面内带“AI”标识的视觉指针，不移动操作系统鼠标；用户真实鼠标和键盘始终可用。
- 每一步根据真实动作的开始、完成和失败更新，不预先显示成功；动画不决定业务状态。
- 操作区不能被助手面板挡住：桌面优先调整面板位置，必要时折叠为步骤条；移动端操作时折叠面板，展示目标表单及浮动进度条，提供返回对话入口。
- 步骤条持续提供“暂停”“停止”“我来操作”。暂停保留任务，恢复前重新检查页面；停止结束后续动作；接管停止自动操作并把当前表单留给用户。
- 用户编辑目标表单、切换页签或主动离开目标页面时暂停，避免抢占操作；更改内容或目标后旧发布授权失效。单纯查看其他区域不自动覆盖用户行为。
- 表单已有非空内容时不得直接覆盖：保留原草稿并询问替换、追加或取消；回复目标改变前同样检查未提交草稿。
- 填写中的部分文本不能被提前提交。任务停止保留当前草稿；失败后不清空表单；提交成功且表单未被用户重新编辑时才清理本次草稿。
- 未收到用户发布授权时，只能填写或展示草稿；“已填写”与“已发布”必须明确区分。
- 动效采用轻量描边、光标移动和点击波纹；填写动画建议总时长不超过 1.5 秒，不按长文本逐字拖慢操作。支持减少动态效果设置，保留静态高亮与步骤文字；键盘和读屏可获知进度。
- 浏览器标签页不可见时暂停未开始的页面动作，返回后由用户继续；正在提交的事务仍以服务端结果为准。

本期操作范围仍是已接入的网站功能。模型选择业务动作，页面适配器负责控件定位；不开放任意 DOM 操作、地址栏控制、跨站浏览或桌面控制。

## 5. 异常与一致性要求

1. 登录失效：后端拒绝，前端清理助手并沿用登录引导。
2. 网络断开、重复点击、刷新：同一发布操作不能重复落库；先查询已有执行状态，再决定是否恢复。
3. 工具失败：展示失败原因，不把模型预测当执行结果；多步操作展示哪些已完成、哪些未完成，不自动撤销已发布内容。
4. 停止：停止后续生成与待执行操作；正在提交的事务以服务端最终结果为准。
5. 账号隔离：不能通过猜测会话或操作 ID 读取/执行他人的任务；旧账号返回的流不得进入新账号界面。
6. 页面同步：发布成功后刷新对应列表并展示新记录；当前不在社区页时提供“查看评论/建议”入口。
7. 文本、Markdown 和来源链接安全渲染；资料与评论中的“忽略规则”等文本不能成为操作授权。

## 6. 验收场景

下表是本次需求评审的验收依据，正式验收文档在实施后按项目简化模板另行生成。

| 场景 | 预期结果 |
| --- | --- |
| 游客访问各页面及直接请求助手接口 | 无入口；受保护接口拒绝访问 |
| 登录、退出、切换账号 | 可见性正确，无历史消息或迟到事件串号 |
| 桌面/平板/手机、明暗主题 | 面板比例与适配规则符合约定，无明显遮挡和溢出 |
| 询问如何开始刷题或获得成长经验 | 回答与现有代码/资料一致，有站内依据 |
| 询问不存在的功能 | 不捏造能力，明确说明范围 |
| 打开评论区且当前已经在该页 | 正确切换页签，路由不重复堆积，不丢失助手消息 |
| 明确提交原文评论 | 只生成一条当前用户名下的评论，显示实际结果 |
| 要求生成评论草稿、取消或确认 | 确认前不发布；确认后只发布被确认版本 |
| 内容过短、过长、包含表情或艾特 | 按现有规则拒绝，不能偷偷修改后提交 |
| 回复目标不明确或已失效 | 澄清或报错，不回复错误对象 |
| 网络中断后重试、重复确认、刷新 | 不重复发布，可获取最终状态 |
| 模型更换、授权到期、工具能力不兼容 | 模型选择与刷题一致，降级和错误说明准确 |
| 工具成功后模型总结失败 | 仍显示已完成结果，不诱导再次发布 |
| 同时使用刷题和助手 | 刷题状态、历史、评分和模型权益原有逻辑正常 |
| 从首页要求发布评论 | 可见导航、定位、填写、点击及真实结果，不能发布后补播动画 |
| 仅要求填写评论 | 输入框出现指定原文，状态为已填写，无发布请求 |
| 表单已有草稿、用户中途编辑或更换回复目标 | 原内容被保留，操作暂停；旧内容授权不能用于新内容 |
| 暂停、停止、接管、标签页切后台 | 不再执行后续页面动作；已提交事务可查询实际结果 |
| 控件未加载、按钮禁用、路由变化 | 等待或暂停并说明原因，不绕过表单后台发布 |
| 重复动作事件、同时手动点击提交、刷新恢复 | 同一 operation 只发布一次，未确认状态不自动重放提交 |
| 手机软键盘、面板遮挡、减少动态效果 | 操作目标可见，进度与停止入口可用，不依赖动画理解状态 |

## 7. 待人工确认的建议决策

1. 本期工具范围采用 F01～F12，增加真实表单操作与视觉反馈，管理写操作及自动答题不纳入。
2. 明确给出原文且要求提交时直接发布；AI 草稿或语义不明确时先确认。
3. 桌面按约 25% 面积设计，手机采用接近全宽面板。
4. 会话建议服务端保留 7 天，待确认动作 10 分钟；同一会话只允许一个活跃执行任务。
5. 采用已有 MySQL 保存必要会话与幂等状态，不引入 Redis、Qdrant 或新的部署服务。
6. 根据本次补充要求，发布默认经过真实页面表单；定位失败时暂停，具体动效、暂停与草稿处理按第 4.5 节评审。

以上为建议默认方案，不代表已经确认。当前交付仅为需求及设计文档；人工确认或调整后再开始编码。
