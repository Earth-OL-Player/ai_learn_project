# sprint2620 当期需求文档

版本：v1.0  
日期：2026-05-17  
迭代定位：重新完善开发勋章功能，让勋章只围绕 AI 智能刷题行为发放、记录和展示，形成刷题即时激励闭环。

## 1. 背景与目标

当前成长体系中已经存在徽章墙，但徽章规则与 AI 智能刷题链路关联不足，且历史徽章包含高分、专项题型等本期不再需要的规则。新项目没有历史包袱，本迭代需要清理旧勋章口径，只保留本期明确列出的勋章，并把发放触发点接入 AI 智能刷题的出题、评分和追问流程。

本迭代目标如下：

1. 勋章只保留入门类、坚持类、隐藏/稀有类共 11 个，不新增其他勋章。
2. 用户完成刷题评分后，根据累计完成题数、学习天数、作答时段和周末行为发放勋章。
3. 用户在单题评分后连续追问 3 次时发放“问到底”勋章。
4. 发放时写入用户勋章记录，并写入成长事件，避免重复发放。
5. AI 智能刷题页面在触发新勋章时弹框提示。
6. 个人中心徽章墙中，入门类和坚持类未获得时置灰展示、获得后点亮展示；隐藏/稀有类未获得时不展示，获得后点亮展示。

## 2. 勋章范围

### 2.1 入门类：降低新手门槛

| 勋章名称 | 获得条件 | 展示规则 |
| --- | --- | --- |
| 初次启程 | 完成第 1 道题 | 未获得置灰展示，获得后点亮展示 |
| 十题小成 | 累计完成 10 道题 | 未获得置灰展示，获得后点亮展示 |
| 百题修炼 | 累计完成 100 道题 | 未获得置灰展示，获得后点亮展示 |
| 大成圆满 | 累计完成 300 道题 | 未获得置灰展示，获得后点亮展示 |

说明：累计完成题数按 AI 智能刷题评分完成次数统计，同一道题重答并完成评分也计入刷题完成次数。

### 2.2 坚持类：强化连续学习

| 勋章名称 | 获得条件 | 展示规则 |
| --- | --- | --- |
| 三日不辍 | 总共学习 3 天 | 未获得置灰展示，获得后点亮展示 |
| 月度坚持者 | 总共学习 30 天 | 未获得置灰展示，获得后点亮展示 |
| 百日成神 | 总共学习 100 天 | 未获得置灰展示，获得后点亮展示 |

说明：总共学习天数按用户完成 AI 智能刷题评分的自然日去重统计，不要求连续自然日。

### 2.3 隐藏/稀有类：增加惊喜感

| 勋章名称 | 获得条件 | 展示规则 |
| --- | --- | --- |
| 深夜修行者 | 晚上 22:00 后完成刷题 | 未获得不展示，获得后点亮展示 |
| 清晨启动者 | 早上 6:00-8:00 完成刷题 | 未获得不展示，获得后点亮展示 |
| 周末不摆烂 | 周六或周日完成刷题 | 未获得不展示，获得后点亮展示 |
| 问到底 | 单题评分后连续追问 3 次 | 未获得不展示，获得后点亮展示 |

说明：时间判断使用后端服务所在时区；清晨区间按 `06:00 <= 完成时间 < 08:00` 判断。

## 3. 业务流程需求

### 3.1 刷题评分后勋章发放

1. 用户在 AI 智能刷题页面提交答案。
2. 后端完成 AI 或本地兜底评分。
3. 后端更新用户题目汇总和成长经验。
4. 后端根据最新完成次数、学习天数、完成时间和星期判断候选勋章。
5. 未获得过的候选勋章写入 `user_badges`。
6. 新发放勋章写入 `growth_events`，并返回给前端。
7. 前端弹框提示本次新获得的勋章。

### 3.2 单题追问勋章发放

1. 用户完成某题评分后进入本题讨论阶段。
2. 用户围绕本题连续发送有效追问。
3. 后端按当前题会话累计追问次数。
4. 当前题评分后第 3 次连续追问时，发放“问到底”。
5. 切换下一题、重答本题或重新评分后，当前题追问计数重新开始。

### 3.3 个人中心展示

1. 个人中心徽章墙按分类展示。
2. 入门类和坚持类所有勋章都展示，未获得时置灰。
3. 隐藏/稀有类只展示已获得勋章，未获得的不出现在页面中。
4. 已获得勋章展示获得态视觉，不再置灰。
5. 徽章名称、说明和图标来自后端统一定义，前端不额外扩展勋章。

## 4. 后端接口需求

### 4.1 成长信息接口

`GET /api/v1/growth/me` 返回徽章墙时需要包含：

| 字段 | 说明 |
| --- | --- |
| id | 徽章 ID |
| name | 徽章名称 |
| description | 徽章说明 |
| icon | 徽章图标 |
| ruleCode | 规则编码 |
| category | 分类编码：ENTRY、PERSISTENCE、RARE |
| categoryName | 分类名称 |
| hidden | 是否隐藏/稀有勋章 |
| acquired | 是否已获得 |
| acquiredAt | 获得时间 |

### 4.2 刷题消息接口

`POST /api/v1/practice/messages/stream` 在触发新勋章时，通过评分结果或成长信息返回 `newBadges`，供前端弹框提示。

## 5. 非功能需求

1. 本迭代禁止新增单元测试代码。
2. 不新增 Redis、Qdrant 等中间件，不新增新的连接配置和启动参数。
3. 涉及 MySQL 表结构调整时必须通过 Flyway migration 完成。
4. 清理历史旧勋章，只保留本需求列出的 11 个勋章定义。
5. 勋章发放必须幂等，同一用户同一勋章不能重复记录。
6. 前端 UI 保持清新、简约、大气，弹框提示不打断核心刷题流程过久。
7. 代码和文档统一使用 UTF-8 简体中文。
