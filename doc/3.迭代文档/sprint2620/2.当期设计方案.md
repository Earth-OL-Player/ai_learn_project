# sprint2620 当期设计方案

版本：v1.0  
日期：2026-05-17  
迭代定位：开发勋章体系与 AI 智能刷题强联动设计，覆盖勋章定义刷新、发放规则、追问计数、个人中心展示和弹框提示。

## 1. 设计原则

1. 严格只保留需求列出的 11 个勋章，不做额外扩展。
2. 勋章发放以 AI 智能刷题链路为唯一触发入口，避免和普通页面浏览行为混淆。
3. 发放逻辑放在后端统一判断，前端只负责展示和提示。
4. 用户勋章记录使用唯一键保证幂等，重复满足条件不重复发放。
5. 隐藏/稀有类未获得时由后端和前端双重过滤，降低误展示概率。
6. 新项目没有历史包袱，历史旧勋章通过 migration 清理，不保留兼容展示。
7. 本迭代不新增单元测试代码。

## 2. 总体链路

```text
用户在 AI 智能刷题页面作答
  ↓
后端完成评分并更新 user_question_stats
  ↓
GrowthAwardService 统计完成次数、学习天数、时间段、星期
  ↓
INSERT IGNORE 写入 user_badges
  ↓
写入 growth_events 成长明细
  ↓
PracticeMessageResponse 返回 newBadges
  ↓
前端弹框提示新勋章
  ↓
个人中心刷新后展示已获得或置灰勋章
```

追问勋章链路：

```text
评分完成进入 DISCUSSING
  ↓
用户围绕本题连续追问
  ↓
user_practice_sessions.discussion_follow_up_count + 1
  ↓
累计达到 3 次
  ↓
发放“问到底”并通过 growth.newBadges 返回前端
```

## 3. 数据库设计

### 3.1 徽章定义刷新

新增 Flyway migration `V16__refresh_practice_badges.sql`：

1. 删除不在本期规则内的历史用户勋章记录。
2. 删除不在本期规则内的历史徽章定义。
3. 使用 upsert 写入或刷新本期 11 个勋章。
4. 保留 `badges.rule_code` 唯一键，业务规则通过编码稳定关联。

本期规则编码：

| 规则编码 | 勋章名称 | 分类 |
| --- | --- | --- |
| FIRST_ANSWER | 初次启程 | 入门类 |
| ANSWER_10 | 十题小成 | 入门类 |
| ANSWER_100 | 百题修炼 | 入门类 |
| ANSWER_300 | 大成圆满 | 入门类 |
| LEARNING_3_DAYS | 三日不辍 | 坚持类 |
| LEARNING_30_DAYS | 月度坚持者 | 坚持类 |
| LEARNING_100_DAYS | 百日成神 | 坚持类 |
| LATE_NIGHT | 深夜修行者 | 隐藏/稀有类 |
| EARLY_MORNING | 清晨启动者 | 隐藏/稀有类 |
| WEEKEND_PRACTICE | 周末不摆烂 | 隐藏/稀有类 |
| ASK_TO_END | 问到底 | 隐藏/稀有类 |

### 3.2 当前题追问计数

`user_practice_sessions` 新增字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| discussion_follow_up_count | INT NOT NULL DEFAULT 0 | 当前题评分后连续有效追问次数 |

重置规则：

1. 抽取下一题时重置为 0。
2. 重答本题时重置为 0。
3. 当前题重新评分完成时重置为 0。
4. 有效讨论追问成功处理后加 1。

## 4. 后端设计

### 4.1 BadgeRule 规则枚举

新增 `BadgeRule` 枚举，集中维护：

- 规则编码。
- 分类编码。
- 分类展示名。
- 是否隐藏。
- 展示顺序。

这样可以避免前端自行推断隐藏勋章，也可以保证后端过滤未知旧规则。

### 4.2 GrowthAwardService 发放策略

评分后发放入口：

```text
awardAfterAnswer(userId, score, earnedExperience)
```

处理步骤：

1. 写入一条 `ANSWER` 成长事件，记录本次刷题评分和经验变化。
2. 查询 `SUM(user_question_stats.answer_count)` 获取累计完成次数。
3. 查询答题事件和题目汇总日期并集，获取总学习天数。
4. 根据服务当前时间判断深夜、清晨和周末。
5. 组装候选规则并逐个 `INSERT IGNORE` 到 `user_badges`。
6. 对新插入成功的勋章写入 `BADGE` 成长事件并返回。

追问后发放入口：

```text
awardAfterDiscussion(userId, followUpCount)
```

当 `followUpCount >= 3` 时尝试发放 `ASK_TO_END`。

### 4.3 GrowthService 成长响应

`GrowthService` 增加带新勋章参数的响应构造能力：

```text
getCurrentGrowth(newBadges)
```

用于刷题接口把本次新获得勋章透传给前端。普通个人中心查询继续返回空 `newBadges`。

### 4.4 个人中心徽章墙

后端 `findBadgeWall` 处理：

1. 只返回 `BadgeRule` 中定义过的 11 个规则。
2. 按 `BadgeRule` 展示顺序排序。
3. 隐藏/稀有类未获得时过滤掉。
4. 每个徽章补充 `category`、`categoryName`、`hidden` 字段。

## 5. 前端设计

### 5.1 AI 智能刷题弹框

`PracticeAgentPage.vue` 在处理接口最终结果时调用统一函数：

```text
showNewBadgeDialog(result)
```

数据来源：

1. `result.grading.newBadges`：评分后触发的勋章。
2. `result.growth.newBadges`：讨论追问触发的勋章。

展示策略：

- 多个勋章一次性合并展示。
- 按 `ruleCode` 去重，避免评分结果和成长信息同时携带时重复显示。
- 使用 Element Plus 弹框，标题为“恭喜获得新勋章”。

### 5.2 个人中心徽章墙

`GrowthOverviewPanel.vue` 改为按分类分组展示：

1. 入门类、坚持类始终显示。
2. 隐藏/稀有类仅在存在已获得勋章时展示该分类。
3. 未获得的非隐藏勋章使用灰度、低透明度和虚线描边。
4. 已获得勋章使用轻量渐变卡片点亮。

### 5.3 TypeScript 类型

`BadgeInfo` 增加：

```ts
category: 'ENTRY' | 'PERSISTENCE' | 'RARE' | string;
categoryName: string;
hidden: boolean;
```

## 7. 验证方案

1. 执行后端编译：`mvn -DskipTests package`，不运行单元测试。
2. 执行前端构建：`npm run build`。
3. 本地启动后端时确认 Flyway 执行 `V16__refresh_practice_badges.sql` 成功。
4. 手工登录 AI 智能刷题页面完成一次评分，验证“初次启程”和符合时段的隐藏勋章弹框。
5. 手工在评分后连续追问 3 次，验证“问到底”弹框和用户勋章记录。
6. 访问个人中心，验证非隐藏勋章置灰/点亮、隐藏勋章未获得不展示。
