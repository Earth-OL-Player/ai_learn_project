# AI 自查优化建议

生成时间：2026-05-23

本次按“前端学习平台 + Java 业务后端 + Python AI 服务 + 数据库迁移 + 项目文档 + 工程化配置”进行全项目扫描。当前项目已经形成可运行闭环，包含首页与学习路线、用户认证、建议评论、热门面试题、系统题库管理、AI 智能刷题、AI 评分/讨论、成长等级/段位/勋章、管理者中心等核心能力。

已执行的辅助验证：

- [x] 后端构建：在 `ai-learn-backend` 执行 `mvn -DskipTests package`，结果通过。
- [x] 未新增单元测试代码，符合当前项目要求。

- [x] 工程配置：README、中间件文档、Vite 配置、Maven 配置、Python requirements 均已存在。

总体判断：

- [x] 当前系统功能闭环完整，构建可通过，已具备继续迭代的基础。

## 2. 优先级定义

- [ ] P0：必须优先处理。影响安全、数据一致性、线上稳定性、核心功能正确性的问题。
- [ ] P1：高价值优化。影响长期可维护性、性能、可观测性、主要用户体验的问题。
- [ ] P2：产品体验增强。提升系统好用程度、学习效果、管理效率和留存体验。
- [ ] P3：工程完善项。提升团队效率、交付规范、部署体验和后续扩展能力。

## 3. P0 必须优先处理

- [x] P0-01 收敛真实 AI 评分字段契约。
  现状：建议复习点没有前端独立展示价值，且真实模型结构化评分响应未稳定产出该字段，继续保留会造成协议噪声。
  处理：已从前端类型、Java 评分响应、领域评分结果、AI 客户端解析、本地兜底评分和评分摘要中删除该字段。
  验收：真实 AI 评分、本地兜底评分、前端评分展示和接口文档字段一致。

- [x] P0-02 收敛 `v-html` 和 Markdown 渲染安全边界。
  现状：`HomePage.vue`、`LearningRoadmapPage.vue` 使用 `markdown-it` 且 `html: true`；`InterviewQuestionsPage.vue`、`PracticeAgentPage.vue` 也通过 `v-html` 渲染 Markdown 结果。部分内容当前来自本地 Markdown 或后端题库，但后续一旦引入用户上传、管理员导入或模型输出，XSS 风险会放大。
  建议：抽取统一 `safeMarkdown` 工具，默认 `html: false`，必要 HTML 白名单通过 DOMPurify 处理；模型输出和题库内容必须走同一安全渲染链路。
  验收：所有 `v-html` 调用点都有明确可信来源或统一消毒；恶意脚本、事件属性、危险链接无法执行。

- [x] P0-03 升级认证与 Token 安全模型。
  现状：前端使用 `localStorage` 保存访问令牌；后端 `logout` 只返回成功，未做服务端失效；`JwtTokenService` 手写 JWT 生成和 payload 解析；认证失败在过滤器中返回 HTTP 200。
  建议：改用成熟 JWT 库；启动时校验 `JWT_SECRET` 强度；短期可保留 Bearer Token，但建议规划 HttpOnly、Secure、SameSite Cookie 或 access token + refresh token；退出登录需要服务端失效机制。
  验收：JWT 解析不再依赖手写字符串切分；退出登录后旧令牌不可继续访问；认证失败语义在网关、浏览器和日志中都清晰可判定。

- [x] P0-04 控制 AI 服务日志中的敏感数据。
  现状：`ai-service/app/practice/agent_service.py` 会完整记录大模型调用入参和返回，日志中可能包含用户答案、题目、参考答案、模型回复和业务上下文。
  建议：默认只记录 traceId、模型、耗时、token、状态、字段长度和错误摘要；完整 prompt/response 只允许在本地调试或受控开关下短期启用，并做脱敏。
  验收：生产日志不落用户答案原文、不落模型完整回复、不落密钥；排障仍能通过 traceId 定位链路。

- [x] P0-05 为 SSE 流式请求使用受控线程池和取消机制。
  现状：`PracticeController` 使用 `CompletableFuture.runAsync`，会进入默认公共线程池；服务端还通过 `Thread.sleep` 控制分片节奏。并发上来后，AI 流式请求容易和其他异步任务互相影响。
  建议：为 AI/SSE 单独配置有界线程池、队列长度、拒绝策略和监控指标；客户端断开时尽快取消上游模型请求；视觉打字节奏尽量放在前端完成。
  验收：并发流式请求不会拖垮公共线程池；断开连接后后端不继续长时间占用模型调用和线程资源。

- [x] P0-06 加固题库“一键清空”数据一致性和审计。
  现状：`SystemQuestionAdminService.clearAll` 先重置会话再 `TRUNCATE questions`，但用户答题汇总继续保留；该操作没有操作审计、备份确认、二次校验和可恢复能力。
  建议：将“一键清空”改为强确认操作，增加操作审计和导出备份入口；优先采用逻辑删除或版本化题库批次，谨慎使用 `TRUNCATE`；清空后明确处理用户历史统计和成长经验的业务规则。
  验收：管理员可追溯谁在何时清空了题库；误操作有恢复路径；清空后刷题状态、成长经验、历史最高分口径一致。

- [x] P0-07 增加登录、注册、点赞、评论、AI 评分和 CSV 导入的限流。
  现状：核心写接口和高成本 AI 接口目前没有统一限流。注册、登录、CSV 导入和 AI 讨论都可能被恶意或误操作高频触发。
  建议：先实现内存级限流作为过渡；如果接入 Redis，需要同步更新 `doc/中间件/Redis.md` 和 README，说明用途、配置、启动和部署注意事项。
  验收：同一 IP 或同一用户短时间高频请求会被明确拦截；高成本 AI 接口有单用户并发和频率限制。

- [x] P0-08 收敛跨域与公网隧道配置。
  现状：后端 CORS 放行 `*.cpolar.top`，Vite 也允许 cpolar 域名，适合临时公网体验，但不适合默认生产配置。
  建议：按 `dev`、`public-demo`、`prod` 拆分 CORS 配置，生产只允许明确域名；公网隧道能力放到本地或演示 profile。
  验收：生产环境不会默认放行临时隧道域名；本地演示仍能通过 profile 显式启用。

## 4. P1 高价值优化

- [x] P1-01 拆分前端 AI 刷题页。
  现状：`PracticeAgentPage.vue` 约 1518 行，包含分类选择、消息渲染、流式打字、快照恢复、滚动记忆、勋章弹窗、评分卡片、样式等多类职责。
  建议：拆成页面编排、消息列表、输入栏、题目卡、评分卡、勋章弹窗、分类选择器、`usePracticeChat`、`usePracticeSnapshot`、`useStreamTypewriter` 等模块。
  验收：单个 Vue 文件控制在更易维护的规模；刷题页新增功能时不需要同时修改大量无关逻辑。
- [x] P1-02 拆分后端 `PracticeService`。
  现状：`PracticeService.java` 约 766 行，混合了会话状态机、抽题权重、答案提交、成长经验、讨论历史、内容识别和响应组装。
  建议：拆成 `PracticeSessionService`、`QuestionSelectionService`、`PracticeGradingService`、`DiscussionHistoryService`、`PracticeResponseAssembler` 等边界清晰的服务。
  验收：每个服务职责单一；后续改抽题策略、成长规则或 AI 讨论时影响范围可控。
- [x] P1-03 拆分 Python `PracticeAgentService`。
  现状：`agent_service.py` 集中处理模型初始化、评分、流式讨论、日志、SSE、结构化解析、供应商兼容和本地兜底。
  建议：拆分为模型工厂、评分 Agent、讨论 Agent、日志脱敏器、SSE 编码器、供应商适配器。
  处理：已拆分为 `model_factory.py`、`grading_agent.py`、`discussion_agent.py`、`llm_logger.py`、`sse.py`、`provider_adapter.py`、`prompts.py`、`local_fallback.py`，`agent_service.py` 仅保留门面编排。
  验收：更换模型供应商、修改日志策略、调整提示词时不需要编辑同一个大文件。
- [ ] P1-04 重构全局样式为设计令牌和页面样式分层。
  现状：`global.scss` 约 1134 行，混合了全局布局、Markdown、管理端、认证弹窗、个人中心等样式，且有多处迭代注释。
  建议：抽取 `tokens.scss`、`layout.scss`、`markdown.scss`、`admin.scss`、`auth.scss`、`responsive.scss`；统一颜色、圆角、阴影、间距和字体等级。
  验收：新增页面优先复用设计令牌；不再通过继续追加全局 CSS 解决局部页面问题。
- [ ] P1-05 优化 Element Plus 样式和首屏包体。
  现状：前端构建通过，但 `vendor-element-plus` CSS 约 357 KB，JS 约 329 KB；入口已按组件注册，但仍引入了 `element-plus/dist/index.css`。
  建议：使用按需样式导入或自动导入插件；对低频管理页面继续保持路由级拆包；评估 Markdown 内容和图片的 lazy load。
  验收：首屏 CSS 和 JS 体积下降；首页、学习路线和刷题页加载更快。
- [ ] P1-06 统一 API 错误语义和前端登录态处理。
  现状：业务异常多以 HTTP 200 返回，通过 `code` 判断；认证过滤器也对未授权返回 200。这样对代理、监控、浏览器网络面板和通用错误处理不够友好。
  建议：保留统一响应体，但 HTTP 状态建议与错误类别一致，例如 400、401、403、404、409、500；前端 `http.ts` 按状态和业务码共同处理。
  验收：监控平台能通过 HTTP 状态直接统计错误率；前端仍能展示中文业务错误。
- [x] P1-08 建立 AI 调用可观测性。
  现状：Java 后端有 traceId，Python AI 服务也有局部日志，但 Java 调 Python 时没有完整透传统一 traceId，也没有 P95、超时率、兜底率、token 用量和成本看板。
  建议：Java 调用 AI 服务时透传 `X-Trace-Id`；记录评分成功率、兜底率、流式首包时间、总耗时、模型、token、错误类别；后续接入指标看板。
  验收：一次用户刷题请求能从浏览器、Java 后端、Python 服务、模型调用日志串起来。
- [ ] P1-09 优化 CSV 导入体验和失败处理。
  现状：后端支持多行 CSV 和最大 1000 行导入，但前端只展示新增/更新数量；导入前缺少预览、差异、失败行汇总和部分失败处理。
  建议：增加导入预检接口，返回新增、更新、冲突、错误行、字段问题；前端展示预览表和确认导入按钮。
  验收：管理员能在真正写库前知道会影响哪些题目；导入失败能定位到具体行和字段。
- [ ] P1-12 增强前端可访问性和键盘体验。
  现状：界面整体清爽，但导航、弹窗、图标按钮、Markdown 目录、对话区和管理表格仍需要系统性可访问性检查。
  建议：增加跳到正文的 skip link；检查焦点顺序、按钮 aria-label、表单 label、键盘可达、对比度、错误提示和 reduced-motion。
  验收：仅使用键盘可以完成登录、刷题、切换分类、提交答案、查看评分和管理题库的主要流程。

## 5. P2 产品体验增强

- [ ] P2-02 增加题目难度、标签和掌握状态。
  建议：题库除分类外增加难度、知识点标签、是否高频、是否已掌握；刷题时支持按弱点和难度筛选。
  验收：用户能选择“只练 RAG 中高频但未掌握的中等难度题”。
- [ ] P2-03 增加答题前提示和分步启发。
  建议：当用户不会答时，提供“给我一点提示”“拆解思路”“展示答案框架”，但不直接泄露完整答案。
  验收：用户不会因为卡住而退出，同时仍保留练习价值。
- [ ] P2-07 增强热门面试题浏览体验。
  建议：增加关键词搜索、分类组合筛选、折叠/展开答案、收藏、掌握状态、导出复习清单。
  验收：用户可以快速定位特定知识点和自己的未掌握题。
- [ ] P2-08 增强建议评论区的产品闭环。
  建议：建议增加状态流转，例如已收到、计划中、已完成、暂不采纳；评论支持举报、置顶、管理员回复和热度排序解释。
  验收：用户提交建议后能看到处理进展，评论区不只是留言板。
- [ ] P2-09 增加个人学习数据看板。
  建议：展示累计答题、平均分、最高分、近 7 天学习趋势、强弱分类、勋章墙、连续学习天数。
  验收：用户可以通过个人中心了解自己的学习成长趋势。
- [ ] P2-10 增加管理后台总览页。
  建议：管理者中心首页展示用户数、题库数、答题次数、AI 兜底率、今日活跃、热门分类、最近导入和异常事件。
  验收：管理员进入后台先看到系统健康和运营概况，而不是直接进入表格。
- [ ] P2-11 增加题库质量检测。
  建议：后台支持检测重复题、空答案、过短答案、分类不规范、重要性异常、面试次数异常、Markdown 格式异常。
  验收：批量导入后能自动指出低质量题目。
- [ ] P2-12 增加模型配置与提示词版本管理。
  建议：AI 服务配置模型、温度、最大输出、提示词版本、启用状态；记录每次评分使用的模型和提示词版本。
  验收：模型效果变化可以按版本回溯，提示词改动可以灰度和回滚。
- [ ] P2-13 增加 AI 评分质量反馈。
  建议：评分卡片增加“评分有帮助/不准确”反馈；低质量反馈进入后台待复盘列表。
  验收：真实用户反馈可以反哺题库、提示词和评分策略。
- [ ] P2-15 统一视觉语言，减少单一蓝绿渐变依赖。
  建议：保留清新简约主风格，但用语义色、灰阶层级、轻量强调色和更克制的卡片阴影建立设计系统；管理端更偏工作台密度，学习端更偏陪伴感。
  验收：不同页面视觉一致但不单调；管理端信息密度更高，学习端更轻松。

## 6. P3 工程完善项

- [ ] P3-01 更新 `.gitignore`，清理 Python 缓存和虚拟环境产物。
  现状：工作区存在 `ai-service/app/**/__pycache__` 未跟踪文件；`.gitignore` 目前未覆盖 `__pycache__/`、`*.pyc`、`.venv/`。
  建议：补充 Python 常见忽略项，并清理已生成缓存文件。
  验收：运行 Python 服务后不会出现新的缓存文件污染工作区。

- [ ] P3-02 增加统一静态检查和格式化命令。
  建议：Java 引入 Checkstyle 或 Spotless，前端引入 ESLint + Prettier，Python 引入 Ruff；命令写入 README。
  验收：提交前可通过一组命令检查格式、复杂度、未使用变量和明显 Sonar 风险。

- [ ] P3-03 建立 CI 构建流水线。
  建议：至少包含前端 `npm run build`、后端 `mvn -DskipTests package`、Python 语法检查或 Ruff；按当前规则不新增单元测试代码。
  验收：每次提交都能自动发现构建失败和静态问题。

- [ ] P3-04 接入 SonarQube 扫描配置。
  建议：补充 `sonar-project.properties` 或 CI 参数，覆盖 Java、TypeScript、Python；排除构建产物、图片、历史归档文档和大体量种子数据。
  验收：Sonar 扫描聚焦有效源码，不被 `dist`、`target`、题库大 SQL 和归档文档干扰。

- [ ] P3-05 增加 OpenAPI 或接口契约文档生成。
  建议：Spring Boot 接入 springdoc-openapi；FastAPI 自带 OpenAPI，需要和 Java 调用契约对齐；前端类型可从契约生成或至少定期校验。
  验收：前后端字段不一致能在开发阶段被发现，而不是运行后才发现。

- [ ] P3-06 提供一键本地启动脚本。
  建议：在不引入新中间件的前提下，提供 PowerShell 脚本分步启动前端、后端、AI 服务；如果未来增加 Docker Compose 启动 MySQL/Redis，需要同步更新 `doc/中间件/`。
  验收：新开发者按 README 和脚本能快速启动本地联调环境。

- [ ] P3-07 增加配置分层和启动前校验。
  建议：后端按 `local`、`dev`、`prod` profile 管理 CORS、JWT、AI 服务、日志级别；AI 服务启动时校验 token、模型和 baseUrl 配置。
  验收：生产环境不会使用占位密钥、宽松 CORS 或本地默认配置启动。

- [ ] P3-08 建立依赖升级和漏洞检查机制。
  建议：前端定期执行 `npm audit` 或等价工具；Java 使用 Maven versions 或 OWASP dependency-check；Python 使用 pip-audit 或 Safety。
