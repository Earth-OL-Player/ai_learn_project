# AI 学习系统日志平台方案

## 1. 背景与目标

当前系统由 `ai-learn-backend`、`ai-service`、`ai-learn-web` 组成。本方案只聚焦需要集中检索的服务端日志：

- `ai-learn-backend`：Spring Boot 后端服务日志。
- `ai-service`：FastAPI / Uvicorn AI 服务日志。

本项目日志平台统一采用 `Grafana Loki + Grafana + Grafana Alloy`。该组合部署轻、界面成熟、查询体验清爽，适合当前个人项目从本地开发逐步扩展到单台服务器部署。

建设目标：

- 支持按服务、环境、日志级别、时间范围、关键字检索日志。
- 支持快速定位接口异常、AI 调用失败、模型响应异常、限流拦截、启动失败等问题。
- 支持在 Grafana 中建立清爽美观的日志检索页和错误趋势面板。
- 降低中间件复杂度，避免为了日志平台引入过重的搜索集群和运维成本。
- 严格避免日志写入真实密码、Token、密钥、生产连接地址、用户敏感内容和模型完整上下文。

## 2. 总体方案

### 2.1 组件职责

| 组件 | 用途 | 本项目定位 |
| --- | --- | --- |
| Grafana | 日志检索界面、仪表盘、告警入口 | 开发和部署后的统一日志查看入口 |
| Loki | 日志存储和 LogQL 查询 | 存储后端与 AI 服务日志流 |
| Grafana Alloy | 日志采集、标签处理、转发 | 采集本机或容器日志并推送到 Loki |

Loki 官方文档已将 Alloy 列为日志发送方式。Promtail 在 Loki 3.x 体系中已进入迁移路径，因此新项目建议直接使用 Alloy。

### 2.2 推荐架构

```text
ai-learn-backend 日志文件
ai-service 日志文件
        |
        v
Grafana Alloy 采集日志、解析字段、补充标签
        |
        v
Grafana Loki 按日志流存储
        |
        v
Grafana Explore / Dashboard 检索、过滤、展示、告警
```

### 2.3 部署形态

第一阶段建议采用单机部署：

```text
同一台开发机或服务器
├── ai-learn-backend
│   └── logs/backend/app.log
├── ai-service
│   └── logs/ai-service/app.log
├── Grafana Alloy
├── Grafana Loki
└── Grafana
```

如果后续改为 Docker Compose 部署，仍建议保留同样的服务标签和日志字段，Alloy 可以从文件采集切换为容器日志采集。

## 3. 日志采集设计

### 3.1 采集模式

| 模式 | 本地开发 | 服务器部署 | 建议 |
| --- | --- | --- | --- |
| 文件采集 | 推荐 | 推荐 | 第一阶段优先采用，路径清晰，排查简单 |
| 容器采集 | 可选 | 可选 | 后续容器化部署后再启用 |
| 控制台采集 | 不推荐 | 不推荐 | 不利于保留和精确拆分服务日志 |

第一阶段统一使用文件采集：

```text
logs/backend/app.log
logs/ai-service/app.log
```

### 3.2 日志标签

Loki 查询依赖标签，标签必须稳定、低基数。不要把用户 ID、接口路径、请求 ID、异常消息作为 Loki 标签。

推荐标签：

| 标签 | 示例值 | 说明 |
| --- | --- | --- |
| `app` | `ai-learn` | 项目标识 |
| `service` | `backend` / `ai-service` | 服务标识 |
| `env` | `local` / `prod` | 环境标识 |
| `level` | `INFO` / `WARN` / `ERROR` | 日志级别 |
| `host` | `local-windows` / `server-01` | 主机标识 |

不建议作为标签的字段：

| 字段 | 原因 |
| --- | --- |
| `traceId` | 每个请求不同，基数过高 |
| `userId` | 用户数量增长后基数过高，也存在隐私风险 |
| `path` | 接口路径数量可能增长，建议保留在日志正文或 JSON 字段 |
| `message` | 文本无限变化，不适合作为标签 |
| `exception` | 堆栈内容变化大，不适合作为标签 |

### 3.3 日志保留策略

第一阶段建议保留周期：

| 环境 | Loki 保留周期 | 文件日志保留周期 | 说明 |
| --- | --- | --- | --- |
| 本地开发 | 7 天 | 7 天 | 控制磁盘占用 |
| 服务器测试 | 15 天 | 7 天 | 便于回看近期问题 |
| 正式部署 | 15 到 30 天 | 7 到 15 天 | 按服务器磁盘容量调整 |

## 4. 服务日志规范

### 4.1 统一字段

后端和 AI 服务建议统一输出 JSON 日志，便于后续在 Loki 中解析字段。

统一字段：

| 字段 | 示例值 | 必填 | 说明 |
| --- | --- | --- | --- |
| `timestamp` | `2026-05-26T20:00:00+08:00` | 是 | 日志时间 |
| `service` | `backend` | 是 | 服务名 |
| `env` | `local` | 是 | 环境 |
| `level` | `INFO` | 是 | 日志级别 |
| `traceId` | `本地请求链路ID占位符` | 建议 | 请求链路标识 |
| `logger` | `com.earth.online.player.ailearn` | 是 | 日志来源 |
| `message` | `请求处理完成` | 是 | 日志正文 |
| `exception` | `异常堆栈摘要占位符` | 否 | 异常信息 |

### 4.2 后端日志示例

```json
{
  "timestamp": "2026-05-26T20:00:00+08:00",
  "service": "backend",
  "env": "local",
  "level": "INFO",
  "traceId": "本地请求链路ID占位符",
  "logger": "com.earth.online.player.ailearn",
  "message": "请求处理完成"
}
```

后端建议记录：

- 服务启动和关闭。
- 接口异常和统一异常处理结果。
- AI 服务调用失败、超时、降级。
- 限流拦截结果。
- Flyway 启动结果。

后端禁止记录：

- `JWT_SECRET`、`AI_SERVICE_TOKEN`、数据库密码。
- 用户密码、验证码、完整 Token。
- 生产数据库连接地址。
- 用户完整答案、模型完整上下文和敏感业务数据。

### 4.3 AI 服务日志示例

```json
{
  "timestamp": "2026-05-26T20:00:00+08:00",
  "service": "ai-service",
  "env": "local",
  "level": "INFO",
  "traceId": "本地请求链路ID占位符",
  "logger": "app.practice",
  "message": "AI评分请求完成"
}
```

AI 服务建议记录：

- 服务启动和健康检查异常。
- 模型接口调用失败、超时、返回格式不合法。
- 本地规则兜底触发情况。
- 流式讨论中断原因。

AI 服务禁止记录：

- `AI_GRADING_API_KEY`、`AI_SERVICE_TOKEN`。
- 用户完整答案、参考答案、完整题干、聊天全文。
- 模型完整请求体和完整响应体。

### 4.4 日志级别约定

| 级别 | 使用场景 |
| --- | --- |
| `DEBUG` | 仅本地开发临时排查问题，生产默认关闭 |
| `INFO` | 服务启动、关键业务动作完成、外部调用完成 |
| `WARN` | 可恢复异常、降级、限流、参数异常 |
| `ERROR` | 接口失败、外部服务不可用、未预期异常 |

当前 `ai-service` 已支持 `AI_SERVICE_LOG_LEVEL`，生产默认 `INFO`。接入日志平台后仍建议生产保持 `INFO`，本地临时排查才允许切换到 `DEBUG`。

## 5. Alloy 采集配置建议

### 5.1 文件路径规划

建议后续落地时使用以下日志路径：

```text
ai-learn-backend/logs/backend/app.log
ai-service/logs/ai-service/app.log
```

如果服务器统一部署到 `/opt/ai-learn`，建议路径为：

```text
/opt/ai-learn/logs/backend/app.log
/opt/ai-learn/logs/ai-service/app.log
```

### 5.2 Alloy 配置示例

以下为示意配置，真实落地时需要按本地或服务器实际路径调整：

```hcl
loki.write "default" {
  endpoint {
    url = "http://127.0.0.1:3100/loki/api/v1/push"
  }
}

local.file_match "backend_logs" {
  path_targets = [{
    __path__ = "C:/Users/用户名占位符/Desktop/ai_learn_project/ai-learn-backend/logs/backend/*.log",
    app = "ai-learn",
    service = "backend",
    env = "local",
    host = "local-windows",
  }]
}

loki.source.file "backend_logs" {
  targets = local.file_match.backend_logs.targets
  forward_to = [loki.process.backend_logs.receiver]
}

loki.process "backend_logs" {
  stage.json {
    expressions = {
      level = "level",
      traceId = "traceId",
      message = "message",
    }
  }

  stage.labels {
    values = {
      level = "level",
    }
  }

  forward_to = [loki.write.default.receiver]
}

local.file_match "ai_service_logs" {
  path_targets = [{
    __path__ = "C:/Users/用户名占位符/Desktop/ai_learn_project/ai-service/logs/ai-service/*.log",
    app = "ai-learn",
    service = "ai-service",
    env = "local",
    host = "local-windows",
  }]
}

loki.source.file "ai_service_logs" {
  targets = local.file_match.ai_service_logs.targets
  forward_to = [loki.process.ai_service_logs.receiver]
}

loki.process "ai_service_logs" {
  stage.json {
    expressions = {
      level = "level",
      traceId = "traceId",
      message = "message",
    }
  }

  stage.labels {
    values = {
      level = "level",
    }
  }

  forward_to = [loki.write.default.receiver]
}
```

配置原则：

- 示例中的本地用户名、服务器地址、账号密码均使用占位符，不允许提交真实敏感信息。
- `level` 可以作为标签，便于快速检索错误日志。
- `traceId` 只作为 JSON 字段解析，不作为 Loki 标签。
- Windows 本地路径和 Linux 服务器路径需要分别维护示例。

## 6. Grafana 检索设计

### 6.1 数据源

Grafana 中新增 Loki 数据源：

```text
Name: ai-learn-loki
URL: http://loki:3100 或 http://127.0.0.1:3100
Access: Server
```

本地开发可以使用 `http://127.0.0.1:3100`。Docker Compose 场景下 Grafana 与 Loki 在同一网络内时，可以使用 `http://loki:3100`。

### 6.2 常用查询

查看全部服务日志：

```logql
{app="ai-learn"}
```

查看后端错误：

```logql
{app="ai-learn", service="backend", level="ERROR"}
```

查看 AI 服务错误：

```logql
{app="ai-learn", service="ai-service", level="ERROR"}
```

查看 AI 评分相关日志：

```logql
{app="ai-learn", service="ai-service"} |= "评分"
```

查看后端调用 AI 服务异常：

```logql
{app="ai-learn", service="backend"} |= "AI" |= "失败"
```

按请求链路 ID 检索：

```logql
{app="ai-learn"} |= "本地请求链路ID占位符"
```

统计 5 分钟内错误日志数量：

```logql
sum by (service) (count_over_time({app="ai-learn", level="ERROR"}[5m]))
```

### 6.3 推荐仪表盘

第一阶段建议创建一个 `AI Learn 日志总览` 仪表盘：

| 面板 | 类型 | 查询目标 |
| --- | --- | --- |
| 服务错误趋势 | Time series | 按服务统计 `ERROR` 数量 |
| 后端最新错误 | Logs | 展示 `backend` 最新 `ERROR` 日志 |
| AI 服务最新错误 | Logs | 展示 `ai-service` 最新 `ERROR` 日志 |
| 后端日志检索 | Logs | 展示 `backend` 全部日志 |
| AI 服务日志检索 | Logs | 展示 `ai-service` 全部日志 |

仪表盘变量建议：

| 变量 | 示例 | 说明 |
| --- | --- | --- |
| `env` | `local` / `prod` | 切换环境 |
| `service` | `backend` / `ai-service` | 切换服务 |
| `level` | `INFO` / `WARN` / `ERROR` | 切换日志级别 |

## 7. Loki 存储与保留建议

### 7.1 单机存储

第一阶段建议使用 Loki 单机模式和本地文件系统存储，降低部署复杂度。

建议目录：

```text
logs-platform/loki/data
logs-platform/grafana/data
logs-platform/alloy/config.alloy
```

### 7.2 保留策略

建议先按环境配置：

| 环境 | 保留时间 | 说明 |
| --- | --- | --- |
| 本地 | 7 天 | 快速排查即可 |
| 测试服务器 | 15 天 | 便于回看近期联调问题 |
| 正式服务器 | 30 天以内 | 根据磁盘容量调整 |

### 7.3 磁盘控制

需要关注：

- Loki 数据目录磁盘占用。
- 后端和 AI 服务本地日志文件滚动策略。
- Grafana 数据目录备份与迁移。
- 定期清理历史压缩日志，避免本地文件和 Loki 双重占满磁盘。

## 8. 安全与脱敏要求

日志平台接入后，所有日志都更容易被集中检索，因此脱敏要求必须前置。

禁止输出：

- 数据库真实连接地址、用户名、密码。
- `JWT_SECRET`、`AI_SERVICE_TOKEN`、`AI_GRADING_API_KEY`。
- 用户密码、验证码、完整手机号、邮箱等敏感信息。
- 完整 Token、Cookie、Authorization Header。
- 用户完整答案、完整题干、参考答案、聊天全文。
- 模型完整请求体和完整响应体。

允许输出：

- 服务名、接口名、异常类型。
- 外部调用耗时、失败原因摘要。
- 脱敏后的请求标识。
- 不包含敏感正文的业务状态变化。

建议脱敏方式：

- Token 只保留前后少量字符，或统一输出 `***`。
- 用户标识优先使用内部脱敏 ID。
- AI 调用日志只记录模型提供方、模型名、耗时、状态码、错误摘要。
- 异常堆栈可以记录，但需要避免异常消息拼接敏感请求体。

## 9. 落地实施步骤

第一阶段：最小可用日志平台。

1. 后端补充滚动文件日志，输出到 `logs/backend/app.log`。
2. AI 服务补充滚动文件日志，输出到 `logs/ai-service/app.log`。
3. 两个服务统一 JSON 日志字段。
4. 新增 Loki、Grafana、Alloy 本地启动配置。
5. Alloy 采集两个日志文件并打上 `app`、`service`、`env`、`host` 标签。
6. Grafana 配置 Loki 数据源。
7. 创建 `AI Learn 日志总览` 仪表盘。
8. 配置本地 7 天日志保留策略。
9. 正式接入运行依赖时，同步新增 `doc/中间件/日志平台.md`。

第二阶段：链路检索增强。

1. 后端生成或透传 `X-Request-Id`。
2. 后端调用 AI 服务时继续透传 `X-Request-Id`。
3. AI 服务日志写入同一个 `traceId`。
4. Grafana 中增加按 `traceId` 检索说明。
5. 后端接口异常、AI 服务调用异常均输出统一错误摘要。

第三阶段：告警与运维增强。

1. 增加后端 `ERROR` 数量告警。
2. 增加 AI 服务 `ERROR` 数量告警。
3. 增加 Loki 磁盘占用检查。
4. 增加 Grafana 仪表盘导出备份。
5. 服务器部署文档补充启动、停止、备份、恢复步骤。

## 11. 验收标准

最小可用版本验收标准：

- Grafana 可以正常打开日志检索页面。
- Loki 数据源在 Grafana 中连接成功。
- Alloy 能采集 `ai-learn-backend` 日志。
- Alloy 能采集 `ai-service` 日志。
- Grafana 可按 `service=backend` 检索后端日志。
- Grafana 可按 `service=ai-service` 检索 AI 服务日志。
- Grafana 可按 `level=ERROR` 检索错误日志。
- Grafana 可按关键字检索接口异常和 AI 调用异常。
- 日志中不存在真实密码、Token、密钥、生产连接地址和模型完整上下文。
- 已补充 `doc/中间件/日志平台.md`，并能根据该文档完成本地启动和验证。
