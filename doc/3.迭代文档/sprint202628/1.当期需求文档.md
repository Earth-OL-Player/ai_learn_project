# sprint202628 当期需求文档

版本：v1.0  
日期：2026-05-26  
迭代定位：日志级别运行期管理

## 1. 背景

当前 Java 后端和 Python AI 服务的日志级别主要依赖配置文件或环境变量。开发工程师排查问题时，如果需要临时打开 `DEBUG` 或恢复 `INFO`，通常需要修改配置并重启服务，影响排查效率。

本迭代基于 `日志方案.md` 的运行期日志管理诉求，先在现有管理者中心内提供最小可用能力：超级管理员可以分别查看和调整 Java 后端、Python AI 服务当前生效的日志级别，服务运行中的实际日志输出随设置立即变化。

## 2. 目标

1. 管理者中心新增“日志管理”导航入口。
2. 日志管理页面展示 Java 后端和 Python AI 服务当前日志级别。
3. 超级管理员可以分别设置两个服务的日志级别。
4. 设置完成后不重启服务即可生效。
5. 普通用户和游客不能访问日志管理接口和页面。
6. AI 服务日志级别调整通过 Java 后端代理完成，前端不直接访问 AI 服务内部接口。

## 3. 功能范围

### 3.1 Java 后端日志级别管理

- 支持读取 Java 后端当前有效日志级别。
- 支持设置 Java 后端当前有效日志级别。
- 设置范围覆盖根日志器和项目主包日志器，保证业务日志立即按新级别输出。

### 3.2 Python AI 服务日志级别管理

- AI 服务新增内部接口，支持读取和设置当前有效日志级别。
- 内部接口必须继续使用 `X-Internal-Token` 鉴权。
- Java 后端负责调用 AI 服务内部接口，并向前端返回统一管理结果。
- 当 AI 服务未启动或不可达时，页面需要显示不可用状态，不能影响 Java 后端日志级别管理。

### 3.3 管理者中心页面

- 左侧导航新增“日志管理”。
- 页面以简洁卡片展示两个服务的日志状态。
- 每个服务支持选择日志级别并保存。
- 支持刷新当前日志级别。
- 保存成功、失败、AI 服务不可用等场景需要有清晰提示。

## 4. 日志级别范围

本迭代支持以下日志级别：

| 级别 | 说明 |
| --- | --- |
| `TRACE` | 最细粒度排查，仅建议本地短时间开启 |
| `DEBUG` | 开发排查问题时使用 |
| `INFO` | 默认推荐级别 |
| `WARN` | 仅输出警告及以上日志 |
| `ERROR` | 仅输出错误日志 |

## 5. 权限要求

- 前端路由沿用管理者中心超级管理员限制。
- 后端 `/api/v1/admin/**` 接口必须登录后访问。
- 日志管理接口内部再次校验当前用户是否为超级管理员。
- AI 服务内部日志接口只接受 Java 后端携带的内部 Token。

## 6. 非功能要求

1. 日志级别调整不能输出真实 Token、密钥、数据库密码等敏感信息。
2. 代码保持 UTF-8 编码，注释使用简体中文。
3. 不新增单元测试代码。
4. 不新增数据库表和 Flyway 迁移。
5. 不新增运行时中间件依赖。
6. 不修改历史数据库迁移文件。

## 7. 验收标准

1. 超级管理员可以在管理者中心看到“日志管理”导航。
2. 日志管理页面可以展示 Java 后端当前日志级别。
3. 日志管理页面可以展示 Python AI 服务当前日志级别；AI 服务不可用时显示不可用。
4. 分别设置 Java 后端和 Python AI 服务日志级别后，无需重启即可生效。
5. 非超级管理员无法通过接口调整日志级别。
6. 后端构建通过。
7. 前端构建通过。
