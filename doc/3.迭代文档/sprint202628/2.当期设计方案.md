# sprint202628 当期设计方案

版本：v1.0  
日期：2026-05-26  
迭代定位：日志级别运行期管理

## 1. 总体设计

本迭代不接入新的日志平台中间件，只实现运行期日志级别动态调整能力。整体链路如下：

```text
管理者中心日志管理页面
        |
        v
Java 后端 /api/v1/admin/log-levels
        |                         |
        |                         v
        |                 Spring LoggingSystem
        |
        v
Python AI 服务 /internal/v1/log-levels
```

前端只访问 Java 后端，AI 服务继续作为内部服务存在。这样可以复用现有登录态、超级管理员校验、统一响应结构和内部服务 Token，不把 AI 服务内部地址或 Token 暴露到浏览器。

## 2. 后端设计

### 2.1 Java 后端接口

新增接口前缀：

```text
/api/v1/admin/log-levels
```

接口列表：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/admin/log-levels` | 查询 Java 后端和 AI 服务日志级别 |
| `PUT` | `/api/v1/admin/log-levels/{service}` | 设置指定服务日志级别 |

`service` 支持：

| 值 | 含义 |
| --- | --- |
| `backend` | Java 后端 |
| `ai-service` | Python AI 服务 |

### 2.2 Java 后端日志调整

Java 端使用 Spring Boot 内置 `LoggingSystem` 设置运行期日志级别：

- `ROOT`：控制第三方和整体日志输出下限。
- `com.earth.online.player.ailearn`：控制项目业务包日志输出。

设置后立即生效，不修改 `application.yml`，服务重启后仍回到配置文件或环境变量定义的默认级别。

### 2.3 AI 服务代理调用

Java 后端新增内部客户端，使用现有 `app.ai-service.base-url` 和 `app.ai-service.token` 调用 AI 服务内部接口：

```text
GET /internal/v1/log-levels
PUT /internal/v1/log-levels
```

请求头：

```text
X-Internal-Token: AI_SERVICE_TOKEN占位符
```

AI 服务不可用时，查询接口返回 `available=false`，设置接口返回业务错误提示，避免误判为设置成功。

## 3. AI 服务设计

### 3.1 内部接口

AI 服务新增 `app/api/log_levels.py`，路由前缀：

```text
/internal/v1/log-levels
```

接口列表：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/internal/v1/log-levels` | 查询当前 AI 服务日志级别 |
| `PUT` | `/internal/v1/log-levels` | 设置当前 AI 服务日志级别 |

两个接口都依赖 `verify_internal_token`。

### 3.2 日志级别生效方式

AI 服务在 `log_config.py` 内维护当前运行期日志级别：

- `configure_logger` 创建日志器时读取当前运行期级别。
- `set_service_log_level` 更新根日志器、已存在的项目日志器和处理器级别。
- `get_service_log_level` 返回当前生效级别。

这样已经创建的日志器和后续新创建的日志器都能使用同一个运行期级别。

## 4. 前端设计

### 4.1 路由和导航

管理者中心新增路由：

```text
/admin/log-levels
```

左侧菜单新增“日志管理”。

### 4.2 页面结构

页面展示两张服务卡片：

- 服务名称。
- 当前日志级别。
- 可用状态。
- 日志级别选择器。
- 保存按钮。

顶部提供刷新按钮，用于重新读取两个服务当前级别。

### 4.3 交互规则

1. 页面加载时自动查询日志级别。
2. 保存 Java 后端日志级别时，只更新 Java 后端服务。
3. 保存 AI 服务日志级别时，通过 Java 后端代理更新 AI 服务。
4. AI 服务不可用时禁用保存按钮，并显示不可用提示。
5. 保存失败时展示后端返回的中文错误消息。

## 5. 安全设计

1. 浏览器不直接访问 AI 服务内部接口。
2. AI 服务内部接口使用 `X-Internal-Token` 校验。
3. Java 后端日志管理应用服务校验当前用户必须是超级管理员。
4. 接口日志不输出 Token、密码、模型 Key 和用户答案内容。

## 6. 中间件影响

本迭代不新增 MySQL、Redis、Qdrant、Loki、Grafana、Alloy 等中间件运行依赖，也不新增数据库结构。因此无需新增或更新 `doc/中间件/` 文档。

后续如果真正接入 Loki、Grafana、Alloy 采集和检索平台，需要按项目规范补充 `doc/中间件/日志平台.md`。
