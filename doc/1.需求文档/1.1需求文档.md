# AI应用开发学习平台 MVP 需求文档

版本：v1.3
日期：2026-05-18
来源：`doc/1.需求文档/1.1我的大白话需求.md`

## 1. 项目定位

本项目面向正在学习 AI 应用开发的用户，先交付一个可访问、可演示、可持续迭代的 MVP。首期重点不是一次性做完整学习社区，而是持续打磨四个入口、登录权限、内容展示、建议评论、系统题库、成长激励和 AI 智能刷题闭环。

项目后续的核心竞争力放在“智能刷题”：平台提供默认题库，用户可以维护个人题库；系统结合系统题库、答题记录、短期讨论记忆、RAG 检索、大模型评分/讨论和本地兜底能力，帮助用户刷题、复盘和持续提升。

## 2. 目标与边界

### 2.1 MVP 交付目标

MVP 需要完成以下内容：

- 搭建网站基础布局：顶部横向主导航、主内容区、右上角用户区。
- 提供四个顶部横向菜单，顺序为：路线和资料、AI智能刷题、热门面经、建议评论区。
- 完成注册、登录、退出和基础权限控制。
- 将 `doc/学习路线页面` 中的学习资料展示为首页内容。
- 支持游客查看建议和评论，登录用户可以提交建议和评论。
- 热门面经展示系统题库内容，支持按分类浏览和查看题目详情。
- AI智能刷题提供出题、答题、评分、重新作答、下一题、本题讨论、短期记忆和成长奖励闭环。
- 管理者中心支持超级管理员管理用户容量、用户状态和系统题库导入维护。

### 2.2 后续产品目标

- 沉淀 AI 学习路线、学习资料、面试题、项目实战和题库内容。
- 建设基于 LangChain、LangGraph、LlamaIndex、RAG 和向量数据库的智能刷题能力。
- 通过经验、等级、段位、徽章和复习推荐，让用户有持续学习的反馈。
- 逐步补齐社区互动、后台管理、学习统计和 AI 助教能力。

### 2.3 本期不做或只预留

为避免 MVP 失控，以下能力本期只做结构预留或页面占位：

- 复杂评论举报、审核流和多级嵌套回复。
- 完整个人题库在线编辑器。
- 大规模 RAG 入库调度、权限过滤和向量检索调优。
- Redis 缓存、限流、验证码等高并发能力。

## 3. 用户角色

| 角色 | 说明 | 本期能力 |
| --- | --- | --- |
| 游客 | 未登录用户 | 查看首页、查看建议评论区；触发发布、面试题、AI智能刷题、个人中心时引导登录 |

## 4. 页面与菜单

### 4.1 页面框架

页面采用知识平台常见布局：

- 顶部左侧：平台品牌标识。
- 顶部中间：横向主导航，依次展示“路线和资料、AI智能刷题、热门面经、建议评论区”。
- 顶部右侧：登录入口或用户头像、用户名。
- 中间：当前菜单对应的主内容。
- 用户头像区域：悬浮或点击后展开用户菜单。

未登录时右上角展示“登录 / 注册”；登录后展示头像、昵称和下拉菜单。受限功能不直接报错，统一弹出登录引导。

### 4.2 菜单规划

## 5. 功能需求

### 5.1 路线和资料

#### 5.1.1 功能说明

该页面同时作为网站首页。它负责把已有学习资料整理成适合阅读的页面，帮助用户快速了解 AI 应用开发的学习路径。

#### 5.1.2 内容来源

资料来源目录：

```text
doc/学习路线页面
```

MVP 可以先由前端读取或转换 Markdown 内容；后续如需要后台管理，再迁移到数据库或内容管理模块。

#### 5.1.3 页面内容

页面至少包含：

- 平台说明：说明项目适合哪些学习者。
- 路线总览：用阶段卡片、时间线或知识地图展示学习顺序。
- 基础阶段：Python、数学基础、机器学习基础。
- 进阶阶段：深度学习、NLP、CV、大模型基础。
- 工程阶段：LangChain、LangGraph、RAG、向量数据库、模型部署。
- 实战阶段：AI Agent、知识库问答、智能刷题、企业应用。
- 资料区：书籍、课程、文档、论文和开源项目。
- 学习建议：学习顺序、避坑说明、常见问题。

#### 5.1.4 权限

游客和登录用户均可访问。

### 5.2 建议评论区

#### 5.2.1 功能说明

该页面用于收集平台改进建议，也用于用户围绕学习内容进行交流。页面分为两个 Tab：建议区和评论区。

#### 5.2.2 建议区

建议区用于收集对平台功能、体验和内容的反馈。

字段范围：

| 字段 | 说明 |
| --- | --- |
| 标题 | 建议标题 |
| 内容 | 具体说明 |
| 类型 | 功能建议、体验建议、内容建议、Bug 反馈等 |
| 状态 | 待处理、已采纳、已拒绝、已完成 |
| 提交用户 | 登录用户信息 |
| 提交时间 | 建议创建时间 |

MVP 要求：

- 游客可以查看建议列表。
- 登录用户可以提交建议。
- 游客点击提交时弹出登录 / 注册引导。
- 状态变更可先由数据字段预留，管理后台后续实现。

#### 5.2.3 评论区

评论区用于发布学习心得、问题讨论或对平台内容的评价。

字段范围：

| 字段 | 说明 |
| --- | --- |
| 内容 | 评论正文 |
| 用户 | 评论发布人 |
| 头像 | 用户头像 |
| 发布时间 | 评论创建时间 |
| 点赞数 | 后续扩展 |
| 父评论 ID | 后续支持回复时使用 |

MVP 要求：

- 游客可以查看评论列表。
- 登录用户可以发表评论。
- 游客点击发布时弹出登录 / 注册引导。
- 回复、点赞、审核先做字段或接口扩展点，不进入首期验收范围。

### 5.3 热门面经

#### 5.3.1 功能说明

该页面用于后续沉淀 AI、大模型、Java、后端、算法、Agent、RAG 等方向的面试题。MVP 阶段先做占位页，保证菜单和权限链路完整。

#### 5.3.2 MVP 页面要求

占位页展示：

- 页面标题：热门面经。
- 简短说明：内容建设中，后续将提供 AI、大模型、后端、算法等方向面试题。
- 空状态插画或提示文案。

#### 5.3.3 后续能力

后续迭代时补充：

- 面试题分类、标签和难度。
- 搜索、筛选、收藏。
- 题目解析和参考答案。
- AI 生成参考答案或补充解析。
- 后台导入和维护题库。

#### 5.3.4 权限

游客点击菜单时引导登录；登录用户可访问。

### 5.4 AI智能刷题

#### 5.4.1 功能说明

AI智能刷题是项目重点。它围绕“出题 - 答题 - 评分 - 复盘 - 成长反馈”形成闭环，让用户在刷题过程中获得明确反馈。

能力由两部分组成：

- 业务侧能力：题库、个人题库、答题记录、经验、等级、段位、徽章。
- AI 侧能力：RAG 检索、题目推荐或生成、答案审题、评分和学习建议。

#### 5.4.2 基础流程

1. 用户进入AI智能刷题页面。
2. 系统校验登录态。
3. 系统根据默认题库、个人题库和答题记录生成候选题。
4. 系统按推荐权重选择题目，必要时结合 RAG 生成新题。
5. 用户提交答案。
6. AI 服务或评分模块输出评分、参考答案和改进建议。
7. 后端校验评分结果并保存答题记录。
8. 系统更新经验、等级、段位和徽章状态。
9. 前端展示本次得分、命中点、遗漏点、复习建议和成长反馈。

#### 5.4.3 MVP 交付范围

MVP 至少完成：

- AI智能刷题入口页。
- 登录后可开始一次刷题。
- 从默认题库或示例题中给出题目。
- 用户可以提交答案。
- 页面展示评分结果结构，包括得分、参考答案、改进建议。
- 保存答题记录，为后续推荐权重和成长体系提供数据。

RAG 检索、LangGraph 编排、LlamaIndex 索引和复杂个性化推荐可以先以原型接口或灰度能力接入，不阻塞基础页面验收。

#### 5.4.4 智能出题

出题能力按阶段增强：

- 从平台默认题库选择题目。
- 从用户个人题库选择题目。
- 根据答题记录提高薄弱知识点出现概率。
- 避免短时间内反复出现用户已高分通过的题目。
- 基于 RAG 检索学习资料或题库片段生成新题。
- 支持题型扩展：选择题、简答题、代码题、场景题。
- 支持难度扩展：简单、中等、困难。

#### 5.4.5 审题与评分

用户提交答案后，评分结果必须结构化，方便前端展示和后端落库。

评分结果包含：

| 字段 | 说明 |
| --- | --- |
| score | 0 - 100 分 |
| isCorrect | 是否基本正确 |
| hitPoints | 命中的关键点 |
| missingPoints | 缺失的关键点 |
| problems | 错误或不严谨表述 |
| referenceAnswer | 参考答案 |
| improvementAdvice | 改进建议 |
| reviewKnowledgePoints | 建议复习的知识点 |

后端不得直接信任 AI 输出，必须校验分数范围、必填字段、文本长度和数组长度。

#### 5.4.6 推荐权重规则

初始权重规则保持简单可解释：

```text
题目权重 = 基础权重 + 未刷加权 + 低分加权 + 薄弱知识点加权 + 个人题库加权 - 高频重复惩罚
```

规则说明：

- 没刷过的题权重更高。
- 刷过但得分低的题权重更高。
- 近期频繁刷过且得分高的题权重降低。
- 用户个人题库题目适当加权。
- 长期薄弱知识点对应题目适当加权。

MVP 可以先在后端实现简单规则；后续再根据数据表现调整或迁移到 AI 服务。

#### 5.4.7 默认题库和个人题库

默认题库由平台维护，用户无需上传即可使用。题目字段包括：标题、内容、题型、难度、标签、知识点、标准答案、解析、来源说明。

个人题库由用户维护，支持两种导入方式：

1. 全量替换：新题库覆盖当前个人题库。
2. 追加补充：新题追加到当前个人题库。

MVP 先预留个人题库数据结构和导入入口；在线编辑、批量校验、冲突处理后续迭代。

#### 5.4.8 答题记录

每次答题完成后保存记录。字段包括：用户 ID、题目 ID、用户答案、得分、AI 评语、改进建议、耗时、答题时间、是否首次作答、关联知识点。

答题记录用于：

- 后续题目推荐。
- 个人学习统计。
- 经验和徽章计算。
- 薄弱知识点分析。

### 5.5 成长体系

成长体系用于给用户持续反馈。MVP 可先展示基础数值，完整规则后续调整。

#### 5.5.1 经验与等级

经验来源：

- 完成答题获得基础经验。
- 高分答题获得额外经验。
- 连续学习获得额外经验。
- 低分题复刷后提分获得额外经验。

等级示例：

| 等级 | 称号 | 经验范围 |
| --- | --- | --- |
| Lv1 | AI 入门者 | 0 - 99 |
| Lv2 | AI 探索者 | 100 - 299 |
| Lv3 | AI 实践者 | 300 - 699 |
| Lv4 | AI 进阶者 | 700 - 1499 |
| Lv5 | AI 工程师 | 1500 - 2999 |
| Lv6 | AI Agent 玩家 | 3000 - 5999 |
| Lv7 | AI 架构师 | 6000 以上 |

#### 5.5.2 段位

段位用于展示学习状态，可由累计经验、平均得分、连续学习天数、完成题量和高难度题完成情况综合计算。

段位示例：青铜、白银、黄金、铂金、钻石、大师、王者。

#### 5.5.3 徽章

徽章在用户达成里程碑时发放，并在个人中心展示。

| 徽章 | 获得条件 |
| --- | --- |
| 初次启程 | 完成第 1 道题 |
| 坚持三天 | 连续学习 3 天 |
| 七日修炼 | 连续学习 7 天 |
| 百题斩 | 累计完成 100 道题 |
| 高分选手 | 单题得分达到 90 分以上 |
| 查漏补缺 | 低分题复刷后提升 20 分以上 |
| RAG 初体验 | 完成 RAG 相关题目 10 道 |
| Agent 探索者 | 完成 Agent 相关题目 10 道 |

### 5.6 用户中心

#### 5.6.1 入口

右上角展示头像和用户名。悬浮或点击后显示：个人中心、我的题库、我的答题记录、我的等级与徽章、账号设置、退出登录。

#### 5.6.2 个人中心内容

个人中心展示：

- 头像、昵称、注册时间。
- 当前等级、段位、经验值。
- 已获得徽章。
- 累计答题数、平均得分、连续学习天数。

## 8. 非功能需求

### 8.1 易用性

- 首页内容结构清晰，学习路线便于快速浏览。
- 受限功能提供明确登录引导，不使用生硬错误页。
- 刷题结果突出得分、优点、不足、参考答案和下一步建议。

### 8.2 可扩展性

- 菜单、题库、标签、知识点、等级和徽章规则可扩展。
- AI Agent 流程可替换模型、向量数据库和提示词策略。
- 默认题库和个人题库在数据结构上明确区分。

### 8.3 安全性

- 密码必须加密存储，不保存明文。
- 用户只能访问和修改自己的个人题库、答题记录和个人资料。
- 建议、评论和 AI 输出预留内容安全处理。
- AI 评价需要提示“仅供学习参考”，避免用户误认为绝对正确。

### 8.4 性能

- 首页和学习路线优先静态化或缓存。
- 列表接口分页加载。
- AI智能刷题调用 AI 时展示 loading 和失败兜底。
- 题目推荐、答题记录、向量检索等高频场景预留索引或缓存。

### 8.5 可维护性

- 前端、后端、AI 服务职责清晰。
- 经验、等级、徽章、推荐权重集中管理。
- Prompt、评分规则和 RAG 策略可版本化维护。

## 9. AI Agent 技术方向

### 9.1 RAG 流程

1. 学习资料和题库内容入库。
2. 对题目、答案、解析和知识点进行切分、向量化。
3. 用户请求刷题时，结合历史答题和薄弱点生成检索条件。
4. 从向量数据库召回相关题目和知识片段。
5. Agent 选择已有题或生成新题。
6. 用户答题后，Agent 基于标准答案和知识片段评分。
7. 后端保存答题记录，更新学习画像和成长数据。

### 9.2 LangGraph 工作流

AI智能刷题可拆为：用户画像分析、候选题召回、推荐决策、出题、答案评审、学习建议、成长计算、结果保存。

### 9.3 LlamaIndex 用途

LlamaIndex 用于资料索引、文档切分、元数据管理和检索逻辑封装。

### 9.4 向量数据库用途

向量数据库保存学习资料、题目内容、标准答案、解析和知识点说明的向量索引，用于 RAG 检索和相似题推荐。

## 10. 验收标准

### 10.1 页面验收

- 打开网站默认进入“路线和资料”。
- 顶部横向导航展示四个菜单，顺序为“路线和资料、AI智能刷题、热门面经、建议评论区”，菜单切换正常。
- 右上角根据登录状态展示登录 / 注册或用户信息。
- 热门面经和AI智能刷题在未登录时触发登录引导。

### 10.2 权限验收

- 游客可以查看首页和建议评论列表。
- 游客不能发布建议和评论。
- 游客不能访问热门面经、AI智能刷题和个人中心。
- 登录用户可以访问全部菜单并发布建议、评论。

### 10.3 AI智能刷题验收

- 登录用户可以开始一次刷题。
- 页面能展示题目并提交答案。
- 系统能返回评分、参考答案和改进建议。
- 答题记录能够保存，为后续推荐和成长体系提供数据。
- 文档中明确默认题库、个人题库、推荐权重、评分结构和成长体系方向。
