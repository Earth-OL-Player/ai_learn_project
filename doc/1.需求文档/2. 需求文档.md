# AI学习项目 MVP 需求文档

## 1. 项目背景

本项目定位为一个面向 AI 学习者的综合学习平台，首期以 MVP 形式快速落地核心功能，帮助用户完成 AI 学习路线查看、学习资料浏览、建议评论互动，以及后续通过 AI 智能刷题系统进行持续学习和能力提升。

项目第一阶段重点验证以下目标：

- 通过结构化学习路线降低 AI 初学者的学习门槛。
- 通过建议与评论模块收集真实用户反馈，辅助后续产品迭代。
- 通过权限控制区分游客和登录用户，形成基础用户体系。
- 以“刷题 Agent”为核心亮点，打造智能出题、智能批改、评分反馈、经验成长、徽章激励的正反馈学习闭环。

## 2. 项目目标

### 2.1 MVP 目标

- 搭建一个可访问、可演示、可扩展的 AI 学习平台。
- 完成基础页面框架、菜单导航、用户登录注册入口和权限控制。
- 完成 AI 学习路线与资料静态展示页面。
- 完成建议与评论页面的基础交互设计。
- 完成面试题大全的占位页面，为后续内容建设预留入口。
- 完成刷题 Agent 的需求设计，为后续研发 RAG Agent 智能刷题系统打好基础。

### 2.2 长期目标

- 建设 AI 学习路线、资料、题库、面试题、项目实战内容的综合知识库。
- 打造基于 LangChain、LangGraph、RAG、LlamaIndex、向量数据库等技术的智能刷题系统。
- 通过个性化题库、智能推荐、答题评分、学习成长体系，提高用户持续学习意愿。
- 逐步演进为一个具备社区属性、AI 助教能力和学习进度管理能力的 AI 学习平台。

## 3. 用户角色

### 3.1 游客用户

未注册或未登录的用户。

游客用户可以：

- 访问网站首页。
- 查看“AI学习路线与资料”页面。
- 查看“建议与评论”页面内容。

游客用户不可以：

- 发布建议。
- 发布评论。
- 访问“面试题大全”。
- 访问“刷题Agent”。
- 使用个性化题库、答题记录、经验等级、徽章等登录态能力。

### 3.2 注册用户

已经注册并登录的普通用户。

注册用户可以：

- 查看全部菜单页面。
- 发布建议与评论。
- 使用面试题大全功能。
- 使用刷题 Agent 功能。
- 管理个人题库。
- 查看答题记录、评分记录、经验、等级、段位和徽章。
- 进入个人中心维护基础资料。

### 3.3 管理员用户（后续扩展）

管理员用于平台内容和社区治理，MVP 阶段可先预留能力，不一定实现完整后台。

管理员后续可以：

- 管理用户。
- 管理建议与评论内容。
- 管理默认题库。
- 管理面试题内容。
- 管理学习路线资料。
- 管理徽章、等级、段位规则。

## 4. 页面与菜单规划

### 4.1 整体布局

系统采用常见后台/知识平台式布局：

- 左侧为菜单导航区域。
- 中间为主要内容展示区域。
- 右上角为用户信息区域，展示用户名和头像。
- 鼠标悬浮或点击用户信息区域时，展示用户中心相关入口。

### 4.2 左侧菜单

首期规划 4 个菜单：

1. AI学习路线与资料
2. 建议与评论
3. 面试题大全
4. 刷题Agent

## 5. 功能需求

## 5.1 AI学习路线与资料

### 5.1.1 功能定位

该页面同时作为网站首页，是游客和登录用户都可以访问的核心入口页面。

页面主要展示 AI 学习路线、学习阶段、推荐资料、学习建议等静态知识内容。

### 5.1.2 内容来源

页面展示资料来自项目目录：

```text
doc/学习路线页面
```

后续开发时需要读取或转化该目录下已编写好的资料，形成前端可展示内容。

### 5.1.3 页面内容建议

建议页面包含以下模块：

- 顶部介绍区：说明平台用途和适合人群。
- AI 学习路线总览：以时间线、阶段卡片或知识地图形式展示。
- 基础阶段：Python、数学基础、机器学习基础。
- 进阶阶段：深度学习、NLP、CV、大模型基础。
- 工程阶段：LangChain、LangGraph、RAG、向量数据库、模型部署。
- 实战阶段：AI Agent、知识库问答、智能刷题、企业级应用。
- 推荐资料区：书籍、课程、文档、论文、开源项目等。
- 学习建议区：学习顺序、避坑建议、常见问题。

### 5.1.4 权限要求

- 游客可访问。
- 登录用户可访问。

## 5.2 建议与评论

### 5.2.1 功能定位

该页面用于收集用户对平台的建议，也用于用户围绕学习内容进行评论交流。

页面分为两个区域，可通过 Tab 或按钮切换：

- 建议区
- 评论区

### 5.2.2 建议区

用户可以在建议区提交对平台的改进建议。

建议字段包括：

- 建议标题
- 建议内容
- 建议类型，例如功能建议、体验建议、内容建议、Bug 反馈
- 提交时间
- 提交用户
- 处理状态，例如待处理、已采纳、已拒绝、已完成

MVP 阶段可优先实现：

- 建议列表展示。
- 登录用户提交建议。
- 游客点击提交时引导注册登录。

### 5.2.3 评论区

用户可以在评论区发表学习心得、问题讨论或对平台内容的评论。

评论字段包括：

- 评论内容
- 评论用户
- 用户头像
- 发布时间
- 点赞数（可后续扩展）
- 回复列表（可后续扩展）

MVP 阶段可优先实现：

- 评论列表展示。
- 登录用户发表评论。
- 游客点击发表时引导注册登录。

### 5.2.4 权限要求

- 游客可查看建议和评论。
- 游客不可发布建议和评论，点击发布时需要弹出登录/注册引导。
- 登录用户可发布建议和评论。

## 5.4 刷题Agent

### 5.4.1 功能定位

刷题 Agent 是本项目的核心亮点，目标是打造一个 AI 智能刷题系统，让用户获得个性化、正反馈、可持续的刷题体验。

系统需要结合：

- LangChain
- LangGraph
- RAG
- LlamaIndex
- 向量数据库
- 大模型能力
- 用户答题记录
- 个性化题库
- 经验、等级、段位、徽章系统

具体技术选型应在开发阶段优先使用最新稳定版本，并保证可维护性、社区活跃度和工程可落地性。

### 5.4.2 核心流程

刷题 Agent 的核心流程如下：

1. 用户进入刷题 Agent 页面。
2. 系统基于默认题库和用户个性化题库构建候选题目集合。
3. 系统结合用户历史答题情况，计算题目推荐权重。
4. AI Agent 智能选择或生成题目。
5. 用户提交答案。
6. AI Agent 对用户答案进行审题和评分。
7. 系统返回评分、参考答案、改进建议和知识点解析。
8. 系统记录本次答题结果。
9. 系统根据得分、完成情况和连续学习行为计算经验值。
10. 系统更新用户等级、段位和徽章。

### 5.4.3 AI 智能出题

AI 智能出题需要支持以下能力：

- 从默认题库中选择题目。
- 从用户个性化题库中选择题目。
- 基于 RAG 检索相关知识后生成新题。
- 根据用户薄弱知识点提高相关题目出现概率。
- 根据用户历史答题情况避免长期重复刷同一批题。
- 支持题目难度控制，例如简单、中等、困难。
- 支持题目类型扩展，例如选择题、简答题、代码题、场景题。

### 5.4.4 AI 智能审题与评分

用户提交答案后，系统需要调用 AI 审题能力，输出结构化评审结果。

评审结果建议包括：

- 总评分，建议 0 到 100 分。
- 答案正确性判断。
- 命中的关键点。
- 缺失的关键点。
- 错误或不严谨的表述。
- 标准参考答案。
- 改进建议。
- 推荐复习知识点。

### 5.4.5 题目推荐权重规则

题目推荐需要体现正反馈和个性化。

推荐权重建议遵循以下原则：

- 未刷过的题目权重更高。
- 已刷过但得分较低的题目权重更高。
- 最近频繁刷过且得分较高的题目权重降低。
- 用户个性化题库中的题目可适当提高权重。
- 用户长期薄弱知识点相关题目权重提高。

可参考的初始规则：

```text
题目权重 = 基础权重 + 未刷加权 + 低分加权 + 薄弱知识点加权 - 高频重复惩罚
```

MVP 阶段不要求规则特别复杂，但需要预留后续调优空间。

### 5.4.6 默认题库

默认题库由平台维护，用户无需上传即可使用。

默认题库内容由项目维护者人工搜寻和整理，后续可导入系统。

默认题库建议包含：

- 题目标题
- 题目内容
- 题目类型
- 难度
- 标签
- 知识点
- 标准答案
- 解析
- 来源说明

### 5.4.7 个性化题库

用户可以维护自己的个性化题库。

支持两种方式：

1. 全量替换：用户上传新题库后，替换当前个人题库。
2. 额外补充：用户上传新题库后，在当前个人题库基础上追加题目。

个性化题库建议支持：

- 在线编辑题目。
- 上传题库文件。
- 查看题库列表。
- 删除题目。
- 修改题目。
- 设置题目标签和难度。

MVP 阶段可优先实现基础数据结构和导入入口，复杂编辑能力后续迭代。

### 5.4.8 答题记录

每次答题完成后，系统需要记录用户答题结果。

记录字段建议包括：

- 用户 ID
- 题目 ID
- 用户答案
- AI 评分
- AI 评语
- 改进建议
- 答题耗时
- 答题时间
- 是否首次作答
- 关联知识点

答题记录将用于：

- 后续智能出题推荐。
- 个人学习统计。
- 经验值计算。
- 薄弱知识点分析。

### 5.4.9 经验与等级系统

系统需要通过经验值激励用户持续刷题。

经验值建议来源：

- 完成一次答题获得基础经验。
- 高分答题获得额外经验。
- 连续学习获得额外经验。
- 完成每日目标获得额外经验。
- 复习低分题并提升分数获得额外经验。

等级示例：

| 等级 | 称号 | 经验范围 |
| --- | --- | --- |
| Lv1 | AI 入门者 | 0 - 99 |
| Lv2 | AI 探索者 | 100 - 299 |
| Lv3 | AI 实践者 | 300 - 699 |
| Lv4 | AI 进阶者 | 700 - 1499 |
| Lv5 | AI 工程师 | 1500 - 2999 |
| Lv6 | AI Agent 玩家 | 3000 - 5999 |
| Lv7 | AI 架构师 | 6000 以上 |

等级规则后续可根据真实用户行为调整。

### 5.4.10 段位系统

段位系统用于展示用户学习成长状态。

建议段位：

- 青铜
- 白银
- 黄金
- 铂金
- 钻石
- 大师
- 王者

段位可由综合分决定，综合分可基于以下指标：

- 累计经验值
- 平均答题得分
- 连续学习天数
- 完成题目数量
- 高难度题目完成情况

### 5.4.11 徽章系统

用户达成指定里程碑时可以获得徽章，徽章可在个人中心展示。

徽章示例：

| 徽章名称 | 获得条件 |
| --- | --- |
| 初次启程 | 完成第 1 道题 |
| 坚持三天 | 连续学习 3 天 |
| 七日修炼 | 连续学习 7 天 |
| 百题斩 | 累计完成 100 道题 |
| 高分选手 | 单题得分达到 90 分以上 |
| 查漏补缺 | 低分题复刷后提升 20 分以上 |
| RAG 初体验 | 完成 RAG 相关题目 10 道 |
| Agent 探索者 | 完成 Agent 相关题目 10 道 |

### 5.4.12 权限要求

- 游客点击该菜单时，需要引导注册登录。
- 登录用户可访问并使用刷题 Agent。

## 9. 非功能需求

### 9.1 易用性

- 页面结构清晰，学习路线要便于阅读。
- 游客访问受限功能时要有明确引导，不让用户困惑。
- 刷题结果反馈需要直观展示评分、优点、不足和建议。

### 9.2 可扩展性

- 菜单、题库、徽章、等级规则需要支持后续扩展。
- AI Agent 流程需要模块化，便于替换模型、向量数据库和提示词策略。
- 题库需要区分默认题库和用户个性化题库。

### 9.3 安全性

- 用户密码必须加密存储，不允许明文保存。
- 用户只能访问和修改自己的个性化题库与答题记录。
- 评论和建议内容需要预留审核或敏感词处理能力。
- AI 输出内容需要有兜底提示，避免用户误认为所有 AI 评价都绝对正确。

### 9.4 性能要求

- 首页和学习路线页面应优先保证加载速度。
- 刷题 Agent 调用大模型时需要展示加载状态。
- 对向量检索、题目推荐、用户记录查询等高频操作预留缓存或索引优化空间。

### 9.5 可维护性

- 前后端模块职责清晰。
- 业务规则如经验、等级、徽章、推荐权重应集中管理。
- AI 提示词、评分规则、RAG 检索策略应可配置或易于调整。

## 10. AI Agent 技术设计方向

### 10.1 RAG 知识流程

建议流程：

1. 题库和学习资料入库。
2. 对题目、答案、解析、知识点进行切分和向量化。
3. 用户请求刷题时，结合用户画像和薄弱点生成检索查询。
4. 从向量数据库中召回相关题目和知识片段。
5. Agent 基于召回内容生成题目或选择题目。
6. 用户答题后，Agent 基于标准答案和知识片段进行评分。
7. 系统沉淀答题记录和学习画像。

### 10.2 LangGraph 工作流建议

刷题 Agent 可拆分为多个节点：

- 用户画像分析节点
- 题目候选召回节点
- 题目推荐决策节点
- 出题节点
- 答案评审节点
- 学习建议生成节点
- 经验和徽章计算节点
- 记录保存节点

通过图工作流管理各节点之间的状态流转，提升复杂 Agent 流程的可维护性。

### 10.3 LlamaIndex 使用方向

LlamaIndex 可用于：

- 构建题库和学习资料索引。
- 管理文档切分、元数据和检索逻辑。
- 辅助构建知识库问答或题目解析能力。

### 10.4 向量数据库使用方向

向量数据库用于存储：

- 学习资料向量。
- 题目内容向量。
- 标准答案和解析向量。
- 知识点说明向量。

选型时需考虑：

- 本地开发便利性。
- 数据量增长后的性能。
- 与当前技术栈的集成成本。
- 是否支持元数据过滤。

## 12. 验收标准

### 12.1 页面验收

- 用户打开网站后默认进入“AI学习路线与资料”页面。
- 左侧菜单展示完整 4 个菜单。
- 点击各菜单后页面能够正常切换。
- “面试题大全”和“刷题Agent”在未登录时会引导登录。
- 右上角展示用户相关入口。

### 12.2 权限验收

- 游客可以查看首页和建议评论内容。
- 游客不能发布建议和评论。
- 游客不能访问面试题大全和刷题 Agent。
- 登录用户可以访问全部菜单。
- 登录用户可以发布建议和评论。

### 12.3 刷题 Agent 需求验收

- 系统需求文档中明确刷题 Agent 的核心流程。
- 明确默认题库和个性化题库的关系。
- 明确 AI 出题、AI 审题、评分建议的输出结构。
- 明确答题记录如何影响后续出题权重。
- 明确经验、等级、段位、徽章的激励规则方向。
