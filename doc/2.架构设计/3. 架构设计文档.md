# AI 学习平台架构设计文档

版本：v1.0  
日期：2026-05-13  
依据文档：`doc/需求文档/2. 需求文档.md`

## 1. 架构目标

本项目首期以 MVP 快速落地为目标，采用“前端一个项目、后端一个项目、AI 一个项目”的三项目架构，暂不拆分复杂微服务。

核心目标：

- 支撑 AI 学习路线、建议评论、面试题大全占位、刷题 Agent 原型等 MVP 功能。
- 建立用户、权限、题库、答题记录、成长体系等核心业务模型。
- 为后续 RAG、LangGraph Agent、个性化题库、AI 审题评分预留清晰扩展边界。
- 技术栈使用 2026 年当前稳定版本，优先选择社区活跃、生态成熟、可维护性好的方案。

## 2. 总体架构

```text
┌──────────────────────────┐
│ frontend                 │
│ Vue + Vite + TypeScript  │
└─────────────┬────────────┘
              │ HTTPS / REST API
              ▼
┌──────────────────────────┐
│ backend                  │
│ Java + Spring Boot       │
│ 用户/权限/业务数据/API   │
└───────┬──────────┬───────┘
        │          │ HTTP / 内部 API
        │          ▼
        │  ┌──────────────────────┐
        │  │ ai-service            │
        │  │ Python + FastAPI      │
        │  │ RAG / Agent / 评分    │
        │  └──────────┬───────────┘
        │             │
        ▼             ▼
┌──────────────┐  ┌──────────────┐
│ MySQL        │  │ Qdrant       │
│ 业务主库      │  │ 向量数据库    │
└──────────────┘  └──────────────┘
        │
        ▼
┌──────────────┐
│ Redis        │
│ 缓存/限流/会话│
└──────────────┘
```

### 2.1 架构原则

- 前端只负责页面、交互、路由守卫和 API 调用，不直接访问数据库或 AI 模型。
- 后端作为唯一业务入口，负责认证授权、业务规则、数据一致性和对外 API。
- AI 服务独立部署，负责 RAG 检索、Agent 编排、出题、评分、学习建议生成等 AI 密集逻辑。
- 后端调用 AI 服务，AI 服务不直接操作用户核心业务表；需要保存结果时由后端落库。
- MySQL 保存业务主数据，Qdrant 保存向量索引，Redis 用于缓存、限流和热点数据。

| 构建工具 | Vite | 8.0.12 | 快速开发和构建 |

主要模块：

- `layout`：左侧菜单、顶部用户区、主内容区域。
- `routes`：路由配置、游客/登录用户访问控制。
- `pages/learning-roadmap`：AI 学习路线与资料页面。
- `pages/suggestions-comments`：建议与评论页面。

### 3.2 backend

定位：核心业务后端，统一暴露 REST API。

推荐技术栈：

| 类型 | 技术 | 版本建议 | 说明 |
| --- | --- | --- | --- |
| 语言 | Java | 25 LTS | 当前长期支持版本，适合长期维护 |
| 框架 | Spring Boot | 4.0.6 | 当前稳定版，作为后端主框架 |
| 安全 | Spring Security | 7.0.5 | 登录认证、JWT、权限控制 |
| 数据访问 | Spring Data JPA | 随 Spring Boot 4.0.6 管理 | 业务数据 CRUD |
| 数据库驱动 | MySQL Connector/J | 使用兼容 Spring Boot 4 的稳定版 | 连接 MySQL |
| 数据库迁移 | Flyway | 12.6.1 | 管理表结构版本 |
| 工具库 | Lombok | 1.18.46 | 简化 DTO、实体、构造代码 |
| API 文档 | springdoc-openapi | 使用兼容 Spring Boot 4 的稳定版 | 生成 OpenAPI 文档 |
| 测试 | JUnit 6 / Spring Boot Test | 随 Spring Boot 4 管理 | 单元测试和集成测试 |

主要模块：

- `auth`：注册、登录、JWT 签发、刷新、退出。
- `user`：用户资料、头像、个人中心数据。
- `permission`：游客与登录用户访问控制。
- `learning`：学习路线资料读取、页面数据 API。
- `suggestion`：建议提交、列表查询、状态预留。
- `comment`：评论发布、列表查询、回复和点赞预留。
- `question`：默认题库、个人题库、题目分类和标签。
- `answer`：答题记录、评分结果、耗时、知识点关联。
- `growth`：经验、等级、段位、徽章计算。
- `agent`：刷题 Agent 会话、调用 AI 服务、结果落库。
- `common`：统一响应、异常处理、分页、审计字段。

## 6. 业务能力设计

### 6.1 用户与权限

认证方式：

- 前端登录后获得 JWT access token。
- 后端使用 Spring Security 校验 token。
- 游客接口允许匿名访问，受限接口要求登录。

权限规则：

| 页面/操作 | 游客 | 登录用户 |
| --- | --- | --- |
| AI 学习路线与资料 | 可访问 | 可访问 |
| 建议与评论列表 | 可查看 | 可查看 |
| 发布建议 | 引导登录 | 可发布 |
| 发布评论 | 引导登录 | 可发布 |
| 面试题大全 | 引导登录 | 可访问 |
| 刷题 Agent | 引导登录 | 可访问 |
| 个人中心 | 引导登录 | 可访问 |

### 6.2 学习路线与资料

MVP 阶段资料来源为：

```text
doc/学习路线页面
```

落地方式：

- 前端可先将 Markdown 转换为静态页面内容。
- 后端预留学习资料 API，后续迁移到数据库或内容管理后台。
- 学习资料后续进入 AI 知识库时，由 ai-service 对 Markdown 内容切分并写入 Qdrant。

### 6.3 建议与评论

建议模块：

- 游客可查看建议列表。
- 登录用户可提交建议。
- 建议状态预留：`PENDING`、`ACCEPTED`、`REJECTED`、`DONE`。

评论模块：

- 游客可查看评论列表。
- 登录用户可发表评论。
- 回复、点赞、审核能力先保留字段和扩展点。

### 6.4 面试题大全

MVP 阶段：

- 登录后可访问占位页面。
- 后端可先提供分类和题目列表空接口，便于前端对接。

后续扩展：

- 分类、标签、难度筛选。
- 收藏、解析、AI 生成参考答案。
- 管理后台导入和维护面试题。

### 6.5 刷题 Agent

MVP 阶段先实现入口页面和基础原型流程：

1. 用户进入刷题 Agent。
2. 后端校验登录态。
3. 后端根据题库和答题记录生成推荐请求。
4. 后端调用 ai-service 获取题目或评分。
5. 后端保存答题记录和 AI 反馈。
6. 后端计算经验、等级、徽章。
7. 前端展示评分、参考答案、改进建议和成长反馈。

AI 服务返回结构建议：

```json
{
  "score": 86,
  "isCorrect": true,
  "hitPoints": ["理解了 RAG 的检索增强思想"],
  "missingPoints": ["没有说明向量检索和重排序"],
  "problems": ["答案对数据入库流程描述较弱"],
  "referenceAnswer": "标准参考答案文本",
  "improvementAdvice": "建议补充 Embedding、向量库、召回、重排序、生成之间的关系",
  "reviewKnowledgePoints": ["RAG", "Embedding", "Vector Search"]
}
```

## 7. AI Agent 工作流设计

LangGraph 节点建议：

| 节点 | 输入 | 输出 | 职责 |
| --- | --- | --- | --- |
| 用户画像分析节点 | 用户 ID、历史记录 | 薄弱知识点、熟练度 | 识别学习短板 |
| 候选题召回节点 | 知识点、难度、标签 | 候选题列表 | 从业务题库和向量库召回题目 |
| 推荐决策节点 | 候选题、历史得分 | 推荐题目 | 根据权重规则选择题目 |
| 出题节点 | 推荐题目或知识片段 | 最终题目 | 选择已有题或生成新题 |
| 答案评审节点 | 题目、标准答案、用户答案 | 评分结果 | 输出结构化评审 |
| 学习建议节点 | 评分结果、薄弱点 | 复习建议 | 给出下一步学习建议 |
| 结果回传节点 | 评分和建议 | 后端可落库结果 | 返回给 backend |

推荐权重初始公式：

```text
题目权重 = 基础权重 + 未刷加权 + 低分加权 + 薄弱知识点加权 + 个人题库加权 - 高频重复惩罚
```

MVP 可先在后端实现简单规则，后续再将推荐策略部分迁移到 ai-service 或独立推荐模块。

## 8. 数据库设计概览

核心表：

| 表 | 说明 |
| --- | --- |
| `users` | 用户账号、昵称、头像、经验、等级、段位 |
| `suggestions` | 用户建议 |
| `comments` | 评论和回复 |
| `questions` | 默认题库和个人题库 |
| `answer_records` | 答题记录和 AI 评分 |
| `badges` | 徽章定义 |
| `user_badges` | 用户已获得徽章 |
| `knowledge_points` | 知识点 |
| `question_knowledge_points` | 题目和知识点关系 |
| `agent_sessions` | 刷题 Agent 会话 |

关键设计：

- `questions.owner_user_id` 为空表示平台默认题库，不为空表示用户个人题库。
- `questions.source_type` 区分 `DEFAULT`、`USER_UPLOAD`、`AI_GENERATED`。
- `answer_records.ai_feedback` 可使用 MySQL `JSON` 类型保存结构化 AI 反馈。
- `badges.rule_code` 对应后端成长规则，便于后续扩展。
- 用户私有数据查询必须带 `user_id` 条件，避免越权访问。

### 9.2 后端调用 AI 服务

AI 服务仅作为内部服务，不直接暴露给浏览器。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/internal/agent/question/recommend` | 推荐或生成题目 |
| `POST` | `/internal/agent/answer/grade` | 答案评分 |
| `POST` | `/internal/rag/index/documents` | 学习资料和题库入库 |
| `POST` | `/internal/rag/search` | 检索知识片段 |

内部调用要求：

- 使用内网地址或服务名访问。
- 增加内部服务 token，避免 AI 服务被外部直接调用。
- AI 服务返回结构化 JSON，后端负责校验和兜底。

## 10. 安全设计

- 密码使用 BCrypt 或 Argon2 哈希存储，不保存明文。
- JWT 设置合理过期时间，刷新 token 可后续实现。
- 所有用户私有资源必须校验 `user_id`。
- 建议和评论预留敏感词、审核状态、举报能力。
- AI 输出必须标记为辅助建议，不作为绝对标准答案。
- AI 服务需要设置超时、重试、限流和失败兜底。
- 文件上传仅允许白名单格式，并限制大小。

## 11. 性能与可维护性设计

性能：

- 学习路线页面优先静态化或缓存。
- 建议、评论、题目列表使用分页。
- 答题记录按 `user_id`、`question_id`、`created_at` 建索引。
- Qdrant 检索使用知识点、难度、题型等 metadata 过滤。
- Redis 缓存热点学习资料、用户概要、验证码和限流计数。

可维护性：

- 业务规则集中管理，例如经验、等级、段位、徽章、推荐权重。
- Prompt 模板独立存放并维护版本号。
- AI 响应使用 JSON Schema 或 Pydantic 模型约束。
- 数据库结构全部通过 Flyway migration 管理。
- 后端统一异常、统一响应、统一日志 traceId。

## 13. 阶段落地计划

### 13.1 第一阶段：MVP 页面与权限

- 创建 frontend、backend 基础项目。
- 实现左侧菜单、首页、建议评论、面试题占位、刷题 Agent 占位。

### 13.2 第二阶段：题库与答题基础能力

- 建立题库、知识点、答题记录表。
- 支持默认题库录入。
- 支持用户提交答案。
- 支持基于标准答案的基础评分展示。

### 13.3 第三阶段：AI 服务与 RAG

- 创建 ai-service。
- 接入 Qdrant。
- 将学习路线资料和题库内容向量化入库。
- 实现题目推荐、AI 出题、AI 审题评分接口。

### 13.4 第四阶段：成长体系

- 实现经验计算。
- 实现等级和段位规则。
- 实现徽章定义和自动发放。

### 13.5 第五阶段：内容和社区增强

- 完善面试题大全。
- 增加评论回复、点赞、收藏。
- 增加后台管理能力。
- 增加学习统计、薄弱点分析和复习推荐。

## 14. 技术选型结论

最终建议：

- 后端项目：`backend`，使用 Java 25 LTS + Spring Boot 4.0.6 + Spring Security 7.0.5 + MySQL 8.4 LTS。
- 前端项目：`frontend`，使用 Node.js 24 LTS + Vue 3.5.34 + Vite 8.0.12 + TypeScript 6.0.3 + Vue Router 5.0.7 + Pinia 3.0.4 + Element Plus 2.14.0。
- AI 项目：`ai-service`，使用 Python 3.14.x + FastAPI 0.136.1 + LangGraph 1.2.0 + LangChain 1.3.0 + LlamaIndex 0.14.21 + Qdrant 1.18.0。
- 基础设施：MySQL 8.4 LTS 作为业务主库，Redis 8.2.5 作为缓存，Qdrant 1.18.0 作为向量数据库。

该架构在 MVP 阶段保持项目数量少、边界清晰、开发成本可控，同时为后续智能刷题 Agent、RAG 知识库、成长体系和社区功能预留扩展空间。
