# AI应用开发学习平台接口规范

版本：v1.1  
日期：2026-05-14  
适用范围：前端调用后端 API、后端调用 AI 服务内部 API

## 1. 规范目标

本文档统一接口路径、响应结构、错误码、分页、认证、时间格式和内部服务调用方式。实现接口前应先确认本文档，避免前端、后端和 AI 服务各自定义一套规则。

## 2. API 路径

### 2.1 对外 API

前端调用后端统一使用：

```text
/api/v1
```

示例：

```text
GET /api/v1/users/me
POST /api/v1/auth/login
GET /api/v1/questions
```

要求：

- 路径使用小写字母，多个单词使用中划线。
- 资源集合使用复数名词，例如 `/questions`、`/comments`。
- 当前登录用户资源使用 `/me`，例如 `/users/me`。
- 路径不暴露数据库表名和内部实现细节。
- 重大不兼容变更通过 `/api/v2` 演进。

### 2.2 内部 API

后端调用 AI 服务统一使用：

```text
/internal/v1
```

示例：

```text
POST /internal/v1/agent/question/recommend
POST /internal/v1/agent/answer/grade
```

要求：

- `/internal/**` 不对浏览器开放。
- 内部接口校验 `AI_SERVICE_TOKEN` 或等价内部鉴权机制。
- 内部接口也返回统一结构，便于后端做解析、兜底和日志追踪。
- 健康检查接口可使用 `/health`，不强制放在 `/internal/v1` 下。

## 3. HTTP 方法

| 方法 | 使用场景 |
| --- | --- |
| `GET` | 查询资源，不产生业务副作用 |
| `POST` | 创建资源、提交动作、复杂查询 |
| `PUT` | 全量更新资源 |
| `PATCH` | 局部更新资源 |
| `DELETE` | 删除资源，优先逻辑删除 |

## 4. 统一响应

成功响应：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {},
  "traceId": "trace-id占位符"
}
```

失败响应：

```json
{
  "code": "AUTH_UNAUTHORIZED",
  "message": "请先登录后再访问该功能",
  "data": null,
  "traceId": "trace-id占位符"
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `code` | 业务错误码，成功固定为 `SUCCESS` |
| `message` | 面向前端展示或排查问题的中文提示 |
| `data` | 响应数据，失败时可为 `null` |
| `traceId` | 请求链路标识 |

## 5. 分页

请求参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `pageNo` | number | `1` | 页码，从 1 开始 |
| `pageSize` | number | `10` | 每页数量，最大建议 100 |

分页响应：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "records": [],
    "pageNo": 1,
    "pageSize": 10,
    "total": 0,
    "totalPages": 0,
    "hasNext": false
  },
  "traceId": "trace-id占位符"
}
```

要求：

- 列表接口默认支持分页。
- 确实不分页的接口，需要在接口说明中写明原因。
- `pageSize` 超过最大值时，后端应自动限制或返回 `PARAM_INVALID`。

## 6. 错误码

错误码使用大写下划线，按业务域归类。

| 错误码 | HTTP 状态 | 说明 |
| --- | --- | --- |
| `SUCCESS` | 200 | 成功 |
| `PARAM_INVALID` | 400 | 参数不合法 |
| `AUTH_UNAUTHORIZED` | 401 | 未登录或 token 无效 |
| `AUTH_FORBIDDEN` | 403 | 无权限访问 |
| `RESOURCE_NOT_FOUND` | 404 | 资源不存在 |
| `RESOURCE_CONFLICT` | 409 | 资源冲突或重复提交 |
| `RATE_LIMITED` | 429 | 请求过于频繁 |
| `AI_SERVICE_TIMEOUT` | 502 | AI 服务调用超时 |
| `AI_SERVICE_UNAVAILABLE` | 503 | AI 服务不可用 |
| `SYSTEM_ERROR` | 500 | 系统异常 |

要求：

- Controller 不硬编码错误文案。
- 错误码、默认文案和 HTTP 状态集中管理。
- 前端根据错误码处理登录引导、权限提示、参数错误、重试提示。
- 返回给前端的信息要克制，不暴露堆栈、SQL、Token、连接串等细节。

## 7. 认证与鉴权

前端访问登录态接口：

```text
Authorization: Bearer <access_token占位符>
```

后端调用 AI 服务：

```text
X-Internal-Token: <AI_SERVICE_TOKEN占位符>
```

要求：

- Token 只通过 HTTPS 或本地开发环境传输。
- Token 不写入 URL 查询参数。
- Token 不打印到日志。
- 用户只能访问自己的私有资源，后端必须校验资源归属。

## 8. 时间、ID 和字段命名

时间：

- 对外时间字段使用 ISO-8601 字符串。
- 常用字段名：`createdAt`、`updatedAt`、`submittedAt`。
- 后端内部明确时区策略；对外响应建议包含时区信息。

ID：

- 接口中的 ID 使用字符串，避免前端数字精度问题。
- 字段名使用 `id`、`userId`、`questionId` 等小驼峰。

字段：

- JSON 字段使用小驼峰，例如 `pageNo`、`isCorrect`、`referenceAnswer`。
- 数据库字段使用小写下划线，例如 `created_at`。

## 9. 幂等和重复提交

以下场景需要考虑幂等或重复提交保护：

- 注册。
- 发布建议。
- 发布评论。
- 提交答案。
- RAG 入库任务提交。
- 文件上传。

可选方案：

- 前端按钮 loading 防重复点击。
- 后端使用业务唯一键。
- 后端使用 Redis 短期幂等键。
- 重要动作支持 `Idempotency-Key` 请求头。

| `POST` | `/api/v1/suggestions` | 登录用户 | 提交建议 |
| `GET` | `/api/v1/comments` | 游客 | 评论列表 |
| `POST` | `/api/v1/comments` | 登录用户 | 发布评论 |

## 12. 接口示例

### 12.1 登录

请求：

```json
{
  "username": "用户名占位符",
  "password": "密码占位符"
}
```

响应：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "accessToken": "access_token占位符",
    "tokenType": "Bearer",
    "expiresIn": 7200
  },
  "traceId": "trace-id占位符"
}
```

### 12.2 开始刷题

请求：

```json
{
  "difficulty": "MEDIUM",
  "questionType": "SHORT_ANSWER",
  "knowledgePoints": ["RAG", "Embedding"]
}
```

响应：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "sessionId": "会话ID占位符",
    "questionId": "题目ID占位符",
    "title": "题目标题占位符",
    "content": "题目内容占位符",
    "questionType": "SHORT_ANSWER",
    "difficulty": "MEDIUM",
    "knowledgePoints": ["RAG", "Embedding"]
  },
  "traceId": "trace-id占位符"
}
```

### 12.3 提交答案

请求：

```json
{
  "sessionId": "会话ID占位符",
  "questionId": "题目ID占位符",
  "userAnswer": "用户答案占位符",
  "durationSeconds": 180
}
```

响应：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "answerRecordId": "答题记录ID占位符",
    "score": 86,
    "isCorrect": true,
    "hitPoints": ["理解了 RAG 的检索增强思想"],
    "missingPoints": ["没有说明向量检索和重排序"],
    "problems": ["答案对数据入库流程描述较弱"],
    "referenceAnswer": "标准参考答案占位符",
    "improvementAdvice": "建议补充 Embedding、向量库、召回、重排序、生成之间的关系",
    "reviewKnowledgePoints": ["RAG", "Embedding", "Vector Search"],
    "growth": {
      "earnedExperience": 12,
      "currentExperience": 188,
      "level": "Lv2",
      "rank": "青铜"
    }
  },
  "traceId": "trace-id占位符"
}
```

### 12.4 AI 评分内部接口

请求：

```json
{
  "userId": "用户ID占位符",
  "questionId": "题目ID占位符",
  "questionContent": "题目内容占位符",
  "standardAnswer": "标准答案占位符",
  "userAnswer": "用户答案占位符",
  "knowledgePoints": ["RAG", "Embedding"],
  "contextSnippets": ["检索到的知识片段占位符"]
}
```

响应：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "score": 86,
    "isCorrect": true,
    "hitPoints": ["理解了 RAG 的检索增强思想"],
    "missingPoints": ["没有说明向量检索和重排序"],
    "problems": ["答案对数据入库流程描述较弱"],
    "referenceAnswer": "标准参考答案占位符",
    "improvementAdvice": "建议补充 Embedding、向量库、召回、重排序、生成之间的关系",
    "reviewKnowledgePoints": ["RAG", "Embedding", "Vector Search"]
  },
  "traceId": "trace-id占位符"
}
```

校验要求：

- 后端校验 `score` 是否在 0 - 100。
- 数组字段限制长度，避免模型返回过长内容。
- 文本字段限制最大长度。
- 必填字段缺失时返回兜底评分结果或 `AI_SERVICE_UNAVAILABLE`。
- AI 原始异常不直接返回前端。
