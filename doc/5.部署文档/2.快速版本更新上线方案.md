# 快速版本更新上线方案

版本：v1.2  
更新日期：2026-05-25  
适用项目：`ai-learn-web`、`ai-learn-backend`、`ai-service`  
服务器公网 IP：`159.75.111.145`  
适用场景：已完成首次部署后的日常版本更新上线  

## 1. 使用方式

本方案按执行环境分成 4 类命令块，不要把整篇文档混在一起执行：

1. 本地 PowerShell 执行“本地构建和打包”。
2. 本地 PowerShell 执行“上传发布包”。
3. 可选：服务器 SSH 执行“配置文件更新”。
4. 服务器 SSH 执行“服务器快速部署”和“上线后验收”。

每个命令块都按可重复执行设计。执行一半失败后，可以修复问题并重新执行同一个命令块：

1. 本地构建每次都会生成新的发布目录和发布包，不覆盖旧发布包。
2. 上传发布包会覆盖服务器 `/tmp` 下同名包，并写入最新发布包记录。
3. 服务器部署只清理 `/tmp/ai-learn-*` 临时解包目录，不清理生产目录以外的路径。
4. 生产文件替换使用 `mkdir -p`、`rsync --delete`、`chown`、`chmod`、`systemctl restart`，重复执行结果一致。
5. 可选备份开启后，同一个发布版本重复执行不会覆盖第一次生成的备份，避免把已更新后的文件误当成旧版本备份。

> 可选备份说明：备份不参与上线主流程。跳过备份不会影响本次上线，只会影响回滚流程；没有备份时，需要重新检出上一版本并重新发布，或通过补丁修复。

## 2. 本地构建和打包

在 Windows 11 的 PowerShell 中执行，执行前先 `cd` 到项目仓库根目录。命令只使用相对路径，换电脑后只需要进入仓库根目录。

```powershell
$ErrorActionPreference = "Stop"
Set-StrictMode -Version Latest

$CurrentStep = "初始化"
$ReleaseId = Get-Date -Format "yyyyMMddHHmmss"
$ReleaseName = "ai-learn-$ReleaseId"
$LogDir = ".\release\logs"
$LogPath = Join-Path $LogDir "build-$ReleaseId.log"
$TranscriptStarted = $false

function Write-Step {
    param([string]$Message)
    $script:CurrentStep = $Message
    Write-Host "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] $Message"
}

function Assert-LastExitCode {
    param([string]$Message)
    if ($LASTEXITCODE -ne 0) {
        throw "$Message 失败，退出码：$LASTEXITCODE"
    }
}

function Stop-AiLearnWebDevProcess {
    param([string]$WebRoot)

    # 只匹配当前项目前端目录下的 Vite、Rollup、vue-tsc 进程，避免误杀其他 Node 任务。
    $escapedWebRoot = [regex]::Escape($WebRoot)
    $webNodeProcesses = Get-CimInstance Win32_Process -Filter "name = 'node.exe'" |
        Where-Object {
            $_.CommandLine -and
            $_.CommandLine -match $escapedWebRoot -and
            $_.CommandLine -match "(vite|rollup|vue-tsc)"
        }

    # Windows 下 npm ci 会删除 node_modules，被开发服务占用时会出现 EPERM unlink。
    foreach ($process in $webNodeProcesses) {
        Write-Host "停止前端开发进程：PID=$($process.ProcessId)"
        Stop-Process -Id $process.ProcessId -Force -ErrorAction Stop
    }
}

New-Item -ItemType Directory -Force $LogDir | Out-Null
Start-Transcript -Path $LogPath -Append | Out-Null
$TranscriptStarted = $true

try {
    Write-Step "检查当前目录是否为项目根目录"
    if (-not (Test-Path ".\ai-learn-backend\pom.xml")) { throw "未找到 ai-learn-backend\pom.xml，请先 cd 到项目根目录" }
    if (-not (Test-Path ".\ai-learn-web\package.json")) { throw "未找到 ai-learn-web\package.json，请先 cd 到项目根目录" }
    if (-not (Test-Path ".\ai-service")) { throw "未找到 ai-service 目录，请先 cd 到项目根目录" }

    Write-Step "查看 Git 状态，确认本次发布代码"
    git status
    Assert-LastExitCode "git status"

    Write-Step "拉取远程最新代码"
    git pull
    Assert-LastExitCode "git pull"

    Write-Step "创建本地发布目录 .\release\$ReleaseName"
    New-Item -ItemType Directory -Force ".\release\$ReleaseName" | Out-Null

    Write-Step "构建 Java 后端 JAR"
    mvn -f .\ai-learn-backend\pom.xml "-DskipTests" clean package
    Assert-LastExitCode "Java 后端构建"

    Write-Step "停止本项目前端开发进程，避免 Windows 锁定 node_modules"
    Stop-AiLearnWebDevProcess -WebRoot (Resolve-Path ".\ai-learn-web").Path

    Write-Step "安装前端依赖"
    npm --prefix .\ai-learn-web ci
    Assert-LastExitCode "前端依赖安装"

    Write-Step "构建前端 dist"
    $env:VITE_API_BASE_URL = "/api/v1"
    npm --prefix .\ai-learn-web run build
    Assert-LastExitCode "前端构建"

    Write-Step "复制后端 JAR 到发布目录"
    Copy-Item ".\ai-learn-backend\target\ai-learn-backend-0.0.1-SNAPSHOT.jar" ".\release\$ReleaseName\ai-learn-backend.jar" -Force

    Write-Step "复制前端 dist 到发布目录"
    New-Item -ItemType Directory -Force ".\release\$ReleaseName\ai-learn-web" | Out-Null
    Copy-Item ".\ai-learn-web\dist\*" ".\release\$ReleaseName\ai-learn-web" -Recurse -Force

    Write-Step "复制 AI 服务源码到发布目录，排除 .venv、__pycache__、.env"
    robocopy ".\ai-service" ".\release\$ReleaseName\ai-service" /E /XD ".venv" "__pycache__" /XF ".env"
    if ($LASTEXITCODE -gt 7) { throw "AI 服务源码复制失败，robocopy 退出码：$LASTEXITCODE" }
    $global:LASTEXITCODE = 0

    Write-Step "压缩发布包"
    tar -czf ".\release\$ReleaseName.tar.gz" -C ".\release" "$ReleaseName"
    Assert-LastExitCode "发布包压缩"

    Write-Step "校验发布包是否生成"
    if (-not (Test-Path ".\release\$ReleaseName.tar.gz")) { throw "发布包不存在：.\release\$ReleaseName.tar.gz" }

    Write-Host "发布包已生成：.\release\$ReleaseName.tar.gz"
    Write-Host "构建日志：$LogPath"
} catch {
    Write-Error "本地构建失败，当前步骤：$CurrentStep"
    Write-Error "请查看日志：$LogPath"
    throw
} finally {
    if (Test-Path Env:\VITE_API_BASE_URL) { Remove-Item Env:\VITE_API_BASE_URL }
    if ($TranscriptStarted) { Stop-Transcript | Out-Null }
}
```

## 3. 上传发布包

仍在本地项目根目录的 PowerShell 中执行。服务器地址已固定为 `root@159.75.111.145`。

```powershell
$ErrorActionPreference = "Stop"
Set-StrictMode -Version Latest

$CurrentStep = "初始化"
$Server = "root@159.75.111.145"
$Timestamp = Get-Date -Format "yyyyMMddHHmmss"
$LogDir = ".\release\logs"
$LogPath = Join-Path $LogDir "upload-$Timestamp.log"
$TranscriptStarted = $false

function Write-Step {
    param([string]$Message)
    $script:CurrentStep = $Message
    Write-Host "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] $Message"
}

function Assert-LastExitCode {
    param([string]$Message)
    if ($LASTEXITCODE -ne 0) {
        throw "$Message 失败，退出码：$LASTEXITCODE"
    }
}

New-Item -ItemType Directory -Force $LogDir | Out-Null
Start-Transcript -Path $LogPath -Append | Out-Null
$TranscriptStarted = $true

try {
    Write-Step "选择 release 目录下最新发布包"
    $Package = Get-ChildItem ".\release\ai-learn-*.tar.gz" | Sort-Object LastWriteTime -Descending | Select-Object -First 1
    if ($null -eq $Package) { throw "未找到发布包，请先执行本地构建和打包" }

    Write-Step "上传发布包到服务器 /tmp/$($Package.Name)"
    scp $Package.FullName "${Server}:/tmp/$($Package.Name)"
    Assert-LastExitCode "上传发布包"

    Write-Step "记录服务器最新发布包文件名"
    ssh $Server "printf '%s\n' '$($Package.Name)' > /tmp/ai-learn-latest-package.txt && ls -lh '/tmp/$($Package.Name)'"
    Assert-LastExitCode "记录最新发布包"

    Write-Host "已上传到服务器：/tmp/$($Package.Name)"
    Write-Host "上传日志：$LogPath"
} catch {
    Write-Error "上传失败，当前步骤：$CurrentStep"
    Write-Error "请查看日志：$LogPath"
    throw
} finally {
    if ($TranscriptStarted) { Stop-Transcript | Out-Null }
}
```

## 4. 可选配置文件更新

只有后端数据库、JWT、AI 服务地址、AI 服务 Token、AI 模型配置等运行时配置发生变化时，才需要执行本节。

最方便的流程：

1. 如果本次“代码 + 配置”一起发布，先执行本节配置更新，再执行第 5 节服务器快速部署；第 5 节会统一重启服务。
2. 如果本次只改配置，不发代码，执行本节后直接按本节末尾命令重启对应服务。
3. 不要把真实 `.env`、Token、密码放进本地发布包；发布包会继续排除 `.env`。
4. 当前服务器实际使用 systemd 环境文件：`/etc/ai-learn/backend.env` 和 `/etc/ai-learn/ai-service.env`。


## 5. 服务器快速部署

登录服务器后执行。服务器目录是固定部署目录，因此继续使用绝对路径。

```bash
set -Eeuo pipefail

CURRENT_STEP="初始化"

log() {
  echo "[$(date '+%F %T')] $*"
}

fail() {
  echo "[ERROR] $*" >&2
  exit 1
}

step() {
  CURRENT_STEP="$1"
  log "${CURRENT_STEP}"
}

trap 'CODE=$?; echo "[ERROR] 部署失败，步骤：${CURRENT_STEP}，退出码：${CODE}，日志：${DEPLOY_LOG:-未创建}" >&2; exit ${CODE}' ERR

# 可选备份开关：0 表示跳过备份，1 表示执行备份。
ENABLE_BACKUP=0

# AI 服务依赖开关：requirements.txt 有变化时改为 1。
INSTALL_AI_DEPS=1

step "读取最新发布包文件名"
PACKAGE_NAME="${PACKAGE_NAME:-}"
if [ -z "${PACKAGE_NAME}" ] && [ -f /tmp/ai-learn-latest-package.txt ]; then
  PACKAGE_NAME="$(head -n 1 /tmp/ai-learn-latest-package.txt)"
fi

if [ -z "${PACKAGE_NAME}" ]; then
  fail "未找到发布包文件名，请确认第 3 节上传成功，或手工 export PACKAGE_NAME=ai-learn-版本号.tar.gz"
fi

case "${PACKAGE_NAME}" in
  ai-learn-*.tar.gz) ;;
  *) fail "发布包文件名不合法：${PACKAGE_NAME}" ;;
esac

RELEASE_ID="${PACKAGE_NAME%.tar.gz}"
PACKAGE_PATH="/tmp/${PACKAGE_NAME}"
WORK_DIR="/tmp/${RELEASE_ID}"
RELEASE_DIR="/opt/ai-learn/releases/${RELEASE_ID}"
DEPLOY_LOG="${RELEASE_DIR}/deploy.log"

step "创建发布记录目录"
mkdir -p "${RELEASE_DIR}"
exec > >(tee -a "${DEPLOY_LOG}") 2>&1
log "部署日志：${DEPLOY_LOG}"

step "校验发布包存在"
test -f "${PACKAGE_PATH}"
ls -lh "${PACKAGE_PATH}"

step "清理服务器临时解包目录"
case "${WORK_DIR}" in
  /tmp/ai-learn-*) rm -rf "${WORK_DIR}" ;;
  *) fail "临时目录不在允许范围内：${WORK_DIR}" ;;
esac

step "解压发布包"
tar -xzf "${PACKAGE_PATH}" -C /tmp

step "校验发布包内容"
test -f "${WORK_DIR}/ai-learn-backend.jar"
test -f "${WORK_DIR}/ai-learn-web/index.html"
test -d "${WORK_DIR}/ai-service"

step "可选备份当前线上版本"
if [ "${ENABLE_BACKUP}" = "1" ]; then
  mkdir -p "${RELEASE_DIR}/backup"

  if [ -f /opt/ai-learn/backend/ai-learn-backend.jar ] && [ ! -f "${RELEASE_DIR}/backup/ai-learn-backend.jar" ]; then
    cp /opt/ai-learn/backend/ai-learn-backend.jar "${RELEASE_DIR}/backup/ai-learn-backend.jar"
  fi

  if [ -d /www/wwwroot/ai-learn-web ] && [ ! -f "${RELEASE_DIR}/backup/ai-learn-web.tar.gz" ]; then
    tar -czf "${RELEASE_DIR}/backup/ai-learn-web.tar.gz" -C /www/wwwroot ai-learn-web
  fi

  if [ -d /opt/ai-learn/ai-service ] && [ ! -f "${RELEASE_DIR}/backup/ai-service.tar.gz" ]; then
    tar --exclude='.venv' --exclude='__pycache__' -czf "${RELEASE_DIR}/backup/ai-service.tar.gz" -C /opt/ai-learn ai-service
  fi
else
  log "已跳过备份：不影响上线主流程，只影响按备份回滚能力"
fi

step "停止应用服务，避免运行中覆盖 JAR 或源码"
systemctl stop ai-learn-backend
systemctl stop ai-learn-ai

step "替换后端 JAR"
mkdir -p /opt/ai-learn/backend
cp "${WORK_DIR}/ai-learn-backend.jar" /opt/ai-learn/backend/ai-learn-backend.jar
chown ai-learn:ai-learn /opt/ai-learn/backend/ai-learn-backend.jar
chmod 750 /opt/ai-learn/backend
chmod 640 /opt/ai-learn/backend/ai-learn-backend.jar

step "替换前端静态资源"
mkdir -p /www/wwwroot/ai-learn-web
rsync -av --delete "${WORK_DIR}/ai-learn-web/" /www/wwwroot/ai-learn-web/
chown -R www:www /www/wwwroot/ai-learn-web
find /www/wwwroot/ai-learn-web -type d -exec chmod 755 {} \;
find /www/wwwroot/ai-learn-web -type f -exec chmod 644 {} \;

step "替换 AI 服务源码，保留服务器 .venv 和 .env"
mkdir -p /opt/ai-learn/ai-service
rsync -av --delete --exclude '.venv' --exclude '__pycache__' --exclude '.env' "${WORK_DIR}/ai-service/" /opt/ai-learn/ai-service/
chown -R ai-learn:ai-learn /opt/ai-learn/ai-service

step "可选安装 AI 服务依赖"
if [ "${INSTALL_AI_DEPS}" = "1" ]; then
  cd /opt/ai-learn/ai-service
  sudo -u ai-learn python3.11 -m venv .venv
  sudo -u ai-learn /opt/ai-learn/ai-service/.venv/bin/pip install --upgrade pip -i https://mirrors.cloud.tencent.com/pypi/simple --trusted-host mirrors.cloud.tencent.com
  sudo -u ai-learn /opt/ai-learn/ai-service/.venv/bin/pip install -r requirements.txt -i https://mirrors.cloud.tencent.com/pypi/simple --trusted-host mirrors.cloud.tencent.com --prefer-binary
else
  log "已跳过 AI 依赖安装"
fi

step "启动 AI 服务"
systemctl start ai-learn-ai
systemctl status ai-learn-ai --no-pager

step "启动 Java 后端"
systemctl start ai-learn-backend
systemctl status ai-learn-backend --no-pager

step "检查并重载 Nginx"
/www/server/nginx/sbin/nginx -t
/etc/init.d/nginx reload

step "部署完成"
log "发布版本：${RELEASE_ID}"
log "部署日志：${DEPLOY_LOG}"
```

```bash
echo "验收日志：${CHECK_LOG}"
```

## 7. 快速回滚说明

如果第 5 节设置了 `ENABLE_BACKUP=1`，可以按备份回滚：

```bash
set -Eeuo pipefail

# 修改为需要回滚到的发布版本号，例如 ai-learn-20260523213000。
ROLLBACK_RELEASE="ai-learn-<发布版本号>"

test -d "/opt/ai-learn/releases/${ROLLBACK_RELEASE}/backup"

# 回滚后端 JAR。
cp "/opt/ai-learn/releases/${ROLLBACK_RELEASE}/backup/ai-learn-backend.jar" /opt/ai-learn/backend/ai-learn-backend.jar
chown ai-learn:ai-learn /opt/ai-learn/backend/ai-learn-backend.jar
chmod 640 /opt/ai-learn/backend/ai-learn-backend.jar

# 回滚前端静态资源。
rm -rf /www/wwwroot/ai-learn-web/*
tar -xzf "/opt/ai-learn/releases/${ROLLBACK_RELEASE}/backup/ai-learn-web.tar.gz" -C /www/wwwroot
chown -R www:www /www/wwwroot/ai-learn-web

# 可选回滚 AI 服务源码。
if [ -f "/opt/ai-learn/releases/${ROLLBACK_RELEASE}/backup/ai-service.tar.gz" ]; then
  rm -rf /opt/ai-learn/ai-service.rollback-tmp
  mkdir -p /opt/ai-learn/ai-service.rollback-tmp
  tar -xzf "/opt/ai-learn/releases/${ROLLBACK_RELEASE}/backup/ai-service.tar.gz" -C /opt/ai-learn/ai-service.rollback-tmp
  rsync -av --delete --exclude '.venv' --exclude '.env' /opt/ai-learn/ai-service.rollback-tmp/ai-service/ /opt/ai-learn/ai-service/
  rm -rf /opt/ai-learn/ai-service.rollback-tmp
  chown -R ai-learn:ai-learn /opt/ai-learn/ai-service
fi

systemctl restart ai-learn-ai
systemctl restart ai-learn-backend
/www/server/nginx/sbin/nginx -t
/etc/init.d/nginx reload
```

如果发布时没有备份：

1. 上线主流程不受影响。
2. 不能直接使用服务器备份文件回滚。
3. 需要在本地检出上一版代码，重新执行第 2、3、5 节发布上一版。
4. 数据库结构变更优先通过补丁 migration 修复；只有提前创建过 TDSQL 手动备份时，才考虑数据库回档。

## 8. 常见失败定位

| 失败位置 | 常见原因 | 排查方式 |
| --- | --- | --- |
| 本地 Java 构建失败 | JDK 或 Maven 环境异常、代码编译失败 | 查看 `release/logs/build-*.log` |
| 本地前端构建失败 | Node 依赖安装失败、类型检查失败 | 查看 `release/logs/build-*.log` |
| 上传失败 | SSH 未免密、网络不可达、服务器密码错误 | 查看 `release/logs/upload-*.log`，手动执行 `ssh root@159.75.111.145` |
| 服务器解包失败 | `/tmp` 中没有发布包、上传包损坏 | 查看 `/opt/ai-learn/releases/<版本>/deploy.log` |
| 服务重启失败 | 配置错误、端口占用、依赖缺失 | 执行 `journalctl -u ai-learn-backend -n 200 --no-pager` 或 `journalctl -u ai-learn-ai -n 200 --no-pager` |
| Nginx 本机反向代理验收返回 404 | 当前机器存在多个 80 端口站点，`127.0.0.1` 可能命中默认站点或本机状态站点 | 使用 `curl -fsS -H 'Host: 159.75.111.145' http://127.0.0.1/api/v1/health` 验证目标站点，或直接验证 `http://159.75.111.145/api/v1/health` |
| 公网验收失败 | Nginx 配置错误、防火墙未开放、服务未启动 | 查看 `/www/wwwlogs/` 站点日志和第 6 节验收日志 |
