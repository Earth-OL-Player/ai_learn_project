## Agent面试题

### 1.什么是AI  Agent？

**结论：**AI Agent 是围绕目标自主决策、执行动作，并根据反馈调整下一步的智能体。

**重点：**在大模型应用中，通常由模型负责决策、工具负责执行，形成“感知—思考—执行”的循环。



### 2.Agent 的基本架构由哪些核心组件构成？

**结论：**Agent 的基本架构有四个核心组件：大模型、工具、记忆、规划模块。

**重点：**大模型是理解与推理的核心；工具用于执行操作；记忆分为长期和短期，短期记忆保存上下文，长期记忆按需持久化经验；规划负责拆解任务并根据反馈调整步骤；。


### 3.[Workflow，Agent，Tools 这三个的概念和区别介绍一下？](https://xiaolinnote.com/ai/agent/3_workflow_tools.html)

**结论：**Tools 负责执行单项能力；Agent 根据目标动态决定下一步；Workflow 按开发者定义的规则编排流程。

**重点：**三者可以组合：Workflow 的节点可以是工具、模型或 Agent，区别主要在控制流由谁决定。

**例子：**以站内助手为例，查刷题记录是工具，动态选择查询动作的是 Agent，查询后固定校验并返回结果的是 Workflow。

### 4.[了解哪些其他的 Agent 设计范式？Agent 和 Workflow 的区别是什么？](https://xiaolinnote.com/ai/agent/4_patterns.html)

**结论：**常见范式有 ReAct、Plan-and-Execute、Reflection，以及路由、并行和评估优化等编排模式。

**重点：**Workflow 的流程规则预先定义，Agent 根据运行结果动态决策；我会用固定主流程保证可控，在需要判断的节点嵌入 Agent。

### 5.[Agent 推理模式有哪些？ReAct 是啥？具体是怎么实现的？](https://xiaolinnote.com/ai/agent/5_react.html)

**结论：**常见模式有 CoT、ReAct、规划执行和反思；ReAct 把推理与行动交替进行：判断、调用工具、观察结果，再继续决策。

**重点：**实现时把工具描述和当前状态交给模型，由程序执行调用并回传结果；同时设置步数、超时和成本上限。

**例子：**查询薄弱知识点时，先取刷题记录，再按结果检索学习资料；证据足够后生成建议。

### 6.[ReAct、Plan-and-Execute、Reflection 三种范式有什么核心区别？实际项目中该如何选型？](https://xiaolinnote.com/ai/agent/6_three_patterns.html)

**结论：**ReAct 边执行边调整；Plan-and-Execute 先规划再逐步执行；Reflection 根据检查结果修正输出，可叠加到前两者。

**重点：**我会按流程长度、变化程度和质量要求选型，同时限制调用预算。

**例子：**即时问答用 ReAct；学习计划先拆步骤再执行；最终计划用规则或评估器检查遗漏。

### 7.[复杂任务怎么做的任务拆分？为什么要拆分？效果如何提升？](https://xiaolinnote.com/ai/agent/7_tasksplit.html)

**结论：**我会把复杂目标拆成输入输出明确、能独立验收的子任务，再按依赖关系执行。

**重点：**流程稳定时静态拆分，开放任务动态规划；独立步骤并行，关键步骤校验。用成功率、延迟和成本验证收益，不能默认拆得越细越好。

**例子：**生成学习建议时，先统计错题、归类知识点，再检索资料，最后合成计划。

### 8.[请你介绍一下 AI Agent 的记忆机制，并说明在实际开发中应该如何设计记忆模块？](https://xiaolinnote.com/ai/agent/8_memory.html)

**结论：**Agent 记忆用于保持任务状态和复用历史信息，核心是决定存什么、何时写入、如何取用。

**重点：**短期保存当前对话和任务进度，长期保存稳定偏好与经验；实体事实可结构化存储。读取时按相关性、时效和可信度筛选，并支持纠正、过期与删除。

**例子：**学习助手可记住用户偏好的讲解深度；本轮待解答题目只放短期状态。

### 9.[Agent 的长短期记忆系统怎么做的？记忆是怎么存的？粒度是多少？怎么用的？](https://xiaolinnote.com/ai/agent/9_memory_storage.html)

**结论：**我会把短期记忆按会话保存为消息与任务状态，长期记忆按用户和事实或事件保存，按需召回。

**重点：**偏好适合结构化存储，非结构化经验可做向量检索；长期记忆并非必须放向量库，短期状态也可持久化以便恢复。

**例子：**“偏好 Java 示例”是一条长期事实；“正在讲第 3 题”是当前任务状态。

### 10.[什么是 Multi-Agent？](https://xiaolinnote.com/ai/agent/10_multiagent.html)

**结论：**Multi-Agent 是多个具有独立职责和上下文的 Agent，通过协作共同完成目标。

**重点：**可以采用主控调度、流水线或对等协作；优势是专业分工、上下文隔离和并行，代价是通信成本、协调难度和错误传播。任务简单时我会优先单 Agent。

### 11.[说说 Single-Agent 和 Multi-Agent 的设计方案？](https://xiaolinnote.com/ai/agent/11_single_multi.html)

**结论：**Single-Agent 由一个模型循环选择工具，结构简单；Multi-Agent 将任务分给多个角色，适合确有分工或并行收益的场景。

**重点：**多 Agent 可由主控统一调度，也可对等协作；我会明确输入输出、交接条件和共享状态。

**例子：**学习报告可由资料检索、错题分析两个角色产出结果，主控统一合成。

### 12.[Agent 记忆压缩通常有哪些方法？](https://xiaolinnote.com/ai/agent/12_memcompress.html)

**结论：**常见记忆压缩方法有滑动窗口、摘要、重要性过滤和结构化抽取。

**重点：**我会保留近期原文，将旧对话总结为目标、约束和已完成步骤；工具回执、关键数字和未决事项保留原始依据，防止摘要失真。

**例子：**长时间刷题讨论只保留最近几轮，并把已确认的薄弱点写入结构化摘要。

### 13.[在工程实践中，为什么有时候选择「手搓」Agent，而不是直接用成熟框架？](https://xiaolinnote.com/ai/agent/13_handcode.html)

**结论：**当流程简单、业务约束特殊，或框架抽象影响调试和性能时，我会考虑自己实现 Agent 循环。

**重点：**框架适合快速集成；手写能精确控制状态、异常和工具执行，但仍需补齐恢复、观测及预算治理。选型应比较整体维护成本，不能把框架慢当成默认结论。

### 14.[如何赋予 LLM 规划能力？](https://xiaolinnote.com/ai/agent/14_planning.html)

**结论：**规划能力来自模型能力、任务提示和运行时反馈共同作用；工程上我会要求输出可执行、可校验的步骤。

**重点：**计划包含依赖、工具、完成条件与预算，执行后更新状态，失败时重规划；CoT、ToT、GoT 是相关推理思路，不能仅靠提示词保证规划正确。

**例子：**学习计划先诊断基础，再安排资料和练习，按实际掌握情况调整下一阶段。

### 15.[讲讲 Agent 的反思机制？为什么要用反思？具体怎么实现？](https://xiaolinnote.com/ai/agent/15_reflection.html)

**结论：**反思是对已有结果做检查，再根据反馈修改策略或答案，用于发现遗漏和执行错误。

**重点：**我会优先用规则、工具结果或独立评估器提供反馈，只在关键节点启用，并限制修正轮数；没有新证据的自我检查不能保证更正确。

**例子：**学习报告生成后，检查建议是否覆盖薄弱点、链接是否有效，再定向补充。

### 16.[如何设计多 Agent 的协作与动态切换机制？](https://xiaolinnote.com/ai/agent/16_collab.html)

**结论：**我会用主控路由和统一任务状态协调多个 Agent，交接时传递目标、约束、已完成结果及下一步输入。

**重点：**明确场景走规则路由，复杂场景再让模型判断；切换需要校验输出契约，并设置超时、重试和最大交接次数。

**例子：**先由学习助手识别需求，涉及资料查询时交给检索角色，拿到证据后返回主控。

### 17.[Agent 的上下文工程怎么设计？](https://xiaolinnote.com/ai/agent/17_context_engineering.html)

**结论：**上下文工程是在每次调用前，按当前任务组装必要信息，而非不断堆积聊天记录。

**重点：**我会优先保留目标、约束和任务状态，再加入相关记忆、工具与检索证据；预留输出预算，超量时去重、裁剪和摘要。外部文本按数据处理，不能覆盖系统指令。

**例子：**回答当前错题只加载该题、近期讨论及相关资料。

### 18.[Agent 的多轮对话状态如何管理？如何防止跑偏并支持中断恢复？](https://xiaolinnote.com/ai/agent/18_session_state.html)

**结论：**我会分别管理对话历史、业务事实和任务进度，用显式状态机与检查点支持恢复。

**重点：**新消息先判断是补充、纠错还是换题；按会话和任务隔离状态，恢复时核对未决工具调用。写操作使用稳定幂等键，避免重复执行。

**例子：**发布学习建议中断后，先查询发布结果，再决定继续或重试。

### 19.[如何评估一个 Agent 的效果？评测集和指标怎么设计？](https://xiaolinnote.com/ai/agent/19_evaluation.html)

**结论：**我会同时评估工具选择、执行轨迹、最终任务完成和线上体验。

**重点：**评测集覆盖真实需求、历史失败、边界与对抗场景；用工具回执和外部状态判断是否完成，再评开放式质量。主要看成功率、错误完成声明、延迟、Token 和成本。

**例子：**学习报告不仅看文案，还检查是否取到对应用户的记录、建议是否覆盖薄弱点。

### 20.[Agent 为什么会出现路径震荡、重复调用和死循环？怎么检测和治理？](https://xiaolinnote.com/ai/agent/20_loop_stability.html)

**结论：**循环常由目标模糊、停止条件缺失、错误反馈不清或状态未更新导致。

**重点：**我会记录工具及参数指纹、状态变化和交接图，结合重复动作与无进展检测；临时故障有界重试，持续无进展则换路径或重规划，预算耗尽后停止。

**例子：**连续检索同一问题却没有新证据时，应澄清需求或说明资料不足。

### 21.[线上 Agent 延迟明显升高时，如何通过 Trace 定位和优化？](https://xiaolinnote.com/ai/agent/21_agent_latency_trace.html)

**结论：**我会先区分首 Token 延迟和总耗时，再比较异常请求与正常请求的 Trace。

**重点：**为排队、上下文、检索、模型和工具建立分段记录，定位关键路径；检查输入膨胀、工具长尾及重试增多，再做裁剪、缓存或安全并行。优化后复核成功率与 P95 延迟。

**例子：**若慢在串行查询独立数据，可并行；若慢在模型输入，优先减少无关上下文。

### 22.[Multi-Agent 系统如何处理子 Agent 超时、失联和并发修改冲突？](https://xiaolinnote.com/ai/agent/22_multi_agent_resilience.html)

**结论：**我会分别治理执行者失联和共享数据冲突，避免接管后出现两个执行者同时提交。

**重点：**用租约、执行代次和检查点恢复任务，写动作保持幂等；共享状态做版本校验，代码修改使用隔离分支或 worktree，由统一集成者检查并合并。

**例子：**两个 Agent 修改同一报告时分别提交版本，合成阶段校验基线并解决内容冲突。

### 23.[Agent 的「任务幻觉」是什么？如何避免没有执行工具却声称任务已经完成？](https://xiaolinnote.com/ai/agent/23_task_hallucination.html)

**结论：**任务幻觉是把计划、尝试或未经验证的结果，说成任务已真实完成。

**重点：**我会由程序维护执行状态，保存工具回执，并读取外部状态验证；最终回答只依据已验证结果。超时可能是结果未知，应先查询再决定重试。

**例子：**模型说“评论已发布”不算成功，必须确认发布接口回执和评论实际存在。

### 24.[大模型或 Agent 连接数据库时，如何防止越权、敏感数据泄漏和查询幻觉？](https://xiaolinnote.com/ai/agent/24_database_security.html)

**结论：**我会让模型表达查询意图，由业务工具和数据库执行可信的授权与校验。

**重点：**使用最小权限、表列白名单、参数化查询、超时和行数限制，敏感字段先裁剪脱敏；通用 SQL 还需解析语法树并检查口径，Prompt 不能充当安全边界。

**例子：**查询个人刷题统计时，用户身份来自登录态，不能采用模型生成的用户 ID。

## RAG面试题

### 1.[什么是 RAG？详细描述一个完整 RAG 系统的详细工作流程？](https://xiaolinnote.com/ai/rag/1_whatisrag.html)

**结论：**RAG 是检索增强生成：先查外部知识，再让模型基于证据回答。

**重点：**离线流程是解析清洗、切块、向量化和建索引；在线流程是查询处理、召回、重排、组装上下文、生成及引用校验。

**例子：**学习资料问答先检索对应知识点，再依据片段解释并附来源。

### 2.[大模型的 RAG 主要用来解决什么问题？](https://xiaolinnote.com/ai/rag/2_rag_problems.html)

**结论：**RAG 主要补足模型缺少的私有知识和最新知识，并为答案提供可追溯依据。

**重点：**知识保存在外部，更新无需重新训练；检索到可靠资料能降低幻觉，但检索错误、资料过时或模型误读仍会导致错误。

**例子：**新增课程文档入库后即可用于问答，不必等待模型训练。

### 3.[相比直接微调 LLM，RAG 解决了什么问题？微调和 RAG 各自的优劣势是什么？](https://xiaolinnote.com/ai/rag/3_rag_vs_finetune.html)

**结论：**RAG 侧重提供外部知识，微调侧重改变模型行为和任务能力，两者可以组合。

**重点：**RAG 更新快、可溯源，但增加检索延迟且依赖数据质量；微调能稳定风格和格式，但需要训练数据与资源，知识更新和追溯较难。

**例子：**课程知识更新用 RAG；长期稳定的评分格式若提示词仍不可靠，再评估微调。

### 4.[RAG 中的文档是怎么存的？粒度是多大？详细说说文档切割（Chunking）策略？](https://xiaolinnote.com/ai/rag/4_chunking.html)

**结论：**我会保留原始文档，将切块文本、向量和来源元数据关联存储，检索后能回到原文。

**重点：**按标题段落、语义或代码函数切分，必要时重叠；可从数百 Token 起步，用评测决定粒度。父子切块能以小块检索、大块补充上下文。

**例子：**课程章节保留标题路径、版本和片段位置，避免只保存孤立向量。

### 5.[怎么规避语义被切割掉的问题？](https://xiaolinnote.com/ai/rag/5_semantic_cuts.html)

**结论：**我会在切分时尊重语义边界，在召回后补回必要上下文。

**重点：**可以组合段落切分、适量重叠、邻近片段扩展和父子切块；也可给片段补充文档背景再索引，但要防止背景生成引入错误。

**例子：**方法定义和使用限制分到两块时，命中定义后同时返回限制段落。

### 6.[在 RAG 中 Embedding 究竟是什么？如何选择和评估一个 Embedding 模型？](https://xiaolinnote.com/ai/rag/6_embedding.html)

**结论：**Embedding 将文本映射成向量，使语义相关内容在向量空间更容易匹配。

**重点：**我会按语言领域、输入长度、维度、延迟和部署成本选型，用业务问题与相关文档评测 Recall@K、MRR 等指标；维度更高不必然更好。

**例子：**中文面试资料先比较候选模型对术语、缩写和同义问法的召回效果。

### 7.[Embedding 有哪几种算法你了解过吗？](https://xiaolinnote.com/ai/rag/7_embedding_algos.html)

**结论：**我了解静态词向量、上下文表示和专门训练的句子或文档向量。

**重点：**Word2Vec、GloVe 给词固定表示；BERT 根据上下文表示词；SBERT、SimCSE、BGE 等更适合语义检索。常用双编码器提前计算文档向量，交叉编码器更适合候选重排。

### 8.[什么是向量数据库？有没有做过向量数据库的对比选型？](https://xiaolinnote.com/ai/rag/8_vectordb.html)

**结论：**向量数据库提供向量存储与相似度搜索，并常配套元数据过滤和索引管理。

**重点：**我会按规模、过滤效果、更新频率、延迟及运维成本，对比 Qdrant、Milvus、pgvector 等；ANN 用召回损失换速度，需实测。

**例子：**已有 PostgreSQL 的小规模知识库可先评估 pgvector；更复杂场景再考虑独立向量服务。

### 9.[讲讲你用的向量数据库？数据量级是多大？性能如何？遇到过性能瓶颈吗？](https://xiaolinnote.com/ai/rag/9_vectordb_practice.html)

**结论：**若没有生产实践，我会说明评估方案，实际数据量和性能只报压测结果。

**重点：**以 Qdrant 为候选，记录向量数、维度、索引、过滤与并发，衡量召回率、P95 延迟及内存；瓶颈可通过过滤索引、批量写入和调参改善。

**例子：**假设 10 万条 768 维向量，可做不同并发的压测；该规模是示例，不代表我的线上经历。

### 10.[你使用 RAG 给大模型一个输入，系统是怎样的工作流程？](https://xiaolinnote.com/ai/rag/10_online_workflow.html)

**结论：**用户输入后，我会先补齐查询语境，再检索证据，最后让模型生成有出处的答案。

**重点：**流程是意图判断或改写、向量与关键词召回、去重重排、预算裁剪、生成及引用校验；证据不足时澄清或拒答。

**例子：**“这个和微调有什么区别”先结合上轮明确“这个”指 RAG，再检索对比资料。

### 11.[请你介绍一下向量检索和关键词检索的区别？](https://xiaolinnote.com/ai/rag/11_retrieval_types.html)

**结论：**关键词检索擅长精确词项，向量检索擅长语义近似与不同表述。

**重点：**BM25 对型号、编号和专业缩写有效，向量能处理同义表达，但可能混淆精确标识；我通常做混合检索，再融合重排。

**例子：**查“GQA”保留关键词召回；查“怎样减少注意力缓存”补充向量召回。

### 12.[如何润色用户的 Query（Query Rewrite）？目的是什么？](https://xiaolinnote.com/ai/rag/12_query_rewrite.html)

**结论：**Query Rewrite 是将用户问题变为更利于检索的表达，同时保留原始意图。

**重点：**可消解指代、补充术语、扩展多问法、做 Step-back 或 HyDE；改写不能凭空添加条件，HyDE 的假设答案只用于检索，不作为事实。

**例子：**“上面那个怎么避免乱编”可改为“RAG 如何降低生成幻觉”，并保留原问题参与召回。

### 13.[什么是多路召回？具体怎么做？](https://xiaolinnote.com/ai/rag/13_multi_retrieval.html)

**结论：**多路召回是用互补检索路径获取候选，提升覆盖率。

**重点：**我会并行做向量、BM25 或多 Query 检索，统一文档标识后去重，用 RRF 融合排名，再用 Reranker 精排；不同通道原始分数不宜直接相加。

**例子：**术语题结合关键词和语义路径，既命中缩写，也召回解释段落。

### 14.[RAG 检索优化策略有哪些？](https://xiaolinnote.com/ai/rag/14_retrieval_opt.html)

**结论：**我会按索引、查询、召回和重排四层优化，并用失败样本定位瓶颈。

**重点：**索引侧优化解析切块和元数据；查询侧改写与扩展；召回侧混合检索和过滤；排序侧 Rerank、去重及邻段补全。每次比较召回质量、答案质量和成本。

**例子：**型号漏检先补关键词路；上下文断裂先改切块，避免盲目换大模型。

### 15.[了解哪些更复杂的 RAG 范式？](https://xiaolinnote.com/ai/rag/15_advanced_paradigms.html)

**结论：**常见进阶范式有 Self-RAG、CRAG、GraphRAG 和 Agentic RAG。

**重点：**Self-RAG 用反思信号控制检索并评估证据；CRAG 根据检索质量纠正或补检索；GraphRAG 利用实体关系和社区摘要；Agentic RAG 动态多轮检索。选型要看问题类型与额外成本。

### 16.[在什么场景下，你会选择使用图数据库来增强传统的向量检索？](https://xiaolinnote.com/ai/rag/16_graph_db.html)

**结论：**当问题需要明确实体关系、多跳查询或跨文档汇总时，我会评估图结构增强。

**重点：**向量负责找语义相关资料，图检索沿关系补充证据；图构建和维护成本较高，普通问答不一定需要。多轮向量检索也能处理部分多跳问题。

**例子：**学习路线问“先学哪些前置知识”，可沿知识点依赖关系检索，再返回课程说明。

### 17.[如何规避 RAG 系统中大模型的幻觉？](https://xiaolinnote.com/ai/rag/17_hallucination.html)

**结论：**我会从证据质量、生成约束和答案核查三方面降低 RAG 幻觉。

**重点：**先过滤过时资料并评估相关性，生成时要求按证据回答；关键结论核对引用是否支持，缺少依据就说明未知。检索分数阈值要按业务校准，不能当成统一置信度。

**例子：**资料没写某模型是否支持功能，就说明未找到依据，不替它推断。

### 18.[怎么量化你的 RAG 效果？](https://xiaolinnote.com/ai/rag/18_evaluation.html)

**结论：**我会分开评估检索质量、答案质量和线上体验。

**重点：**检索看 Recall@K、MRR、nDCG；答案看正确性、忠实度、相关性和引用有效性；线上看满意度、延迟与成本。评测集标注问题、相关证据及答案要求，模型裁判需要人工校准。

**例子：**新版本既不能漏召回关键定义，也不能让答案添加资料未支持的结论。

### 19.[RAG 知识库如何实现动态与持续更新？](https://xiaolinnote.com/ai/rag/19_dynamic_update.html)

**结论：**我会通过变更检测和版本化索引实现增量更新，兼顾新鲜度与读一致性。

**重点：**用文档 ID、内容 Hash 和版本定位变化，只重建受影响片段；新索引准备并验证后切换，再淘汰旧版本。删除同步清理索引和缓存，更换 Embedding 时需重建。

**例子：**课程修订先准备新版本，避免先删旧向量导致问答暂时无资料。

### 20.[在实际落地中，你觉得 RAG 最难的地方是哪里？](https://xiaolinnote.com/ai/rag/20_hardest_parts.html)

**结论：**我认为难点是持续保证数据、检索和评测质量，而不是搭通调用链。

**重点：**复杂文档解析可能丢语义，切块和查询不匹配可能漏召回，评测缺少证据标注就难以定位错误；我会建立失败样本闭环，逐层优化。

**例子：**答案错时先确认原文是否解析正确，再查是否召回、重排是否留下、生成是否忠实。

### 21.[不同来源的文档发生知识冲突时，RAG 应该信谁？](https://xiaolinnote.com/ai/rag/21_knowledge_conflict.html)

**结论：**我会先判断文档适用范围，再比较权威度、版本状态与生效时间，不能只信相似度最高的材料。

**重点：**入库保留来源、版本、产品与生效区间，检索先过滤；同等权威且有效的内容仍冲突时，应展示分歧与出处，必要时确认。

**例子：**不同版本的 LangChain 文档先按项目版本筛选，避免把旧接口作为当前推荐。

## LLM工具调用面试题

### 1.[什么是 Function Calling？原理是什么？](https://xiaolinnote.com/ai/tools/1_function_calling.html)

**结论：**Function Calling 是模型输出结构化工具调用请求，再由宿主程序执行的机制。

**重点：**开发者提供工具名称、描述和参数 Schema；模型选择工具并生成参数，程序校验执行后回传结果，模型继续回答或调用。一次任务可能有多轮调用。

**例子：**查询刷题统计时，模型提出查询请求，后端实际获取数据，模型依据结果总结。

### 2.[LLM 是如何学会调用外部工具的？](https://xiaolinnote.com/ai/tools/2_llm_tool_learning.html)

**结论：**模型通过包含工具说明和调用轨迹的数据学习何时调用、选哪个工具及如何填参数。

**重点：**运行时会读取当前工具 Schema，生成结构化请求；真正执行的是宿主程序，模型权重不会因一次调用自动更新。工具不存在或能力不足时应澄清或拒绝。

### 3.[大模型的 Function Call 能力是怎么训练出来的？](https://xiaolinnote.com/ai/tools/3_fc_training.html)

**结论：**通常先用监督微调学习工具调用格式和流程，再通过偏好优化或执行反馈提升可靠性。

**重点：**训练样本应覆盖调用与不调用、参数生成、多步依赖及失败修正；评测工具选择、参数合法率和任务成功率。RLHF 是可选路线，并非所有工具模型必经阶段。

### 4.[什么是 MCP（模型上下文协议）？讲讲它的核心内容？](https://xiaolinnote.com/ai/tools/4_what_is_mcp.html)

**结论：**MCP 是连接 AI 应用与外部工具、资源及提示模板的开放协议，减少重复适配。

**重点：**Host 通过 Client 连接 Server，以 JSON-RPC 消息发现和调用能力；本地常用 stdio，远程用 Streamable HTTP。MCP 标准化连接，并不替模型完成推理或授权。

**例子：**同一资料检索服务可通过 MCP 提供给多个兼容客户端。

### 5.[MCP 由哪几部分组成？](https://xiaolinnote.com/ai/tools/5_mcp_components.html)

**结论：**MCP 从架构看包含 Host、Client 和 Server；从服务能力看主要有 Tools、Resources 和 Prompts。

**重点：**Host 是宿主应用，Client 处理连接，Server 提供能力；Tool 是可调用操作，既可查询也可写入，Resource 提供数据，Prompt 提供模板。消息和传输按协商的协议版本实现。

### 6.[MCP 和 Function Calling 有什么区别？有没有实际跑过 MCP？](https://xiaolinnote.com/ai/tools/6_mcp_vs_fc.html)

**结论：**Function Calling 定义模型如何表达调用，MCP 定义应用如何连接和使用外部能力，二者处于不同层次。

**重点：**常见流程是 Client 获取 MCP 工具描述并适配给模型，模型生成调用，再由 Client 执行；MCP 不强制依赖某家模型 API。实际使用经历应据实描述。

**例子：**可用本地文件检索 Server 演示工具发现、调用和结果回传。

### 7.[Function Calling 也属于工具调用，请问什么场景下使用 Function Calling，什么场景下使用 MCP？](https://xiaolinnote.com/ai/tools/7_fc_vs_mcp_usage.html)

**结论：**少量内部工具、仅单应用使用时，我会直接做 Function Calling 集成；跨应用复用或对接标准工具生态时，再使用 MCP。

**重点：**二者可以配合：模型通过 Function Calling 决策，宿主通过 MCP 执行。选型要比较复用收益、认证、部署及运行成本。

**例子：**内部查刷题记录直接封装工具；统一文档服务供多个助手使用时可暴露为 MCP。

### 8.[为什么有些特定的推理模型不支持 MCP 协议？](https://xiaolinnote.com/ai/tools/8_reasoning_no_mcp.html)

**结论：**“模型不支持 MCP”通常是宿主集成或工具调用能力不足，不能简单归因于推理过程无法中断。

**重点：**MCP 由应用层 Client 实现；应检查模型的工具格式、服务端 API、适配器及多轮回传支持。有些推理模型能交错推理与工具调用，兼容性要按具体版本验证。

### 9.[Skill 是什么？](https://xiaolinnote.com/ai/tools/9_skill.html)

**结论：**Skill 是将某类任务的操作知识、步骤和资源封装为可复用能力包。

**重点：**通常以 SKILL.md 描述适用场景和执行要求，附带脚本、模板与参考资料；兼容的 Agent 先发现说明，再按需读取内容。Skill 本身不自动获得外部系统权限。

**例子：**面试回答 Skill 可以规定“结论、重点、例子”和字数要求。

### 10.[MCP 和 Agent Skill 的区别是什么？](https://xiaolinnote.com/ai/tools/10_mcp_vs_skill.html)

**结论：**MCP 提供标准化的外部连接，Skill 提供完成任务所需的知识和流程。

**重点：**二者互补：Skill 可以指导如何使用 MCP 工具，也可以调用本地脚本或其他接口，不必依赖 MCP。

**例子：**整理学习周报时，Skill 规定统计口径和模板，MCP 工具提供学习记录。

### 11.[Function Calling、Skill、MCP 这三个有什么区别？](https://xiaolinnote.com/ai/tools/11_fc_skill_mcp.html)

**结论：**Function Calling 负责表达工具调用，MCP 负责连接外部能力，Skill 负责组织任务知识与步骤。

**重点：**它们不是必须依次叠加的固定技术栈；可独立使用，也可协作。授权、参数校验和实际执行仍由应用负责。

**例子：**周报 Skill 指导整理流程，模型发出查询请求，MCP Client 取回数据后生成报告。

### 12.[什么是 A2A 协议？它和 MCP 协议的区别是什么？](https://xiaolinnote.com/ai/tools/12_a2a_protocol.html)

**结论：**A2A 是 Agent 之间发现能力、委托任务并交换结果的开放协议；MCP 侧重应用连接工具和数据。

**重点：**A2A 通过 Agent Card 描述能力，按任务状态及产物处理协作，可支持长任务和流式更新。Agent 可在内部继续使用 MCP，二者互补。

**例子：**学习助手将资料调研交给研究 Agent，接收报告后再生成学习计划。

### 13.[MCP 协议通常采用什么通信方式？](https://xiaolinnote.com/ai/tools/13_mcp_transport.html)

**结论：**MCP 的标准传输主要是 stdio 和 Streamable HTTP，消息使用 JSON-RPC。

**重点：**stdio 适合本地子进程；Streamable HTTP 适合远程服务，可返回 JSON 或 SSE 流。早期 HTTP+SSE 双端点方案是兼容方案，新项目按双方支持的版本选择传输。

### 14.[说说 WebSocket 和 SSE 通信的区别及局限性？](https://xiaolinnote.com/ai/tools/14_sse_vs_websocket.html)

**结论：**SSE 是服务端向客户端推送文本事件；WebSocket 是双方都能发送消息的双向连接。

**重点：**SSE 易融入 HTTP，但客户端发送需另发请求，原生 EventSource 也有限制；WebSocket 可传二进制，需处理心跳、重连和连接管理。

**例子：**刷题讲解的文本流可用 SSE；高频双向交互可用 WebSocket，取消请求也能另走 HTTP。

### 15.[为什么要用 WebRTC 协议？它和 WebSocket 在 AI 对话流中的核心差异是什么？](https://xiaolinnote.com/ai/tools/15_webrtc_vs_ws.html)

**结论：**WebRTC 面向实时音视频，通常通过 UDP 媒体传输降低丢包时的等待，并提供拥塞控制、抖动缓冲和媒体处理。

**重点：**WebSocket 基于 TCP，可靠有序，但丢包重传可能拖慢后续音频；WebRTC 需要信令和 ICE/STUN/TURN，受网络限制时也可能走中继。

**例子：**实时语音面试适合评估 WebRTC；纯文字讲解通常用 SSE 即可。

### 16.[有没有用过大模型的网关框架？网关层解决了什么问题？](https://xiaolinnote.com/ai/tools/16_llm_gateway.html)

**结论：**LLM 网关位于应用与模型服务之间，统一调用入口、密钥管理和运行治理。

**重点：**我会关注模型路由、限流配额、超时降级、Token 成本和调用观测；统一接口不代表模型能力完全一致。没有真实使用经历时，只介绍评估方案。

**例子：**多供应商评分服务可评估 LiteLLM；涉及个人数据的缓存必须隔离并考虑时效。

### 17.[工具很多时，Agent 如何做 Tool Routing，减少 Token 并避免选错工具？](https://xiaolinnote.com/ai/tools/17_tool_routing.html)

**结论：**工具很多时，我会先筛选少量候选，再将完整 Schema 提供给模型选择。

**重点：**先按可信身份、任务范围和可用性过滤，再按类别或语义召回；低置信度时澄清或扩大候选。评估候选召回、最终选择、参数合法率及 Schema Token。

**例子：**刷题问题只加载题目与学习统计工具，避免同时暴露无关发布操作。

### 18.[工具调用格式非法、参数错误、超时或失败时，Agent 如何容错？](https://xiaolinnote.com/ai/tools/18_tool_reliability.html)

**结论：**我会按错误类型处理：格式与参数错误修正，临时故障有界重试，权限或业务拒绝直接反馈。

**重点：**先校验 Schema 和业务规则，再执行；超时的写操作先按幂等键查询结果，不能直接重复。配合退避、熔断、预算和结构化错误。

**例子：**发布评论超时后先查是否已创建，确认结果再决定重试或告知待确认。

## 大模型工程面试题

### 1.[什么是大语言模型？和传统 NLP 模型有什么区别？](https://xiaolinnote.com/ai/llm/what_is_llm.html)

**结论：**大语言模型通过大规模语料预训练获得通用语言能力，再通过提示或训练适配多种任务。

**重点：**常见生成式 LLM 自回归预测下一个 Token；传统 NLP 多针对具体任务训练，LLM 更强调统一模型与上下文学习。两者并非严格按判别式、生成式或参数量划分。

### 2.[讲讲 Transformer 架构基本原理？Encoder 和 Decoder 是什么？](https://xiaolinnote.com/ai/llm/transformer_architecture.html)

**结论：**Transformer 以注意力机制建模 Token 间关系，结合前馈网络、残差连接和归一化处理序列。

**重点：**Encoder 通常使用双向注意力理解输入；Decoder 用因果掩码生成，原始结构还用交叉注意力读取 Encoder 输出。常见生成式 LLM 采用 Decoder-only，训练可并行，生成仍逐 Token 进行。

### 3.[多头注意力（MHA）有哪些局限？MQA、GQA、Flash Attention 怎么解决？](https://xiaolinnote.com/ai/llm/mha_mqa_gqa_flash_attention.html)

**结论：**MHA 的主要成本是多头 KV Cache 和长序列注意力计算；MQA、GQA 与 Flash Attention 优化不同层面。

**重点：**MQA 所有查询头共享一组 KV，GQA 分组共享，减少缓存与访存；Flash Attention 用分块和融合计算减少显存读写，保持精确注意力，但不消除稠密注意力的平方计算复杂度。

### 4.[大模型的位置编码是干什么用的？sin/cos、RoPE、ALiBi 有什么区别？](https://xiaolinnote.com/ai/llm/position_encoding.html)

**结论：**位置编码为注意力提供顺序信息，避免模型只看到词而无法区分位置关系。

**重点：**sin/cos 将绝对位置编码加入表示；RoPE 旋转 Q、K，使点积携带相对位置关系；ALiBi 对注意力分数加距离偏置。长序列外推效果仍受训练长度和任务影响，不能只看编码方案。

### 5.[什么是大模型项目的分词器？原理是什么？](https://xiaolinnote.com/ai/llm/tokenizer.html)

**结论：**Tokenizer 将文本编码成 Token ID，模型再把 ID 映射为向量；生成后解码为文本。

**重点：**常见子词方法有 BPE、WordPiece、Unigram。BPE 反复合并高频相邻单元；SentencePiece 是分词工具，不等同于某一种算法。Token 不等于汉字，预算和计费应按实际分词器计算。

### 6.[大模型是怎么训练出来的？](https://xiaolinnote.com/ai/llm/llm_training.html)

**结论：**常见训练流程是数据准备、预训练、监督微调，再按目标做偏好或强化学习优化。

**重点：**预训练通过预测 Token 学通用表示和知识；SFT 用指令样本学习任务表达；DPO、RLHF 等进一步优化偏好。流程取决于模型用途，并非每个模型都必须经历所有阶段。

### 7.[什么是 Scaling Law？大模型的「涌现能力」是怎么回事？](https://xiaolinnote.com/ai/llm/scaling_law_emergence.html)

**结论：**Scaling Law 描述模型规模、数据和计算预算与训练损失之间的经验关系，用于配置训练资源。

**重点：**“涌现”指某些能力随规模表现出明显跃升，但也可能受评测阈值影响。参数与数据的最优比例依赖预算和目标，不能把某个配比或参数门槛当成普适定律。

### 8.[大模型微调的方案有哪些？](https://xiaolinnote.com/ai/llm/finetuning.html)

**结论：**按更新参数范围，可选全量微调、LoRA 等参数高效微调，以及量化底座上的 QLoRA。

**重点：**按训练目标，又有 SFT、偏好优化等，二者不是同一维度。我会先验证 Prompt 和 RAG 是否够用，再看数据质量、资源和稳定输出需求决定是否训练。

**例子：**评分格式长期不稳定时，可用高质量标注样本评估 LoRA 的收益。

### 9.[请讲一下 LoRA 技术，除了减少参数量，它还有哪些优点？](https://xiaolinnote.com/ai/llm/lora.html)

**结论：**LoRA 冻结原权重，用低秩矩阵表示增量：W 加上 BA，仅训练 A、B。

**重点：**除了减少训练参数和优化器内存，还便于保存、切换多套适配器；合并权重后可免去额外分支计算。效果取决于秩、目标层和数据，冻结底座不保证通用能力完全不退化。

**例子：**同一底座可维护评分和讲解两套适配器。

### 10.[SFT 之后还有哪些 Post-Training？RLHF、DPO、GRPO、拒绝采样什么关系？](https://xiaolinnote.com/ai/llm/post_training.html)

**结论：**Post-Training 是预训练后的能力与行为优化，通常也包含 SFT，后续还能组合偏好优化和强化学习。

**重点：**RLHF 常用人类反馈与奖励模型；DPO 直接学偏好对；GRPO 用组内奖励计算相对优势，通常无需价值模型；拒绝采样筛选高质量生成再做训练。它们可以组合，不是固定顺序。

### 11.[大模型的 DPO 和 PPO 的区别是什么？](https://xiaolinnote.com/ai/llm/dpo_vs_ppo.html)

**结论：**DPO 直接利用偏好对优化模型；经典 PPO 式 RLHF 先训练奖励模型，再采样并用奖励更新策略。

**重点：**PPO 通常配合价值模型和参考策略，训练与资源管理更复杂；DPO 不需显式奖励模型，流程较简单，但依赖偏好数据覆盖。选择看任务奖励、探索需求和训练预算。

### 12.[大模型生成文本时的解码策略有哪些？贪心、Beam Search、采样分别什么时候用？](https://xiaolinnote.com/ai/llm/decoding_strategies.html)

**结论：**解码策略决定如何从下一 Token 的概率分布选出结果。

**重点：**贪心每步选最大概率；Beam Search 保留多条候选，适合部分序列任务；采样用于开放生成，结合温度和 Top-P 等控制多样性。高序列概率不等于事实正确，低温也不保证完全复现。

**例子：**信息抽取用低随机性和格式约束，创意讲解可适度采样。

### 13.[大模型的参数：温度值、Top-P、Top-K 分别是什么？各个场景下的最佳设置是什么？](https://xiaolinnote.com/ai/llm/temperature_top_p_top_k.html)

**结论：**温度控制分布尖锐程度；Top-P 按累积概率截取候选；Top-K 保留固定数量的高概率候选。

**重点：**我会从厂商默认值开始，一次调整一个参数，用业务样本比较质量与稳定性。模型支持范围不同，没有通用最佳设置。

**例子：**评分和抽取可从低温评估，创意讲解适当提高；某些推理接口不允许调整这些参数。

### 14.[KV Cache 是什么？Prompt Caching 的原理是什么？](https://xiaolinnote.com/ai/llm/kv_cache_prompt_caching.html)

**结论：**KV Cache 保存已处理 Token 的键和值，避免生成新 Token 时重复计算历史表示。

**重点：**Prompt Caching 跨请求复用相同前缀的计算，降低预填充成本；它缓存的不是答案。收益取决于前缀、保留时间、隔离规则和命中率。

**例子：**把稳定评分规则放前面，题目和用户答案放后面，便于复用前缀。

### 15.[大模型量化是什么？INT8/INT4/AWQ/GPTQ 怎么选？](https://xiaolinnote.com/ai/llm/quantization.html)

**结论：**量化用更低位数表示权重或激活，减少存储和访存开销，但可能损失精度。

**重点：**INT8、INT4 是位宽；AWQ 利用激活统计保护重要权重，GPTQ 利用近似二阶信息补偿量化误差。选型需看硬件、内核兼容和业务效果，低位不保证更快；GGUF 是格式。

**例子：**本地讲解模型可评估 INT4，再复核术语准确率和延迟。

### 16.[如何写好 Prompt？分享下 Prompt 工程实践经验？](https://xiaolinnote.com/ai/llm/prompt_engineering.html)

**结论：**我会把任务、背景、约束、输出格式和示例写清楚，再用固定样本验证改动。

**重点：**输入资料与指令分区，信息缺失时要求澄清；机器消费的结果用 Schema 校验，不能只靠文字约束。Prompt 要版本化，并持续收集失败样本。

**例子：**刷题评分说明评分维度与证据要求，约定分数及反馈字段，避免只写“请打分”。

### 17.[什么是 CoT？为啥效果好？它有什么缺点或局限性？](https://xiaolinnote.com/ai/llm/cot.html)

**结论：**CoT 是通过中间推理步骤组织多步问题，让后续计算利用已有步骤，部分任务因此更容易解答。

**重点：**它增加 Token、延迟和成本，中间推理也可能出错，不能把解释流畅当成正确。推理模型不一定需要手动提示；面向用户通常给简要依据和可核验步骤即可。

**例子：**组合条件题可分步骤核对，基础定义题直接回答。

### 18.[大模型为什么会出现幻觉？怎么缓解？](https://xiaolinnote.com/ai/llm/hallucination.html)

**结论：**幻觉是模型生成看似合理却缺乏事实或上下文依据的内容，源于概率生成、知识缺口和数据噪声等因素。

**重点：**我会用可靠检索、工具核查、引用验证及证据不足时拒答降低风险；低温只能减少随机性，不能保证事实正确。关键业务结果用外部状态校验。

**例子：**学习资料未说明的特性应标为未知，不能补写“看起来合理”的结论。

### 19.[MoE 混合专家模型是什么？DeepSeek V3、Qwen 为什么用 MoE？](https://xiaolinnote.com/ai/llm/moe.html)

**结论：**MoE 在部分网络层设置多个专家，通过路由为每个 Token 选择少量专家参与计算。

**重点：**它能在较少激活参数下扩大总容量，但仍需存储总体权重，并处理负载均衡和跨设备通信；激活参数少不代表整体成本等于同规模稠密模型。DeepSeek V3 和部分 Qwen 型号采用这种设计。

### 20.[大模型部署有哪些主流方案？vLLM、TGI、llama.cpp、SGLang 实际项目里怎么选？](https://xiaolinnote.com/ai/llm/deployment_frameworks.html)

**例子：**站内讲解先用 API 验证需求，自部署再做并发成本对比。

### 21.[大模型能力评测指标有哪些？](https://xiaolinnote.com/ai/llm/evaluation_metrics.html)

**结论：**我会把通用能力、业务效果和运行成本分开评估。

**重点：**它与训练分布、位置偏置和干扰信息有关；输入窗口大不等于有效利用强。我会检索重排、压缩无关内容，并在不同长度和证据位置上评测。

**结论：**我了解 LangChain、LangGraph、LlamaIndex，也了解 CrewAI 等多 Agent 框架。

**重点：**LangChain 适合通用模型与工具集成；LangGraph 强调状态和复杂流程控制；LlamaIndex 偏重数据接入与检索。选型看业务主要难点，而不是框架功能清单。

**例子：**学习助手的复杂编排用 LangGraph，资料问答可独立评估检索组件。

### 2.[如何理解 LangChain 中的 Chain？](https://xiaolinnote.com/ai/langchain/chain.html)

**结论：**Chain 是将提示、模型、检索器和解析器按数据流组合成可执行流程。

**重点：**现代 LangChain 用 Runnable 统一执行接口，LCEL 用管道符等组合组件，支持同步、异步、批量和流式。固定数据流适合这种组合；复杂循环与恢复需要图编排。

**例子：**刷题评分可串联评分提示、模型调用和结构化结果解析。

### 3.[LangChain 的底层架构与实现原理是什么？](https://xiaolinnote.com/ai/langchain/langchain_architecture.html)

**结论：**LangChain 用标准消息、模型、工具和执行接口统一集成，再由 Agent 运行时组织调用循环。

**重点：**Runnable 支持组件组合；create_agent 基于 LangGraph：模型生成 tool_calls，运行时执行工具并回写 ToolMessage，再继续决策。状态、检查点和中间件分别承担上下文、恢复与调用治理。

### 4.[使用 LangChain 构建 Agent 的核心步骤是什么？](https://xiaolinnote.com/ai/langchain/build_agent.html)

**结论：**我会先明确目标和结束条件，再选模型、定义工具、约束输出，并补齐状态和异常处理。

**重点：**常见循环用 create_agent 组装模型、tools 与提示；按需接入中间件、Checkpointer 和 Store，再验证工具选择、执行结果与失败恢复。

**例子：**学习助手先开放资料检索，跑通后再接入受控查询和站内操作。

### 5.[在 LangChain 中，如何为 Agent 注册工具？](https://xiaolinnote.com/ai/langchain/tool_registration.html)

**结论：**注册工具要同时提供模型能理解的描述和程序能执行的函数。

**重点：**可用带类型与说明的函数、@tool、StructuredTool 或 BaseTool，再传入 create_agent 的 tools。参数需校验，用户身份等可信信息由 Runtime 注入，不能让模型填写。

**例子：**查我的刷题统计时，模型只提供时间范围，身份由后端确定。

### 6.[LangChain 如何实现短期记忆和长期记忆？](https://xiaolinnote.com/ai/langchain/memory.html)

**结论：**短期记忆对应线程 State 与 Checkpointer，长期记忆用 Store 按命名空间和键保存。

**重点：**同一 thread_id 可恢复会话状态；长期偏好跨线程读取。生产需要持久化后端及用户隔离，长历史按需裁剪或摘要。Store 并非一定要做向量检索。

**例子：**本轮题目保存在 State，跨会话的讲解偏好存入 Store。

### 7.[LangChain 和 LlamaIndex 有什么区别？](https://xiaolinnote.com/ai/langchain/langchain_vs_llamaindex.html)

**结论：**LangChain 偏通用模型、工具和 Agent 集成；LlamaIndex 更关注数据解析、索引和检索增强。

**重点：**二者都能实现 Agent 和 RAG；我会根据主要瓶颈选型，也可组合使用，让 LlamaIndex 提供检索工具，再由 LangChain 或 LangGraph 调度。

**例子：**复杂课程文档优先解决数据层，含多个业务操作的助手优先解决编排层。

### 8.[LangChain4j 主要解决了哪些问题？](https://xiaolinnote.com/ai/langchain/langchain4j.html)

**结论：**LangChain4j 为 Java 应用提供模型、工具、记忆和 RAG 等集成，减少接入大模型的胶水代码。

**重点：**它是独立的 Java 框架；AI Services 支持声明式接口，可融入 Spring Boot。不同供应商能力仍需验证，不能认为统一接口就完全可替换。

**例子：**已有 Java 业务系统可直接封装服务为工具，但当前项目是否迁移仍需评估。

### 9.[LangChain 和 LangGraph 的核心区别是什么？](https://xiaolinnote.com/ai/langchain/langchain_vs_langgraph.html)

**结论：**LangChain 提供高层 Agent 组装，LangGraph 提供更底层的状态和执行编排；当前 create_agent 本身运行在 LangGraph 上。

**重点：**常见工具循环先用 LangChain；需要显式控制分支、并行、子图和恢复边界时直接用 LangGraph。

**例子：**学习助手查询资料后可能进入操作或继续澄清，图结构能明确每条路径。

### 10.[LangGraph 相比于 LangChain 有哪些核心优势？](https://xiaolinnote.com/ai/langchain/langgraph_advantages.html)

**结论：**直接使用 LangGraph 的优势是精确控制状态、节点、边和执行边界，而不只是多一种 Agent API。

**重点：**它支持循环、并行、检查点和中断恢复，也能将确定性步骤与 Agent 混排；LangChain Agent 已继承部分能力，是否直接用图取决于编排复杂度。

**例子：**发布内容前暂停，收到确认后恢复；外部写入仍需幂等，不能靠检查点保证只执行一次。

### 11.[LangChain 大版本升级有哪些核心变化？](https://xiaolinnote.com/ai/langchain/version_evolution.html)

**结论：**我会把版本演进概括为组件拆分、统一组合接口，以及 Agent 运行时走向 LangGraph。

**重点：**core 与供应商包解耦，Runnable 和 LCEL 统一执行；v1 以 create_agent 和 middleware 为主要入口，旧 Chain 等迁入 langchain-classic。升级需核对锁定版本、导入路径和业务行为。

### 12.[Deep Research 的实现逻辑和适用场景是什么？](https://xiaolinnote.com/ai/langchain/deep_research.html)

**结论：**Deep Research 是面向开放问题的多轮研究流程：澄清目标、拆子题、检索核验、发现空白后补搜，再合成带引用的报告。

**例子：**比较多种 RAG 方案时，分别查原理和部署约束，核对来源后统一形成选型报告。
