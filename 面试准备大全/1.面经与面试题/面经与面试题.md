## Agent面试题

### [1.什么是AI  Agent？](https://xiaolinnote.com/ai/agent/1_whatisagent.html)

**结论：**AI Agent 是围绕目标自主决策、执行动作，并根据反馈调整下一步的智能体。

**重点：**在AI应用中，通常由模型负责决策、工具负责执行，形成“感知—思考—行动”的循环。



### [2.Agent 的基本架构由哪些核心组件构成？](https://xiaolinnote.com/ai/agent/2_components.html)

**结论：**Agent 的基本架构有四个核心组件：大模型、工具、记忆、规划模块。

**重点：**大模型是Agent的核心大脑；工具用于执行操作；记忆分为长期和短期，短期记忆保存上下文，长期记忆按需持久化经验；规划模块负责任务拆解和决策，常见**设计范式**包括**ReAct**和**Plan-and-Execute**。




### 3.[Workflow，Agent，Tools 这三个的概念和区别介绍一下？](https://xiaolinnote.com/ai/agent/3_workflow_tools.html)

**结论：**Tools 负责执行单项能力；Agent 根据目标动态决定下一步；Workflow 按开发者定义的规则编排流程。

**重点：**三者可以组合：Agent和工具可以作为Workflow的一个节点被编排。



### 4.[了解哪些 Agent 设计范式？](https://xiaolinnote.com/ai/agent/4_patterns.html)

**结论：**常见设计范式有 ReAct、Plan-and-Execute、Reflection。

**重点：**ReAct模式将Agent的执行拆成了感知、思考、行动3个步骤的循环，大模型决定要不要调用工具，如果要调用工具的话，就调用工具之后进入下一轮循环，否则就退出循环返回结果。

​            Plan-and-Execute是先规划后执行，先生成一个完整的步骤列表，再逐步执行。执行过程中可以根据每一步的执行结果，决定要不要调整后续步骤，即动态重规划。

​            Reflection是在完成任务之后，让另一个大模型来进行评估结果是否符合逾期，如果不符合逾期，则让Agent带着评估结果进行重试。代价是会延迟和token消耗都会增加。

**如何选型：**

任务不复杂，直接用 **ReAct**，够用就好；复杂任务容易跑偏的，使用**Plan-and-Execute**；输出要求高的话，在上面叠加Reflection。

三者可以结合使用，用 Plan-and-Execute 做整体规划，每个步骤内部用 ReAct 来执行，最后再加上 Reflection 做质量把关。



### 5.[CoT是什么？ToT呢？](https://xiaolinnote.com/ai/agent/5_react.html)

**结论：**CoT，全称 Chain of Thought（思维链）

**重点：**CoT 有两种触发方式，第一种叫 Zero-shot CoT，直接在 prompt 末尾加上「让我们一步步思考」这句话就行了；

​            第二种叫 Few-shot CoT，你需要在 prompt 里给几个带有完整推理过程的例子，让 LLM 照着这个格式来模仿。

**扩展：**ToT 的全称是 Tree of Thoughts（思维树），在每次推理的时候，每一步给出多个不同的方向，然后使用另一个大模型评估出，选择最好的方向进行深入。

## RAG面试题

### 1.[什么是 RAG？详细描述一个完整 RAG 系统的详细工作流程？](https://xiaolinnote.com/ai/rag/1_whatisrag.html)

**结论：**RAG 是检索增强生成：从知识库中检索数据，让LLM结合检索到的知识进行回答。

**重点：**RAG主要分成两套阶段：离线阶段是文档加载、文档切割、向量化Embedding、存入向量数据库；

​            在线阶段是查询预处理、向量检索、Rerank重排、组装上下文、LLM生成答案。



### 2.[大模型的 RAG 主要用来解决什么问题？](https://xiaolinnote.com/ai/rag/2_rag_problems.html)

**结论：**RAG 主要解决的是大模型的知识时效性问题和私有知识覆盖的问题。

**重点：**知识时效性是指LLM 训练完知识就固定了，训练截止日期之后的事情他并不知道；私有知识覆盖是指大模型没有公司内部文档，项目专业知识等。

​            

### 3.[微调和 RAG 各自的优劣势是什么？](https://xiaolinnote.com/ai/rag/3_rag_vs_finetune.html)

**结论：**微调是用自己的数据继续训练大模型，可以用于定制模型的行为风格；RAG是让大模型结合知识库中的知识给出正确答案。

**重点：**微调的缺点是训练成本高，需要标注数据，租用GPU，跑训练，并且更新慢。RAG缺点是多了检索延迟，且受限于检索质量上线。



### 4.[详细说说文档切割（Chunking）策略？](https://xiaolinnote.com/ai/rag/4_chunking.html)

**结论：**文档的切割策略有固定大小切割；语义边界切割（先按段落切割，再按句子切割，再按标点切割，直到满足chunk size）；还有父子切割；让大模型辅助切割；切割后让大模型补齐背景上下文等。

**重点：**为了解决语义被切割掉的问题，通常还会加一个10%~20%的重叠overlap。最终的目的都是为了提升每个Chunk的质量。



### 6.[在 RAG 中 Embedding 究竟是什么？如何选择和评估一个 Embedding 模型？](https://xiaolinnote.com/ai/rag/6_embedding.html)

**结论：**Embedding 是指将文本映射成向量，语义相关内容在向量空间更接近。

**重点：**实际项目中，我会根据模型排行榜、擅长语言领域、数据合规等来综合考虑。我们项目中需要综合考虑本地化部署和中文能力强大，于是选择的是Qwen3-Embedding。



### 8.[什么是向量数据库？有没有做过向量数据库的对比选型？](https://xiaolinnote.com/ai/rag/8_vectordb.html)

**结论：**向量数据库是专门用来存储和检索高维向量的数据库，核心能力是近似最近邻搜索，也叫 ANN，能在百万甚至亿级的向量里快速找出最相似的几条。

**重点：**我通常按照数据规模来选择，中小规模场景，如我自己的开源的Agent学习项目，使用的是Qdrant；而我们部门的Agent，底层使用的向量数据库则是Milvus。



### 9.[讲讲你用的向量数据库？数据量级是多大？性能如何？遇到过性能瓶颈吗？](https://xiaolinnote.com/ai/rag/9_vectordb_practice.html)

**结论：**我们生产环境用的是Mivus，数据量级在百万条向量左右，每条是1024维，用HNSW索引，单次查询的延迟在20到50毫秒。

​            选Milvus主要是因为它支持分布式部署和读写分离，适合数据量大、并发高的场景。

**重点：**我遇到过两个比较典型的瓶颈。第一个是内存压力，百万级的1024维向量光原始数据就要好几个GB，后来我们开启了标量量化SQ8，把foat32压成int8，内存直接降到原来的四分之一。
            第二个是大批量写入的时候会触发后台Segment合并，影响查询延迟，我们的解法是把批量写入改到业务低峰期，分批小批次写入。



### 10.[你使用 RAG 给大模型一个输入，系统是怎样的工作流程？](https://xiaolinnote.com/ai/rag/10_online_workflow.html)

**结论：**系统会经过：查询预处理、向量检索、Rerank重排、Prompt拼装、大模型生成几个阶段。

**重点：**预处理的时候可以使用HYDE，让大模型假设一个答案，带着假设的答案去向量搜索。

​            检索阶段可以使用向量检索+BM25关键字混合检索，召回结果使用RRF算法合并，最终召回结果比单路覆盖面更广、质量更高。

​            Rerank重排阶段使用Rerank模型精排，进一步过滤得到高质量片段。

​            大模型生成阶段通常要求生成结果中标注引用来源，方便用户溯源对照，提升可信度。

​          

### 12.[如何润色用户的 Query（Query Rewrite）？目的是什么？](https://xiaolinnote.com/ai/rag/12_query_rewrite.html)

**结论：**Query Rewrite 是将用户问题变为更利于检索的表达，同时保留原始意图。

**重点：**一种是直接改写（如：去掉口语化表达、补齐缩写和指代）；另一种是使用HYDE带着假设的答案去进行向量搜索。



### 14.[RAG 检索优化策略有哪些？](https://xiaolinnote.com/ai/rag/14_retrieval_opt.html)

**结论：**我通常在文档切割阶段、查询预处理阶段、检索阶段、重排序阶段加入合适的优化测试。

**重点：**在文档切割阶段，使用合适的分块和索引策略，如使用语义切割，父子切割等方式优化；

​            查询预处理阶段，使用HYDE带着假设的答案去向量库搜索；

​            检索阶段可以使用向量检索+BM25关键字混合检索，召回结果使用RRF算法合并，最终召回结果比单路覆盖面更广、质量更高。

​            重排序阶段使用Rerank模型精排，进一步过滤得到高质量片段；

### 15.[了解哪些更复杂的 RAG 范式？](https://xiaolinnote.com/ai/rag/15_advanced_paradigms.html)

**结论：**在我的了解里，RAG 的发展经历了三代演进:Naive RAG 是基础的检索加生成;

​            Advanced RAG 在检索前后都加了优化，比如 Query改写、Rerank、混合检索这些;

​            Modular RAG 是把各个环节做成模块可以任意组合。

**重点：**我还知道GraphRAG：将知识库沉淀为知识图谱，擅长解决知识之间关联性强、需要全局视角的场景；

​            Agentic RAG 把 RAG 嵌入 Agent 循环，让Agent自主决定要不要使用知识库的功能，在实际项目中，我们把RAG查询封装成了一个Tool，让大模型自主选择是否使用。



### 17.[如何规避 RAG 系统中大模型的幻觉？](https://xiaolinnote.com/ai/rag/17_hallucination.html)

**结论：**RAG 幻觉主要有两类。

​            第一类是检索没有召回到相关内容，LLM 没有可用的上下文，靠自身知识在编造答案。

​            第二类是检索内容召回了但 LLM 没有严格遵循，在文档内容的基础上加了自己的推断。

**重点：**第一是 Promp强约束，明确告知 LLM 只能根据提供的资料回答，资料里没有的就说不知道；

​            第二是生成后引用核査，每个关键的声明都要在 chunk 里找到来源依据；

​            第三是结构化输出强制溯源，让 LLM 输出 JSON，每条结论必须附上来源编号。



### 18.[怎么量化你的 RAG 效果？](https://xiaolinnote.com/ai/rag/18_evaluation.html)

**结论：**首先是检索层评估，我们准备一批问题+对应正确chunk ID的测评数据，然后评估其Hit@K和MRR是否达到目标；未达到目标则进行分析优化。

​            其次是生成层评估，可以使用RAGAs框架来进行评估。

​            最后我们还需要关注线上指标：如在线追问率、转人工率等。

​            形成离线评测->优化上线->线上观测->离线复现->优化上线的完整闭环。



### 19.[RAG 知识库如何实现动态与持续更新？](https://xiaolinnote.com/ai/rag/19_dynamic_update.html)

**结论：**我们的通用方案是给每个文档算一个内容 hash，通过轮询或者监听数据源变更，检测到文档新增、修改、删除的时候，先清掉旧的向量，再重新切割入库。

**结论：**我认为最难的地方在于保证检索质量。我们通过拆分不同的阶段

### 21.[不同来源的文档发生知识冲突时，RAG 应该信谁？](https://xiaolinnote.com/ai/rag/21_knowledge_conflict.html)

## LLM工具调用面试题

### 1.[什么是 Function Calling？原理是什么？](https://xiaolinnote.com/ai/tools/1_function_calling.html)

**结论：**Function Calling指的是：开发者用 JSON schema 把工具描述好传给模型，模型判断需要调工具的时候输出一段结构化的 tool_calls JSON，指明需要调用的工具和入参，代码再去真正执行，

​            把结果塞回对话，模型再根据执行结果生成最终答案。

**重点：**核心的设计是，模型全程只做决策，执行的事情一律由宿主代码完成。



### 2.[LLM 是如何学会调用外部工具的？](https://xiaolinnote.com/ai/tools/2_llm_tool_learning.html)

**结论：**训练层面，在**SFT**监督微调阶段，给模型喂大量「工具调用示范对话」，让他学会工具调用流程；

​            在RLHF阶段，训练大模型知道什么时候该调用工具。

​            在运行层面：开发者用 JSON schema 把工具描述好传给模型，模型判断需要调工具的时候输出一段结构化的 tool_calls JSON，指明需要调用的工具和入参，代码再去真正执行，

​            把结果塞回对话，模型再根据执行结果生成最终答案。



### 4.[什么是 MCP（模型上下文协议）？讲讲它的核心内容？](https://xiaolinnote.com/ai/tools/4_what_is_mcp.html)

**结论：** MCP 是一套连接 AI 应用与外部工具、数据的开放协议。它的优点是可以让工具一次封装，到处复用。

**重点：** MCP Server封装好一套工具，MCP Client可以和Server进行连接，调用这些工具。

​             MCP的消息格式是JSON-RCP2.0；

​             传输协议有Stdio和Streamable HTTP，本地启动的MCP Server使用Stdio，远端的MCP Server则使用Streamable HTTP。

​             MCP最常用的是暴露Tool能力，初次之外，还有Resources和Prompts模板。

 **例子：**在我的最常用的codex工具中，我们可以在config.toml文件中，安装MCP的格式注册MCP，Codex就要了该MCP提供的所有能力。在一次大模型调用中，codex会调用MCP的tool/list接口，

​             获取到工具定义，将其传递给大模型，大模型返回Tool call之后，codex再调用对应的MCP提供的工具来执行。



### 6.[MCP 和 Function Calling 有什么区别？](https://xiaolinnote.com/ai/tools/6_mcp_vs_fc.html)

**结论：**Function Calling 解决的是大模型调用工具的问题；MCP是一种工具生态协议，让工具可以一次封装，到处复用，MCP底层的工具调用，还是基于Function Calling的。



### 9.[Skill 是什么？](https://xiaolinnote.com/ai/tools/9_skill.html)

**结论：**Agent Skill 是把「指令、脚本、模板」一体化打包成可复用技能包，Agent可以自动发现，按需加载使用技能。

**重点：**Skill本质上是一个文件夹，里面要一个必不可少的Skill.md文件，还有可选的scripts、references、assets文件夹，分别存放脚本、参考文档、模板文件。

​            Skill使用渐进式披露的机制， 每次只给大模型提供Skill.md中的name和description，当大模型需要的时候，再加载完整的Skill.md，

​            Skill.md中提到的脚本、参考文档、目标文件，再按需去读取。

**例子：**现在github上已经要了成千上万的Skill，当我们需要的时候，直接让agent帮忙去github上挑选合适的即可；实在没有合适的，我们也能使用Skill-creator技能自己开发自己的Skill，

​            例如我在职期间，为了提高测试效率，自己研发出了一个基于playwright MCP的端到端测试Skill，用于自动打开浏览器执行测试用例。

### 6.[大模型是怎么训练出来的？](https://xiaolinnote.com/ai/llm/llm_training.html)

**重点：**“涌现”指某些大模型能力随规模表现出明显跃升，某些能力会从完成不能直接变成能做，就像是量变引起质变。

### 13.[大模型的参数：温度值、Top-P、Top-K 分别是什么？各个场景下的最佳设置是什么？](https://xiaolinnote.com/ai/llm/temperature_top_p_top_k.html)

**结论：**temperature 控制输出的随机性，越低越稳定可复现，越高越发散有创意；Top-K 是固定从概率最高的 K 个词里选；Top-P 是从累积概率达到 P 的候选词里采样，比 Top-K 更灵活自适应；

**重点：**我们通常保持Top-P和Top-K为默认值，需要精确问答的时候调低温度，面对创意性问题则调高温度。
